透過將交易金鑰和收款地址與交易比對，驗證一筆特定的 Blocknet 付款。本指南依據 2026 年 10 月 27 日檢查的官方 CLI v1.2.0 和 core v0.22.0，介紹產生證明、分享正確欄位，以及搭配鏈上狀態讀取結果。

## 如何證明一筆 Blocknet 付款？

<Answer>
開啟傳送錢包，用交易 ID 執行 prove，將取得的交易金鑰交給指定驗證者。驗證需要該金鑰、交易 ID 和收款地址。先確認金鑰有效，再檢查符合該地址的輸出和金額。
</Answer>

## 從要證明的付款開始

儲存傳送紀錄中的完整交易 ID。[傳送指南](/zh-hant/blog/send-receive-blocknet/)說明官方用戶端在哪裡印出它，[瀏覽器指南](/zh-hant/blog/blocknet-explorer-guide/)介紹查找交易及所在區塊。公開 ID 可以定位轉帳，但一般瀏覽器頁面不會揭露支付給特定地址的私密金額。

約定要檢查的收款地址和付款紀錄。使用與付款關聯的完整地址，不要用縮略標籤或截圖。如果按名稱付款，請保留交易實際使用的地址。證明可用於核實特定收款，或與收款人解決付款疑問；它不確認任何人的現實身分。

## 在傳送錢包中產生交易金鑰

從終端機連接執行中的 mainnet core：

```sh
blocknet attach mainnet
```

在互動式 shell 中開啟傳送錢包並查看紀錄：

```text
load
address
history
```

選擇目標檔案，必要時透過用戶端解鎖。初始設定請參閱[錢包指南](/zh-hant/blog/blocknet-wallet-for-mining/)。

在 shell 中執行以下指令，將預留位置替換為完整交易 ID：

```text
prove <txid>
```

[已檢查的用戶端](https://github.com/blocknetprivacy/blocknet/blob/948af4de8b7a3e3cddc86a329c7d2d003cb3fd6b/attach_wallet.go)接受 64 字元的十六進位交易 ID，並顯示傳回的交易金鑰。Core 在本機鏈上尋找交易，檢查衍生金鑰是否符合其公鑰。使用傳送該交易的錢包；產生證明不會建立另一筆付款。

## 應該分享哪些資訊？

透過約定管道分享交易 ID、傳回的交易金鑰和目標收款地址。交易金鑰僅針對這筆交易。復原種子、花費金鑰、錢包密碼和整個錢包的私密檢視金鑰應保持私密。驗證者需要證明欄位，而不是存取已載入的錢包或復原資料。

將此視為主動揭露付款資訊：金鑰和收款地址讓驗證者識別該交易的相符輸出、金額，以及任何可復原的備註。只與需要該證據的人分享。[備註指南](/zh-hant/blog/blocknet-encrypted-memos/)解釋付款備註，分享證明前應考慮內容。已分享的金鑰可以被複製，因此使用收款人認可的私密管道。

## 透過文件中的 core API 驗證

[官方 API](https://blocknetcrypto.com/api)提供公開證明驗證端點，不需要已載入的錢包或 bearer 權杖。優先使用自己控制的節點。將以下範本儲存為私密工作資料夾中的 `proof.json`，把三個預留字串全部替換為真實證明欄位。欄位名稱保持不變。

```json
{
  "txid": "REPLACE_WITH_TRANSACTION_ID",
  "tx_key": "REPLACE_WITH_TRANSACTION_KEY",
  "address": "REPLACE_WITH_RECIPIENT_ADDRESS"
}
```

從該資料夾將檔案提交到節點 API 地址：

```sh
curl -H "Content-Type: application/json" --data-binary @proof.json http://127.0.0.1:8332/api/verify-proof
```

如設定了不同本機連接埠，請相應修改；Windows PowerShell 中使用 `curl.exe`。[節點指南](/zh-hant/blog/run-blocknet-node/)介紹執行 core。此請求檢查證據，不傳送幣。若使用遠端伺服器，提交的欄位會向其營運者揭露。

## 分別讀取金鑰有效性和收款比對

先檢查 `valid`。true 表示交易金鑰符合交易公鑰。接著檢查 `outputs`：`match` 為 true 的項目屬於所提供的收款地址。`total_matched` 是其金額總和。如果該地址沒有收到這筆交易，即使金鑰有效，也可能有零個相符輸出。

API 以原子單位報告金額：100,000,000 單位等於 1 BNT。與 BNT 計價帳單比較前先換算總額，保留所有整數位，不要過早捨入。將傳回備註與預期紀錄核對。交易納入和確認請另外透過節點或瀏覽器驗證。僅有證明結果不能說明帳單已全額支付，也不能說明資金目前可花費。

## 用原始紀錄排查不一致

金鑰無效時，將完整 ID 和交易金鑰與傳送方的原始輸出比較。金鑰有效但沒有收款符合項目時，重新檢查付款使用的完整地址。產生證明找不到交易時，檢查節點網路和鏈進度：已檢查的產生端點要求交易在鏈上。本機鏈落後時請按[同步指南](/zh-hant/blog/blocknet-wallet-not-syncing/)處理。

對於礦池付款，您的收款錢包不是產生礦池交易的傳送錢包。從[礦池追蹤紀錄](https://bntpool.com/blog/zh-hant/track-your-miner-on-bntpool/)和錢包入帳歷史開始，傳送方證明應向實際傳送者取得。已檢查的產生端點中，coinbase 挖礦獎勵也沒有傳送方證明。這些區別有助於選擇與所查付款相符的證據。

## 將證明與用途和結果一起儲存

在私密紀錄中一起儲存交易 ID、收款地址、相關付款參照和驗證結果。記錄檢查了哪個網路、節點，以及檢查時間。只保留該目的所需的付款資訊。收到證明的人可以獨立重複驗證，無須依賴他人結果的截圖。

[簽署訊息](/zh-hant/blog/blocknet-sign-verify-message/)用途不同：它展示對某地址簽署金鑰的控制，針對的是特定訊息。交易證據使用付款證明，約定的所有權挑戰使用訊息流程。[唯讀指南](/zh-hant/blog/blocknet-view-only-wallet/)解釋為什麼檢視權限即使不能授權花費，仍是敏感權限。讓每類證據對應它所回答的問題。
