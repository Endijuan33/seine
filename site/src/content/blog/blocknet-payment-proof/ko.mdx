거래 키와 수취 주소를 거래에 대조하여 특정 Blocknet 결제를 검증하세요. 이 안내는 2026년 10월 27일 확인한 공식 CLI v1.2.0과 core v0.22.0을 따릅니다. 증명 생성, 올바른 필드 공유, 체인 상태와 함께 결과 읽기를 설명합니다.

## Blocknet 결제는 어떻게 증명하나요?

<Answer>
보내는 지갑을 열고 거래 ID로 prove를 실행한 뒤 나온 거래 키를 의도한 검증자에게 주세요. 검증은 키, ID, 수취 주소를 사용합니다. 키가 유효한지 확인한 다음 해당 주소의 일치 출력과 금액을 살펴보세요.
</Answer>

## 입증하려는 결제부터 시작하기

발신 기록의 전체 ID를 보관하세요. [보내기 안내](/ko/blog/send-receive-blocknet/)는 공식 클라이언트의 ID 출력 위치를, [탐색기 안내](/ko/blog/blocknet-explorer-guide/)는 거래와 포함 블록 찾기를 설명합니다. 공개 ID는 송금을 찾지만 일반 탐색기 페이지는 특정 주소의 비공개 수취 금액을 공개하지 않습니다.

어느 수취 주소와 기록을 확인할지 합의하세요. 축약 이름이나 스크린샷 대신 그 결제의 전체 주소를 쓰세요. 이름으로 보냈다면 실제 사용 주소를 보관하세요. 증명은 특정 수취 확인이나 수취인과의 결제 질문 해결에 유용하며 실제 인물의 신원을 입증하지 않습니다.

## 보내는 지갑에서 거래 키 만들기

터미널에서 실행 중인 mainnet core에 연결하세요.

```sh
blocknet attach mainnet
```

대화형 셸에서 보내는 지갑을 열고 기록을 확인하세요.

```text
load
address
history
```

원하는 파일을 선택하고 필요하면 클라이언트에서 잠금을 해제하세요. 초기 설정은 [지갑 안내](/ko/blog/blocknet-wallet-for-mining/)를 보세요.

자리표시자를 전체 ID로 바꾸고 셸에서 실행하세요.

```text
prove <txid>
```

[검토한 클라이언트](https://github.com/blocknetprivacy/blocknet/blob/948af4de8b7a3e3cddc86a329c7d2d003cb3fd6b/attach_wallet.go)는 64자 16진수 ID를 받아 반환된 거래 키를 표시합니다. Core는 로컬 체인에서 거래를 찾고 도출한 키가 공개 키에 맞는지 확인합니다. 보낸 지갑을 사용하세요. 생성은 다른 결제를 만들지 않습니다.

## 어떤 정보를 공유하나요?

합의한 경로로 ID, 반환된 거래 키, 수취 주소를 공유하세요. 키는 이 거래에만 해당합니다. 복구 시드, 지출 키, 지갑 비밀번호, 지갑 전체의 보기 개인 키는 비공개로 유지하세요. 검증자는 증명 필드가 필요하며 열린 지갑이나 복구 자료에 접근할 필요가 없습니다.

이는 의도적인 결제 정보 공개입니다. 키와 주소는 일치 출력, 금액, 해당 거래에서 복구 가능한 메모를 식별하게 합니다. 증거가 필요한 사람에게 공유하세요. [메모 안내](/ko/blog/blocknet-encrypted-memos/)는 결제 메모를 설명하므로 공유 전 내용을 고려하세요. 공유한 키는 복사될 수 있으니 수취인과 합의한 비공개 경로를 사용하세요.

## 문서화된 core API로 검증하기

[공식 API](https://blocknetcrypto.com/api)는 불러온 지갑이나 bearer 토큰이 필요 없는 공개 검증 엔드포인트를 제공합니다. 자신이 관리하는 노드를 우선하세요. 템플릿을 비공개 작업 폴더에 `proof.json`으로 저장하고 세 자리표시자 문자열을 실제 필드로 바꾸세요. 필드 이름은 그대로 둡니다.

```json
{
  "txid": "REPLACE_WITH_TRANSACTION_ID",
  "tx_key": "REPLACE_WITH_TRANSACTION_KEY",
  "address": "REPLACE_WITH_RECIPIENT_ADDRESS"
}
```

그 폴더에서 노드 API 주소로 파일을 보내세요.

```sh
curl -H "Content-Type: application/json" --data-binary @proof.json http://127.0.0.1:8332/api/verify-proof
```

로컬 포트가 다르면 설정한 포트를 쓰고 Windows PowerShell에서는 `curl.exe`를 사용하세요. [노드 안내](/ko/blog/run-blocknet-node/)는 core 실행을 설명합니다. 이 요청은 증거 확인이며 코인을 보내지 않습니다. 원격 서버를 쓰면 제출 필드가 운영자에게 공개됩니다.

## 키 유효성과 수취 일치를 따로 읽기

먼저 `valid`를 보세요. true면 키가 거래 공개 키에 일치합니다. 이어 `outputs`를 보세요. `match`가 true인 항목은 제공한 수취 주소에 속합니다. `total_matched`는 그 금액의 합계입니다. 주소가 해당 거래를 받지 않았다면 유효한 키도 일치 출력 0개를 낼 수 있습니다.

API는 원자 단위로 금액을 표시합니다. 100,000,000단위가 1 BNT입니다. BNT 청구서와 비교하기 전에 합계를 환산하고 너무 일찍 반올림하지 말고 모든 정수 자릿수를 보존하세요. 반환된 메모를 예상 기록과 대조하세요. 포함 여부와 확인 수는 노드나 탐색기에서 별도 검증하세요. 증명 결과만으로 청구서 전액 지급이나 현재 사용 가능 여부를 알 수는 없습니다.

## 원본 기록으로 불일치 해결하기

키가 무효하면 전체 ID와 키를 보낸 사람의 원본 출력과 비교하세요. 유효한 키에 수취 일치가 없다면 실제 전체 주소를 다시 확인하세요. 생성 중 거래를 못 찾으면 노드 네트워크와 체인 진행을 보세요. 검토한 생성 엔드포인트는 체인상 거래를 요구합니다. 로컬 체인이 뒤처지면 [동기화 안내](/ko/blog/blocknet-wallet-not-syncing/)를 따르세요.

풀 지급에서 자신의 수취 지갑은 풀 거래를 만든 발신 지갑이 아닙니다. [풀 추적 기록](https://bntpool.com/blog/ko/track-your-miner-on-bntpool/)과 수취 내역에서 시작하고 발신 증명은 실제 발신자에게 받으세요. 검토한 생성 엔드포인트에서 coinbase 채굴 보상도 발신 증명이 없습니다. 이 차이는 결제에 맞는 증거를 고르는 데 도움이 됩니다.

## 증명을 목적과 결과와 함께 보관하기

ID, 수취 주소, 관련 결제 참조, 검증 결과를 비공개 기록에 함께 보관하세요. 확인한 네트워크, 노드, 시각도 적으세요. 그 목적에 필요한 정보만 보관하세요. 증명을 받은 사람은 타인의 결과 스크린샷에 의존하지 않고 독립적으로 검증할 수 있습니다.

[서명 메시지](/ko/blog/blocknet-sign-verify-message/)는 다른 목적입니다. 특정 메시지에 대해 주소의 서명 키를 제어함을 보여 줍니다. 거래 증거에는 결제 증명을, 합의한 소유권 확인에는 메시지 절차를 쓰세요. [보기 전용 안내](/ko/blog/blocknet-view-only-wallet/)는 지출 승인이 불가능해도 보기 접근이 민감한 이유를 설명합니다. 각 증거를 답하는 질문에 연결하세요.
