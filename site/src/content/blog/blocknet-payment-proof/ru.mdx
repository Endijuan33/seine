Проверьте конкретный платёж Blocknet, сопоставив ключ транзакции и адрес получателя с транзакцией. Руководство основано на официальном CLI v1.2.0 и core v0.22.0, проверенных 27 октября 2026 года. Оно описывает создание доказательства, передачу нужных полей и чтение результата вместе со статусом в цепочке.

## Как доказать платёж Blocknet?

<Answer>
Откройте кошелёк отправителя, выполните prove с ID и передайте полученный ключ назначенному проверяющему. Проверка использует ключ, ID и адрес получателя. Убедитесь в валидности ключа, затем изучите совпавшие выходы и сумму для адреса.
</Answer>

## Начните с нужного платежа

Сохраните полный ID из записи отправки. [Руководство по отправке](/ru/blog/send-receive-blocknet/) показывает, где официальный клиент его печатает, а [руководство по обозревателю](/ru/blog/blocknet-explorer-guide/) — как найти транзакцию и блок. Публичный ID находит перевод, но обычная страница не раскрывает приватную сумму конкретному адресу.

Согласуйте адрес и платёжную запись для проверки. Используйте полный связанный адрес, а не сокращённую метку или снимок. При оплате по имени сохраните фактически использованный адрес. Доказательство помогает проверить конкретное получение или решить вопрос с получателем; оно не устанавливает личность человека в реальном мире.

## Создайте ключ в кошельке отправителя

Подключитесь из терминала к работающему mainnet core:

```sh
blocknet attach mainnet
```

Откройте кошелёк отправителя и изучите записи в интерактивной оболочке:

```text
load
address
history
```

Выберите нужный файл и при необходимости разблокируйте через клиент. Начальная настройка описана в [руководстве по кошельку](/ru/blog/blocknet-wallet-for-mining/).

Выполните команду в оболочке, заменив заполнитель полным ID:

```text
prove <txid>
```

[Проверенный клиент](https://github.com/blocknetprivacy/blocknet/blob/948af4de8b7a3e3cddc86a329c7d2d003cb3fd6b/attach_wallet.go) принимает шестнадцатеричный ID длиной 64 символа и показывает возвращённый ключ. Core ищет транзакцию в локальной цепочке и проверяет соответствие выведенного ключа публичному. Используйте отправивший кошелёк; создание доказательства не создаёт нового платежа.

## Какими данными делиться?

Передайте ID, полученный ключ транзакции и адрес получателя согласованным каналом. Ключ относится только к этой транзакции. Сохраняйте в тайне сид-фразу, ключ расходования, пароль и приватный ключ просмотра всего кошелька. Проверяющему нужны поля доказательства, а не доступ к открытому кошельку или данным восстановления.

Это намеренное раскрытие платёжных сведений: ключ и адрес позволяют найти совпавшие выходы, суммы и любую восстанавливаемую заметку транзакции. Делитесь с теми, кому нужно доказательство. [Руководство по заметкам](/ru/blog/blocknet-encrypted-memos/) объясняет платёжные сообщения; учтите содержимое перед передачей. Переданный ключ можно скопировать, поэтому используйте согласованный приватный канал получателя.

## Проверка через документированный API core

[Официальный API](https://blocknetcrypto.com/api) предоставляет публичный endpoint проверки без загруженного кошелька и bearer-токена. Предпочтителен подконтрольный вам узел. Сохраните шаблон как `proof.json` в приватной рабочей папке и замените все три строки-заполнителя реальными полями. Имена полей не меняйте.

```json
{
  "txid": "REPLACE_WITH_TRANSACTION_ID",
  "tx_key": "REPLACE_WITH_TRANSACTION_KEY",
  "address": "REPLACE_WITH_RECIPIENT_ADDRESS"
}
```

Из этой папки отправьте файл на API-адрес узла:

```sh
curl -H "Content-Type: application/json" --data-binary @proof.json http://127.0.0.1:8332/api/verify-proof
```

Если локальный порт настроен иначе, используйте его; в Windows PowerShell используйте `curl.exe`. [Руководство по узлу](/ru/blog/run-blocknet-node/) описывает запуск core. Запрос проверяет доказательство и не отправляет монеты. Удалённый сервер раскрывает переданные поля своему оператору.

## Разделяйте валидность ключа и совпадения адреса

Сначала проверьте `valid`. true означает соответствие ключа публичному ключу транзакции. Затем изучите `outputs`: записи с `match`, равным true, принадлежат указанному адресу. `total_matched` суммирует их суммы. Валидный ключ может дать ноль совпавших выходов, если адрес не получал эту транзакцию.

API возвращает суммы в атомарных единицах: 100 000 000 единиц равны 1 BNT. Переведите итог перед сравнением со счётом в BNT; сохраняйте все целые цифры, не округляя заранее. Сверьте возвращённую заметку с ожидаемой записью. Включение и подтверждения проверьте отдельно через узел или обозреватель. Сам результат не говорит о полной оплате счёта или текущей доступности средств для расходования.

## Устраните расхождения по исходным записям

При невалидном ключе сравните полный ID и ключ с исходным выводом отправителя. При валидном ключе без совпадений перепроверьте полный адрес платежа. Если транзакция не найдена при создании, проверьте сеть и загрузку цепочки: проверенный endpoint требует транзакцию в цепочке. При отставании следуйте [руководству по синхронизации](/ru/blog/blocknet-wallet-not-syncing/).

Для выплат пула ваш кошелёк получателя не является отправителем транзакции пула. Начните с [записи отслеживания пула](https://bntpool.com/blog/ru/track-your-miner-on-bntpool/) и входящей истории; доказательство отправителя запрашивайте у реального отправителя. Coinbase-награды также не имеют доказательства отправителя в проверенном endpoint создания. Эти различия помогают выбрать свидетельство, соответствующее платежу.

## Храните доказательство с целью и результатом

Храните ID, адрес получателя, связанную платёжную ссылку и результат вместе в приватных записях. Укажите сеть, узел и время проверки. Оставляйте только необходимые для цели платёжные сведения. Получатель доказательства может независимо повторить проверку вместо доверия снимку чужого результата.

[Подписанное сообщение](/ru/blog/blocknet-sign-verify-message/) решает иную задачу: демонстрирует контроль ключа подписи адреса для конкретного сообщения. Используйте доказательство платежа для отдельной транзакции, а сообщения — для согласованной проверки владения. [Руководство по просмотру](/ru/blog/blocknet-view-only-wallet/) объясняет чувствительность доступа просмотра без права расходования. Связывайте каждый вид свидетельства с вопросом, на который он отвечает.
