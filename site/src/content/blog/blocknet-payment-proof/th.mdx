ตรวจการชำระ Blocknet รายการหนึ่งโดยจับคู่กุญแจธุรกรรมและที่อยู่รับกับธุรกรรม คู่มือนี้อ้างอิง CLI ทางการ v1.2.0 และ core v0.22.0 ที่ตรวจเมื่อ 27 ตุลาคม 2026 ครอบคลุมการสร้างหลักฐาน แชร์ข้อมูลที่ถูกต้อง และอ่านผลคู่กับสถานะเชน

## พิสูจน์การชำระ Blocknet อย่างไร?

<Answer>
เปิดกระเป๋าผู้ส่ง ใช้ prove กับ ID แล้วมอบกุญแจธุรกรรมที่ได้ให้ผู้ตรวจที่ตั้งใจ การตรวจใช้กุญแจ ID และที่อยู่รับ ยืนยันกุญแจถูกต้อง แล้วตรวจเอาต์พุตกับยอดที่ตรงที่อยู่นั้น
</Answer>

## เริ่มจากการชำระที่ต้องการพิสูจน์

เก็บ ID เต็มจากบันทึกส่ง [คู่มือส่ง](/th/blog/send-receive-blocknet/) อธิบายจุดที่ไคลเอนต์ทางการพิมพ์ ID ส่วน [คู่มือตัวสำรวจ](/th/blog/blocknet-explorer-guide/) อธิบายการหาธุรกรรมและบล็อก ID สาธารณะช่วยหาการโอน แต่หน้าปกติไม่เผยยอดส่วนตัวที่จ่ายไปที่อยู่หนึ่ง

ตกลงว่าจะตรวจที่อยู่และบันทึกใด ใช้ที่อยู่เต็มของการชำระนั้น ไม่ใช่ป้ายย่อหรือภาพ หากชำระด้วยชื่อ ให้เก็บที่อยู่ที่ใช้ หลักฐานช่วยตรวจการรับเฉพาะรายการหรือแก้ข้อสงสัยกับผู้รับ แต่ไม่ยืนยันตัวตนจริงของบุคคล

## สร้างกุญแจธุรกรรมในกระเป๋าผู้ส่ง

เชื่อม mainnet core ที่ทำงานจากเทอร์มินัล:

```sh
blocknet attach mainnet
```

เปิดกระเป๋าผู้ส่งและตรวจบันทึกในเชลล์โต้ตอบ:

```text
load
address
history
```

เลือกไฟล์ที่ต้องการและปลดล็อกผ่านไคลเอนต์หากจำเป็น การตั้งค่าแรกใช้ [คู่มือกระเป๋า](/th/blog/blocknet-wallet-for-mining/)

เรียกในเชลล์โดยแทนข้อความตัวอย่างด้วย ID เต็ม:

```text
prove <txid>
```

[ไคลเอนต์ที่ตรวจสอบ](https://github.com/blocknetprivacy/blocknet/blob/948af4de8b7a3e3cddc86a329c7d2d003cb3fd6b/attach_wallet.go) รับ ID ฐานสิบหก 64 ตัวอักษรและแสดงกุญแจที่คืน core หาธุรกรรมบนเชนในเครื่องและตรวจกุญแจที่สร้างว่าตรงกุญแจสาธารณะ ใช้กระเป๋าที่ส่ง การสร้างหลักฐานไม่สร้างการจ่ายใหม่

## ควรแชร์ข้อมูลใด?

แชร์ ID กุญแจที่คืน และที่อยู่รับผ่านช่องทางที่ตกลง กุญแจเฉพาะธุรกรรมนี้เท่านั้น เก็บ seed กู้คืน กุญแจใช้จ่าย รหัสกระเป๋า และกุญแจดูส่วนตัวทั้งกระเป๋าเป็นความลับ ผู้ตรวจต้องการช่องหลักฐาน ไม่ใช่สิทธิ์เข้ากระเป๋าที่เปิดหรือข้อมูลกู้คืน

ถือเป็นการเปิดเผยข้อมูลการชำระโดยตั้งใจ กุญแจกับที่อยู่ทำให้ผู้ตรวจระบุเอาต์พุตตรง ยอด และบันทึกที่กู้ได้ของธุรกรรม แชร์กับผู้ที่ต้องการหลักฐาน [คู่มือบันทึก](/th/blog/blocknet-encrypted-memos/) อธิบายโน้ตชำระ พิจารณาเนื้อหาก่อนแชร์ กุญแจที่แชร์แล้วคัดลอกได้ จึงใช้ช่องทางส่วนตัวที่ตกลงกับผู้รับ

## ตรวจผ่าน API core ที่มีเอกสาร

[API ทางการ](https://blocknetcrypto.com/api) มีจุดตรวจหลักฐานสาธารณะที่ไม่ต้องโหลดกระเป๋าหรือใช้ bearer token เลือกโหนดที่คุณควบคุมก่อน เก็บแม่แบบเป็น `proof.json` ในโฟลเดอร์ส่วนตัวแล้วแทนข้อความตัวอย่างทั้งสามด้วยข้อมูลจริง คงชื่อช่องเดิม

```json
{
  "txid": "REPLACE_WITH_TRANSACTION_ID",
  "tx_key": "REPLACE_WITH_TRANSACTION_KEY",
  "address": "REPLACE_WITH_RECIPIENT_ADDRESS"
}
```

จากโฟลเดอร์นั้น ส่งไฟล์ไปที่อยู่ API โหนด:

```sh
curl -H "Content-Type: application/json" --data-binary @proof.json http://127.0.0.1:8332/api/verify-proof
```

ใช้พอร์ตในเครื่องที่ตั้งไว้หากต่าง ใน Windows PowerShell ใช้ `curl.exe` [คู่มือโหนด](/th/blog/run-blocknet-node/) อธิบายการรัน core คำขอนี้ตรวจหลักฐาน ไม่ส่งเหรียญ หากใช้เซิร์ฟเวอร์ระยะไกล ข้อมูลที่ส่งจะเปิดให้ผู้ดูแลนั้น

## อ่านกุญแจถูกต้องแยกจากผู้รับตรงกัน

ดู `valid` ก่อน true หมายถึงกุญแจตรงกับกุญแจสาธารณะของธุรกรรม แล้วดู `outputs` รายการที่ `match` เป็น true เป็นของที่อยู่รับที่ให้ `total_matched` รวมยอดรายการเหล่านั้น กุญแจถูกต้องอาจให้เอาต์พุตตรงศูนย์รายการหากที่อยู่ไม่ได้รับธุรกรรมนั้น

API รายงานยอดหน่วยอะตอม 100,000,000 หน่วยเท่ากับ 1 BNT แปลงยอดรวมก่อนเทียบใบแจ้งหนี้ BNT เก็บทุกหลักของจำนวนเต็ม ไม่ปัดเศษเร็ว ตรวจบันทึกที่คืนกับรายการคาดหมาย ตรวจการบรรจุและการยืนยันแยกผ่านโหนดหรือตัวสำรวจ ผลหลักฐานอย่างเดียวไม่บอกว่าใบแจ้งหนี้จ่ายครบหรือเงินพร้อมใช้ตอนนี้

## แก้ข้อมูลไม่ตรงด้วยบันทึกเดิม

กุญแจไม่ถูกต้องให้เทียบ ID เต็มและกุญแจกับผลเดิมของผู้ส่ง กุญแจถูกแต่ไม่มีผู้รับตรงให้ตรวจที่อยู่เต็มที่ใช้ หากสร้างแล้วไม่พบธุรกรรม ให้ดูเครือข่ายและความคืบหน้าเชน จุดสร้างที่ตรวจสอบต้องการธุรกรรมบนเชน ใช้ [คู่มือซิงก์](/th/blog/blocknet-wallet-not-syncing/) หากเชนในเครื่องล่าช้า

สำหรับการจ่ายพูล กระเป๋ารับของคุณไม่ใช่กระเป๋าส่งที่สร้างธุรกรรมพูล เริ่มจาก [บันทึกติดตามพูล](https://bntpool.com/blog/th/track-your-miner-on-bntpool/) และประวัติรับ ขอหลักฐานผู้ส่งจากผู้ส่งจริง รางวัลขุด coinbase ก็ไม่มีหลักฐานผู้ส่งในจุดสร้างที่ตรวจสอบ ความต่างนี้ช่วยเลือกหลักฐานตรงกับการชำระ

## เก็บหลักฐานพร้อมจุดประสงค์และผล

เก็บ ID ที่อยู่รับ อ้างอิงการชำระ และผลตรวจด้วยกันในบันทึกส่วนตัว จดเครือข่าย โหนด และเวลาที่ตรวจ เก็บเฉพาะข้อมูลที่จำเป็นต่อจุดประสงค์ ผู้รับหลักฐานตรวจซ้ำเองได้แทนการเชื่อภาพผลของผู้อื่น

[ข้อความลงนาม](/th/blog/blocknet-sign-verify-message/) มีอีกจุดประสงค์ คือแสดงการควบคุมกุญแจลงนามของที่อยู่สำหรับข้อความหนึ่ง ใช้หลักฐานจ่ายสำหรับธุรกรรมและขั้นตอนข้อความสำหรับคำท้าพิสูจน์เจ้าของที่ตกลง [คู่มือดูอย่างเดียว](/th/blog/blocknet-view-only-wallet/) อธิบายว่าทำไมสิทธิ์ดูยังอ่อนไหวแม้สั่งใช้จ่ายไม่ได้ ผูกหลักฐานแต่ละแบบกับคำถามที่ตอบ
