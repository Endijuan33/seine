Перевірте конкретний платіж Blocknet, зіставивши ключ транзакції й адресу одержувача з транзакцією. Посібник спирається на офіційний CLI v1.2.0 і core v0.22.0, перевірені 27 жовтня 2026 року. Він охоплює створення доказу, передавання потрібних полів і читання результату разом зі станом у ланцюгу.

## Як довести платіж Blocknet?

<Answer>
Відкрийте гаманець відправника, виконайте prove з ID та передайте отриманий ключ призначеному перевіряльнику. Перевірка використовує ключ, ID і адресу одержувача. Підтвердьте дійсність ключа, потім перегляньте відповідні виходи та суму для адреси.
</Answer>

## Почніть із платежу, який хочете довести

Збережіть повний ID із запису надсилання. [Посібник надсилання](/uk/blog/send-receive-blocknet/) показує, де офіційний клієнт його друкує, а [посібник оглядача](/uk/blog/blocknet-explorer-guide/) — як знайти транзакцію та блок. Публічний ID знаходить переказ, але звичайна сторінка не розкриває приватну суму, сплачену певній адресі.

Узгодьте адресу й запис, які перевіряєте. Використовуйте повну пов’язану адресу, а не скорочену мітку чи знімок. Якщо платили за іменем, збережіть використану адресу. Доказ допомагає перевірити конкретне отримання чи вирішити питання з одержувачем; він не встановлює реальну особу людини.

## Створіть ключ у гаманці відправника

Підключіться з термінала до працюючого mainnet core:

```sh
blocknet attach mainnet
```

Відкрийте гаманець відправника й перегляньте записи в інтерактивній оболонці:

```text
load
address
history
```

Виберіть потрібний файл і за потреби розблокуйте через клієнт. Для початкового налаштування скористайтеся [посібником гаманця](/uk/blog/blocknet-wallet-for-mining/).

Виконайте в оболонці, замінивши заповнювач повним ID:

```text
prove <txid>
```

[Перевірений клієнт](https://github.com/blocknetprivacy/blocknet/blob/948af4de8b7a3e3cddc86a329c7d2d003cb3fd6b/attach_wallet.go) приймає шістнадцятковий ID із 64 символів і показує повернутий ключ. Core шукає транзакцію в локальному ланцюгу та перевіряє відповідність виведеного ключа публічному. Використовуйте гаманець, який надіслав її; створення доказу не створює іншого платежу.

## Якими даними ділитися?

Передайте ID, отриманий ключ і адресу одержувача узгодженим каналом. Ключ стосується лише цієї транзакції. Сід-фразу, ключ витрачання, пароль і приватний ключ перегляду всього гаманця тримайте в таємниці. Перевіряльнику потрібні поля доказу, а не доступ до відкритого гаманця чи матеріалів відновлення.

Це свідоме розкриття платіжної інформації: ключ і адреса дозволяють знайти відповідні виходи, суми й будь-яку відновлювану примітку транзакції. Діліться з тими, кому потрібен доказ. [Посібник приміток](/uk/blog/blocknet-encrypted-memos/) пояснює платіжні нотатки; врахуйте їхній зміст перед передаванням. Наданий ключ можна скопіювати, тож використовуйте узгоджений приватний канал одержувача.

## Перевірка через документований API core

[Офіційний API](https://blocknetcrypto.com/api) має публічний endpoint перевірки без завантаженого гаманця й bearer-токена. Краще використати підконтрольний вузол. Збережіть шаблон як `proof.json` у приватній робочій теці та замініть усі три рядки-заповнювачі реальними полями. Не змінюйте назв полів.

```json
{
  "txid": "REPLACE_WITH_TRANSACTION_ID",
  "tx_key": "REPLACE_WITH_TRANSACTION_KEY",
  "address": "REPLACE_WITH_RECIPIENT_ADDRESS"
}
```

Із цієї теки надішліть файл на API-адресу вузла:

```sh
curl -H "Content-Type: application/json" --data-binary @proof.json http://127.0.0.1:8332/api/verify-proof
```

Використайте свій налаштований локальний порт, якщо він інший; у Windows PowerShell використайте `curl.exe`. [Посібник вузла](/uk/blog/run-blocknet-node/) описує запуск core. Запит перевіряє доказ і не надсилає монет. Використання віддаленого сервера розкриває поля його оператору.

## Розділяйте дійсність ключа й відповідність адреси

Спочатку перевірте `valid`. true означає відповідність ключа публічному ключу транзакції. Далі перегляньте `outputs`: записи з `match`, рівним true, належать зазначеній адресі. `total_matched` підсумовує їхні суми. Дійсний ключ може дати нуль відповідних виходів, якщо адреса не отримувала цю транзакцію.

API повідомляє суми в атомарних одиницях: 100 000 000 одиниць дорівнюють 1 BNT. Перетворіть підсумок перед порівнянням із рахунком у BNT; збережіть усі цілі цифри без раннього округлення. Зіставте повернуті примітки з очікуваним записом. Включення й підтвердження перевіряйте окремо у вузлі чи оглядачі. Сам результат не доводить повної оплати рахунка або поточної можливості витратити кошти.

## Узгодьте розбіжності з початковими записами

Для недійсного ключа порівняйте повний ID і ключ із початковим виводом відправника. Для дійсного ключа без збігів перевірте повну адресу платежу. Якщо транзакції немає під час створення, перевірте мережу й поступ ланцюга: перевірений endpoint вимагає транзакцію в ланцюгу. При відставанні скористайтеся [посібником синхронізації](/uk/blog/blocknet-wallet-not-syncing/).

Для виплат пулу ваш гаманець одержувача не є відправником транзакції пулу. Почніть із [запису відстеження пулу](https://bntpool.com/blog/uk/track-your-miner-on-bntpool/) і вхідної історії; доказ відправника отримуйте від справжнього відправника. Coinbase-винагороди теж не мають доказу відправника в перевіреному endpoint створення. Ці відмінності допомагають обрати доказ, відповідний платежу.

## Зберігайте доказ із метою та результатом

Зберігайте ID, адресу одержувача, відповідне посилання на платіж і результат разом у приватних записах. Занотуйте мережу, вузол і час перевірки. Залишайте лише потрібні для мети відомості. Одержувач доказу може незалежно повторити перевірку, а не покладатися на знімок чужого результату.

[Підписане повідомлення](/uk/blog/blocknet-sign-verify-message/) має іншу мету: демонструє контроль ключа підпису адреси для певного повідомлення. Доказ платежу використовуйте для транзакції, а повідомлення — для узгодженої перевірки володіння. [Посібник перегляду](/uk/blog/blocknet-view-only-wallet/) пояснює чутливість доступу перегляду без права витрачання. Пов’язуйте кожен доказ із запитанням, на яке він відповідає.
