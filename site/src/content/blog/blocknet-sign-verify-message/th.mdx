ใช้ลายเซ็นข้อความ Blocknet แสดงการควบคุมที่อยู่โดยไม่ชำระเงิน คู่มือนี้อ้างอิง CLI ทางการ v1.2.0 และ core v0.22.0 ที่ตรวจเมื่อ 27 ตุลาคม 2026 คุณจะเตรียมคำท้าชัดเจน ลงนามในกระเป๋าที่ต้องการ และตรวจที่อยู่เต็ม ข้อความ กับลายเซ็นร่วมกัน

## ลงนามและตรวจข้อความ Blocknet อย่างไร?

<Answer>
โหลดกระเป๋าเต็ม ยืนยันที่อยู่ แล้วใช้ sign ลงนามข้อความที่ตกลง แชร์ที่อยู่ ข้อความตรงตัว และลายเซ็นให้ผู้ตรวจ ผู้ตรวจใช้ verify ตรวจทั้งสามค่าร่วมกัน แล้วดูว่าข้อความตรงจุดประสงค์และคำท้าใหม่ที่ขอไว้
</Answer>

## ตกลงความหมายของข้อความที่จะลงนาม

เริ่มด้วยคำขอเฉพาะ: ที่อยู่ใดต้องแสดงการควบคุม ให้ใคร และเพื่อทำอะไร [หลักฐานชำระเงิน](/th/blog/blocknet-payment-proof/) ยืนยันรายละเอียดธุรกรรม ลายเซ็นข้อความมีประโยชน์เมื่อถามถึงการควบคุมกุญแจลงนาม เช่น ยืนยันที่อยู่ให้บัญชี [คู่มือกระเป๋า](/th/blog/blocknet-wallet-for-mining/) อธิบายการสร้างและเปิดกระเป๋าที่จะลงนาม

ให้ผู้ตรวจส่งคำท้าใหม่ที่คาดเดาไม่ได้สำหรับคำขอนี้ ใส่บริบทพอระบุบริการหรือผู้รับและการดำเนินการที่ตั้งใจ และตกลงวันหมดอายุถ้าจำเป็น นี่คือกฎของแอป ตัวตรวจลายเซ็นไม่บังคับความใหม่ การหมดอายุ หรือใช้ครั้งเดียวโดยอัตโนมัติ ผู้ตรวจต้องเทียบข้อความกับคำขอและบันทึกว่าคำท้าถูกใช้แล้วเมื่อใด

## เปิดกระเป๋าเต็มที่ต้องการ

เชื่อม mainnet core ที่ทำงานจากเทอร์มินัล:

```sh
blocknet attach mainnet
```

ในเชลล์โต้ตอบ โหลดกระเป๋าและตรวจที่อยู่:

```text
load
address
```

เลือกไฟล์ที่ตั้งใจและปลดล็อกผ่านไคลเอนต์เมื่อระบบขอ เทียบที่อยู่เต็มกับที่ผู้ตรวจคาด แม้คุณเก็บหลายไฟล์บนเครื่องเดียวกัน

[core ที่ตรวจสอบ](https://github.com/blocknetprivacy/core/blob/5a0a5b510c1dce46f4eeb12c33a291052e44e7b3/api_handlers.go) ใช้กุญแจส่วนตัวใช้จ่ายลงนาม [กระเป๋าดูอย่างเดียว](/th/blog/blocknet-view-only-wallet/) ทำไม่ได้ เก็บกระเป๋าเต็มบนเครื่องที่ตั้งใจ ผู้ตรวจต้องการเพียงลายเซ็นผลลัพธ์กับข้อมูลสาธารณะ ไม่ต้องส่งเงินหรือส่งออกไฟล์กระเป๋าเพื่อทำขั้นตอนลงนาม

## เตรียมข้อความตรงตัวก่อนลงนาม

อ่านคำขอทั้งหมดและแน่ใจว่าตั้งใจตามจุดประสงค์ ไคลเอนต์ทางการอ่านหนึ่งบรรทัด ตัดช่องว่างต้นท้าย และปฏิเสธข้อความว่างหรือเกิน 1024 ไบต์ ขีดจำกัดนับไบต์ ดังนั้นอักขระที่ไม่ใช่ ASCII อาจใช้มากกว่าหนึ่งไบต์ ใช้บรรทัดสั้นที่ไม่กำกวม และเก็บข้อความที่ส่งตรงตัว

คงตัวพิมพ์ใหญ่เล็ก เครื่องหมาย และช่องว่างภายในเมื่อส่งให้ผู้ตรวจ โปรแกรมแก้ข้อความหรือแชตอาจเปลี่ยนอัญประกาศหรือข้อความที่คัดลอก จึงเทียบข้อความจริงหากตรวจไม่ผ่าน สำหรับเข้าสู่ระบบหรือบัญชี ทำตามรูปแบบคำท้าที่บริการระบุ อย่าแก้คำขอเงียบ ๆ เพราะผู้ตรวจต้องตรวจคำท้าเฉพาะที่ออกให้

## ลงนามในเชลล์ทางการ

เริ่มพรอมต์ในเชลล์โต้ตอบ:

```text
sign
```

ไคลเอนต์ถามข้อความ วางหนึ่งบรรทัดที่ตกลงแล้วกด Enter เมื่อสำเร็จจะแสดงลายเซ็นฐานสิบหก คัดลอกผลทั้งหมดโดยคงทุกตัวอักษร [โค้ดไคลเอนต์](https://github.com/blocknetprivacy/blocknet/blob/948af4de8b7a3e3cddc86a329c7d2d003cb3fd6b/attach_wallet.go) ส่งข้อความไปจุดลงนามกระเป๋า การดำเนินการนี้ไม่สร้างหรือเผยแพร่ธุรกรรม

ให้ที่อยู่เต็ม ข้อความตรงตัว และลายเซ็นเป็นคนละค่า ระบุชื่อชัดเจนไม่ให้สับสนลายเซ็นกับข้อความหรือที่อยู่ เก็บ seed กู้คืน กุญแจส่วนตัว และรหัสกระเป๋าเป็นส่วนตัว [คู่มือ seed](/th/blog/seed-phrase-explained/) อธิบายข้อมูลกู้คืน ซึ่งไม่ควรอยู่ในหลักฐานที่ส่งให้คนตรวจลายเซ็น

## อีกฝ่ายตรวจลายเซ็นอย่างไร?

ใช้พรอมต์ตรวจในเชลล์ทางการกับ core ที่รองรับและทำงานอยู่:

```text
verify
```

กรอกที่อยู่เต็มก่อน ตามด้วยข้อความตรงตัว แล้วลายเซ็นฐานสิบหก [เอกสารเชลล์](https://github.com/blocknetprivacy/blocknet/blob/948af4de8b7a3e3cddc86a329c7d2d003cb3fd6b/docs/reference-core.md) ระบุลำดับนี้ การตรวจไม่ต้องโหลดกระเป๋า ผู้ตรวจจึงไม่ต้องนำเข้ากระเป๋าผู้ลงนามหรือจับกุญแจส่วนตัว

ไคลเอนต์ที่ตรวจสอบแสดง `Signature is VALID` เมื่อชุดข้อมูลตรวจผ่าน และ `Signature is INVALID` เมื่อไม่ผ่าน ข้อผิดพลาดรูปแบบเป็นผลอีกแบบ ให้ตรวจทุกช่องและเก็บหลักฐานเดิมก่อนลองใหม่ หากข้อความหรือที่อยู่ไม่ตรงคำขอ ให้แก้ความต่างแม้ลายเซ็นถูกต้องทางคณิตศาสตร์สำหรับค่าที่ส่งมา

## อ่านความสำเร็จตามบริบทคำขอ

ลายเซ็นถูกต้องตรวจข้อความกับกุญแจสาธารณะใช้จ่ายที่เข้ารหัสในที่อยู่ ไม่ยืนยันตัวตนตามกฎหมาย แสดงยอด หรือพิสูจน์ว่าจ่ายแล้ว สำหรับคำถามการชำระ ใช้ [บันทึกส่ง](/th/blog/send-receive-blocknet/) [ค้นตัวสำรวจ](/th/blog/blocknet-explorer-guide/) และหลักฐานเฉพาะธุรกรรม เลือกสิ่งที่ตอบคำถามจริงแทนการถือว่าทุกลายเซ็นถูกต้องเป็นใบรับเงิน

ตรวจความใหม่ของคำท้าและผู้รับที่ตั้งใจก่อนยอมรับ ใครก็อาจคัดลอกข้อความกับลายเซ็นถูกต้องและยื่นคู่เดิมอีก บริการที่ต้องอนุมัติครั้งเดียวต้องบังคับเอง เช่นเดียวกับวันหมดอายุในข้อความจะมีความหมายเมื่อผู้ตรวจเช็ก การตรวจเหล่านี้เชื่อมความถูกต้องทางเข้ารหัสกับการดำเนินการที่ตกลง

## เก็บบันทึกการตรวจให้ชัดเจน

หากงานต้องมีประวัติตรวจสอบ เก็บที่อยู่ ข้อความตรงตัว ลายเซ็น บริบทคำขอ และผลด้วยกัน บันทึกเวลาตรวจแยกจากเวลาที่ผู้ลงนามเขียน หลีกเลี่ยงข้อมูลส่วนตัวไม่เกี่ยวข้องในข้อความ เพราะใครได้รับข้อความลงนามก็อ่านและคัดลอกได้ แชร์กับผู้ตรวจที่ตั้งใจผ่านช่องทางตกลง

หากใช้กระเป๋ารับเงินขุด [การติดตามพูล](https://bntpool.com/blog/th/track-your-miner-on-bntpool/) ยังเป็นแหล่งบันทึกแชร์และจ่ายของพูล ลายเซ็นไม่แทนบันทึกนั้น [คู่มือโหนด](/th/blog/run-blocknet-node/) อธิบาย core ที่เชลล์ทางการต้องใช้ เมื่อจบการตรวจที่ตกลง เก็บสิทธิ์ลงนามในกระเป๋าเต็มและให้ผู้ตรวจผลใช้การตรวจสาธารณะ
