Blocknet 결제 하나를 지갑이 만드는 구성 요소에 따라 살펴봅니다. 기존 자금, 새 출력, 거스름돈, 네트워크 수수료입니다. 이 안내는 한 사람에게 보내는 결제에 여러 출력이 생기는 이유와 지갑 출력을 사용한다고 그 가치 전부를 수신자에게 주는 것은 아닌 이유를 설명합니다. 회계 예시에는 가상의 금액을 사용하며 구현 기준은 출시된 core v0.22.0 지갑입니다.

## Blocknet 거래는 자금을 어떻게 이동하나요?

<Answer>
지갑은 자신이 소유한 사용 가능한 출력을 골라 입력으로 쓰고 수신자와 필요한 거스름돈을 위한 새 출력을 만듭니다. 선택한 가치는 수신 금액과 네트워크 수수료를 충당합니다. 프라이버시 증명으로 네트워크가 결제를 검증하고, 지갑은 사용자에게 속한 새 출력을 알아봅니다.
</Answer>

## 지갑이 이미 소유한 출력부터 시작하기

출력은 이전 거래가 만든 가치의 한 조각입니다. 아직 사용하지 않았고 성숙 규칙을 만족하면 지갑은 새 결제에 이를 선택할 수 있습니다. 잔액에는 이전 수신, 채굴 지급금, 거스름돈에서 생긴 여러 조각이 포함될 수 있습니다. 보통 직접 선택할 필요는 없습니다.

지갑이 `3 BNT`를 결제하기 위해 `10 BNT` 가치의 출력을 선택했다고 가정해 봅시다. 기존 출력은 통째로 사용됩니다. 새 거래가 그 가치를 수신자, 거스름돈, 수수료에 배분합니다. 지갑의 다른 출력은 그대로 둘 수 있으며 선택한 합계가 전체 잔액일 필요는 없습니다.

여러 작은 출력도 하나의 결제를 충당할 수 있습니다. [출시된 지갑 생성기](https://github.com/blocknetprivacy/core/blob/5a0a5b510c1dce46f4eeb12c33a291052e44e7b3/wallet/builder.go)는 수신 금액과 수수료를 충당할 만큼 성숙한 자금을 선택합니다. 입력 선택과 크기 기반 수수료 추정은 서로 영향을 주므로 현재 지갑 미리보기가 중요합니다. [거래 수수료 안내](/ko/blog/blocknet-transaction-fees/)는 계산 방법과 확인 위치를 설명합니다.

[![거래 예시: 1에서 10 BNT 선택, 2에서 수신자에게 3 BNT 전송, 3에서 거스름돈 6.9995 BNT 반환, 4에서 네트워크 수수료 0.0005 BNT 계산.](/assets/blog/blocknet-transaction-explained-flow.svg)](/assets/blog/blocknet-transaction-explained-flow.svg)

그림을 지갑 회계로 읽어 보세요. **1**은 선택한 입력, **2**는 수신자 출력, **3**은 자신의 거스름돈 출력, **4**는 수수료입니다. 숫자는 설명용이며 수수료는 가정한 값이지 제시된 견적이 아닙니다. 화살표는 소유권과 가치 배분을 보여 주며 탐색기에 공개되는 연결을 뜻하지 않습니다.

## 한 번의 결제로 여러 출력이 생기는 이유는?

이 예시에서는 `10 BNT = 3 BNT + 6.9995 BNT + 0.0005 BNT`입니다. 수신자는 `3 BNT`를 받고, 자신의 지갑은 거스름돈 `6.9995 BNT`를 받으며, 거래는 가정한 수수료 `0.0005 BNT`를 지불합니다. 한 사람에게만 지급하려 했지만 새 지갑 출력은 두 개 생깁니다. 수수료는 거래의 별도 필드이며 세 번째 수신자 출력이 아닙니다.

출력 두 개는 유용한 예시이지 모든 결제의 규칙은 아닙니다. 생성기는 여러 수신자를 지원하며 고급 입력 선택 경로에서는 거스름돈을 여러 출력으로 나눌 수 있습니다. 선택한 가치가 수신자 금액과 수수료를 정확히 충당하면 거스름돈 출력이 필요 없습니다. 전액 보내기는 선택한 사용 가능 합계에서 수수료를 뺀 뒤 수신 금액을 계산합니다.

따라서 출력 개수는 거래 구조를 설명합니다. 고객, 청구서, 서로 다른 지갑의 수를 세는 것이 아닙니다. 여러 출력이 같은 지갑에 속할 수 있고 입력이 여러 개인 거래도 수신자 한 명에게 지급할 수 있습니다. 지갑의 결제 기록과 탐색기의 더 짧은 구조 요약을 비교할 때 이 차이를 기억하세요.

## 거스름돈은 어디로 가나요?

지갑은 자신의 키를 위한 거스름돈을 만듭니다. 예시에서 원래의 `10 BNT` 출력은 소비되고 거스름돈 `6.9995 BNT`는 같은 지갑이 인식할 수 있는 새 출력이 됩니다. 일반적인 보내기 과정에서는 두 번째 수신자를 입력하거나 거스름돈 주소를 직접 복사할 필요가 없습니다.

수신자 출력과 거스름돈은 일회용 출력 키를 사용합니다. 공개 거래에 익숙한 수신 주소가 “거스름돈”이라는 표시 옆에 실리는 것은 아닙니다. 지갑에는 자신의 출력을 식별하는 데 필요한 비공개 정보가 있습니다. [스텔스 주소 안내](/ko/blog/stealth-addresses-explained/)는 이러한 일회용 키와 재사용 가능한 수신 주소의 관계를 설명합니다.

거스름돈도 새로 생성된 출력의 규칙을 따릅니다. 전송 후 잔액 일부가 여전히 자신의 소유이면서 확인이나 성숙을 기다릴 수 있습니다. 새 거스름돈이 대기 중이어도 손대지 않은 성숙한 출력은 계속 사용할 수 있습니다. 다음 결제를 준비할 때 사용 가능 잔액을 확인하세요. [전송 시간 안내](/ko/blog/blocknet-transfer-time/)는 전파부터 사용 가능해질 때까지의 단계를 설명합니다.

## 네트워크의 검증과 탐색기의 표시는?

각 실제 입력에는 가능한 이전 출력 사이에 자신을 놓는 프라이버시 증명이 있습니다. 다른 링 구성원은 미끼이며 소유자의 자금을 자신의 결제에 보태지 않습니다. 키 이미지는 어느 링 구성원이 실제 출처인지 공개하지 않고도 네트워크가 반복 사용을 감지하게 합니다. 이 방식은 [링 서명](/ko/blog/ring-signatures-explained/)에서 설명합니다.

네트워크는 금액 커밋먼트와 증명도 검증하며 수수료를 포함해 거래의 수지가 맞는지도 확인합니다. [범위 증명 안내](/ko/blog/bulletproofs-explained/)는 금액이 숨겨진 상태에서 이런 검사가 작동하는 방법을 설명합니다. 공개 거래 데이터에는 거래 해시, 입력과 출력 구조, 수수료가 포함됩니다. 탐색기에 해시를 붙여 넣는 것만으로 예시의 비공개 회계가 드러나지는 않습니다.

자신의 수신액과 거스름돈을 식별할 때는 지갑을 쓰세요. 공개 거래 및 블록 상태는 [탐색기](/ko/blog/blocknet-explorer-guide/)를 사용하세요. [결제 정보 공개 범위 안내](/ko/blog/blocknet-payment-visibility/)는 송신자, 수신자, 제삼자가 알 수 있는 정보와 의도적으로 공유하는 방법을 비교합니다.

## 확인 과정에서 결제 따라가기

보내기를 확정하기 전에 수신자 정보, 수신 금액, 수수료, 거스름돈을 함께 읽으세요. 제출 후 거래 해시는 모든 입력과 출력을 포함한 전체 거래를 식별합니다. 수신 주소도, 수신자 출력 하나만의 식별자도 아닙니다.

전파, 블록 포함, 사용 가능 상태는 서로 다른 단계입니다. 수신자 지갑은 자신의 키에 속한 출력을 찾고 자신의 지갑은 거스름돈을 인식합니다. 확인과 성숙에 따라 새 출력을 이후 거래에 사용할 수 있는 시점이 정해집니다. [보내기와 받기 안내](/ko/blog/send-receive-blocknet/)는 실제 지갑 단계를 다룹니다.

결제에 관한 의문은 의도한 금액과 지갑 기록부터 살펴본 뒤 거래 상태를 확인하세요. 이렇게 하면 무엇을 선택했는지, 수신자가 무엇을 받았는지, 무엇이 거스름돈으로 돌아왔는지, 무엇이 아직 대기 중인지 파악할 수 있습니다. 자금이 원래 다른 사람에게서 왔든 [채굴 풀 지급금](https://bntpool.com/blog/pool-payout-missing-from-wallet/)에서 왔든 같은 방식이 적용됩니다.
