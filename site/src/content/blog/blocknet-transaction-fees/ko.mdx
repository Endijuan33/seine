Blocknet 결제를 확정하기 전에 무엇이 사용될지 확인하세요. 이 가이드는 검토한 지갑의 네트워크 수수료 추정 방식, 입력 선택의 중요성, 수신액·수수료·거스름돈의 관계를 설명합니다. 문서에 나온 명령줄 지갑의 미리보기 위치도 알려 주어 결제를 전파하지 않고 살펴볼 수 있게 합니다.

## Blocknet 거래 수수료는 어떻게 계산하나요?

<Answer>
검토한 지갑은 보수적인 거래 크기 추정치와 설정된 최소액으로 수수료를 정합니다. 선택한 입력과 생성할 출력이 추정에 영향을 줍니다. 수수료는 수신액과 별개이며 쓰지 않은 입력 가치는 거스름돈이 됩니다. 확정 전에 해당 결제의 현재 미리보기를 검토하세요.
</Answer>

## 지갑 계산과 단위 이해하기

[검토한 데몬 코드](https://github.com/blocknetprivacy/core/blob/514a8cf4c686728147ac4756a9fc7bc9a48552b1/api_handlers.go)의 일반 전송 경로는 최소 1,000 최소 단위와 추정 바이트당 10 최소 단위를 사용합니다. 1 BNT는 100,000,000 최소 단위이므로 각각 0.00001 BNT와 추정 바이트당 0.0000001 BNT입니다. 이는 2026년 10월 26일 확인한 구현 설정이며 모든 지갑 버전의 견적이 아닙니다.

계산은 최소액과 추정 크기×단가 중 큰 값을 택합니다. 명시적으로 예시인 5,000바이트를 가정하면 5,000 × 10 = 50,000 최소 단위, 즉 0.0005 BNT로 명시된 최소액보다 큽니다. 가정한 크기의 산술 예시이지 측정한 거래나 다음 전송 수수료의 약속이 아닙니다.

## 두 결제의 수수료가 다른 이유는 무엇인가요?

지갑은 기존 출력을 거래 입력으로 소비하고 수신자와 필요하면 거스름돈 출력을 생성합니다. [거래 생성기](https://github.com/blocknetprivacy/core/blob/514a8cf4c686728147ac4756a9fc7bc9a48552b1/wallet/builder.go)는 입력 수, 출력 수, 링 크기로 거래 크기를 추정하며 증명을 위한 보수적 여유분도 포함합니다. 추정 크기는 단순한 주소, 메모, 결제 양식의 글자 수가 아닙니다.

여러 작은 가용 출력으로 구성한 결제는 큰 출력 하나로 충당하는 결제와 입력 수가 다를 수 있습니다. 지갑은 충분한 사용 가능 가치를 고를 때 수수료도 고려하므로 선택과 추정은 서로 영향을 줍니다. 따라서 수신액이 같아도 지갑 상태가 다르면 수수료가 같을 필요가 없습니다. 관련 개인정보 보호 구조는 [링 서명](/ko/blog/ring-signatures-explained/)과 [범위 증명](/ko/blog/bulletproofs-explained/)을 보세요.

## 수신액, 수수료, 거스름돈 구분하기

일반적인 고정액 전송에서는 선택한 입력이 수신액과 수수료를 충당하고 나머지는 거스름돈으로 돌아옵니다. 예를 들어 입력 합계 10 BNT, 수신액 3 BNT, 가정한 수수료 0.0005 BNT라면 거스름돈은 6.9995 BNT입니다. 수신자는 지정한 3 BNT를 받습니다. 거스름돈은 추가 요금이 아닙니다.

이 예는 선택한 입력을 설명하며 지갑 전체 잔액과 같다는 뜻은 아닙니다. 다른 출력은 그대로 남을 수 있습니다. 전액 보내기는 목적이 다릅니다. 검토한 구현은 선택한 사용 가능 합계에서 수수료를 빼 수신액을 정합니다. 표시된 총잔액을 그대로 모두 보낼 수 있다고 가정하지 말고 해당 작업의 금액을 읽으세요.

## 보내기 전에 수수료를 어떻게 확인하나요?

[문서화된 CLI 클라이언트](https://github.com/blocknetprivacy/blocknet/blob/948af4de8b7a3e3cddc86a329c7d2d003cb3fd6b/attach_wallet.go)는 전송 흐름에서 모의 미리보기를 요청하고 `Confirm [y/N]:` 전에 금액, 목적지, 수수료와 거스름돈이 있으면 이를 표시합니다. 일반 지갑 흐름에 자신의 수신 정보와 의도한 금액을 넣고 검토 단계에서 멈추세요. [지갑 가이드](/ko/blog/blocknet-wallet-for-mining/)는 준비와 주소 찾기를 설명합니다.

목적지와 금액을 먼저 읽고 수수료와 거스름돈을 확인하세요. 계산만 보려면 확인 질문에서 Enter를 누르거나 아니요로 답하세요. 클라이언트는 전송 요청 대신 취소합니다. 이 가이드는 시험 결제를 요구하지 않습니다. 그래픽 지갑은 다른 문구를 쓸 수 있으므로 CLI 배치와 같다고 가정하지 말고 해당 검토 화면을 살펴보세요.

## 미리보기가 바뀌면 무엇을 확인하나요?

CLI 미리보기와 최종 전송은 별도 요청입니다. 실제 전송은 그때의 지갑 상태로 구성되므로 미리보기가 제시한 수수료를 영구 예약하지 않습니다. 금액, 수신자, 선택한 출력, 사용 가능 자금이 바뀌면 결과가 달라질 수 있습니다. 검토 중 동시 지출을 피하고 결제를 수정하면 새 미리보기를 받으세요.

금액과 수수료를 충당하지 못할 때 총잔액 대신 사용 가능한 자금을 확인하세요. 아직 확인 중인 자금은 별도 범주입니다. 미리보기를 만들 수 없다면 지갑 버전과 정확한 메시지를 기록하세요. 채굴 지급 수령은 [지갑 입금 가이드](https://bntpool.com/blog/ko/pool-payout-missing-from-wallet/)가 거래와 지갑 스캔을 따라갑니다. 새로 보낼 결제의 비용 계산과는 다른 작업입니다.

## 네트워크와 채굴 수수료 구분하기

이 글의 수수료는 지갑 거래에 속합니다. 풀 수수료는 풀 보상 계산에, 채굴기 개발자 수수료는 채굴 소프트웨어의 작업 정책에 관련됩니다. 기준과 단계가 다릅니다. [채굴 수수료 가이드](https://bntpool.com/blog/ko/mining-pool-fees-vs-miner-fees/)는 채굴 쪽을 설명합니다. 거기 나오는 비율을 지갑 거래 크기 추정에 적용하지 마세요.

마찬가지로 풀 최소 지급액은 잔액 기준이지 일반 지갑 전송의 수수료 견적이 아닙니다. 전송 계획에서 각 수치의 이름과 출처를 함께 유지하세요. 준비하는 발신 결제를 확인할 곳은 지갑 미리보기입니다. 채굴 계산기나 풀 잔액 화면이 이를 대신하지 못합니다.

## 명확한 결제 기록 남기기

의도한 결제를 확정하기 전에 목적지, 금액, 사용하는 경우 메모, 수수료, 거스름돈을 함께 검토하세요. [결제 링크](/ko/blog/blocknet-payment-links/)가 정보를 채워 줄 수 있지만 지갑에서 다시 검토해야 합니다. 절차를 문서화할 때 추정치를 준 지갑 버전을 기록하여 이후 독자가 날짜가 있는 예시와 현재 화면을 구분하게 하세요.

의도적으로 확정한 전송 후에는 거래 ID를 자신의 결제 기록에 보관하고 지갑에서 상태를 추적하세요. 수수료를 설명하려고 복구 단어나 개인 키를 공유하지 마세요. 지원 질문에는 지갑의 비공개 데이터를 복사하는 것보다 버전, 작업 유형, 표시 금액이 보통 더 유용합니다. 새 결제마다 미리보기를 다시 확인하세요.
