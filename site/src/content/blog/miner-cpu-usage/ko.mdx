seine v0.2.36으로 Blocknet을 채굴할 때 CPU 사용률을 활성 스레드, 로컬 H/s, 승인된 셰어와 함께 읽으세요. 설정을 바꾸기 전에 이 순서로 확인합니다. 설치는 [채굴 가이드](/ko/blog/how-to-mine-blocknet/)에서 시작하세요.

## 낮은 CPU 사용률은 유용한 작업도 적다는 뜻인가요?

<Answer>
CPU 비율만으로 완료한 유용한 작업량을 알 수 없습니다. 선택한 CPU 백엔드, 활성 스레드 수, 로컬 해시레이트와 수신 작업을 확인하세요. seine은 논리 프로세서보다 적은 채굴 스레드를 선택할 수 있습니다. 수를 바꾸기 전에 일관된 조건에서 완료한 작업을 비교하세요.
</Answer>

## 먼저 비율의 범위를 읽으세요

Windows에서 seine 프로세스와 전체 컴퓨터를 구분하세요. 작업 관리자에서 seine을 찾고 성능과 CPU를 엽니다. 논리 프로세서 그래프는 부하 분포, 전체 수치는 컴퓨터 전체 활동을 나타냅니다. [Microsoft 가이드](https://learn.microsoft.com/en-us/troubleshoot/windows-server/support-tools/support-tools-task-manager)를 참고하고 사용한 보기를 기록하세요.

Linux의 `top` 프로세스 비율은 시스템 요약과 척도가 다를 수 있습니다. Irix 모드에서 다중 스레드 프로세스는 100%를 넘을 수 있고 Solaris는 프로세서 수로 나눕니다. 스레드 보기는 행을 바꿉니다. [매뉴얼](https://man7.org/linux/man-pages/man1/top.1.html)을 읽으세요. 척도 변화는 측정된 채굴 속도 변화가 아닙니다.

## 어떤 장치가 작업하는지 확인하세요

[seine 대시보드](/ko/blog/seine-dashboard-explained/) CPU 행의 H/s와 스레드를 읽으세요. CPU/GPU 합산에는 둘 다 포함되므로 같은 장치를 비교합니다. 명령이 NVIDIA만 선택하면 낮은 CPU 채굴 부하는 정상입니다. [NVIDIA 가이드](/ko/blog/mine-blocknet-nvidia-gpu/)를 참고하세요.

활성 채굴 스레드와 OS 프로세스 스레드 수는 다릅니다. seine에는 네트워크, 제어, 보고 작업도 있습니다. 프로세스 스레드는 CPU 행보다 많을 수 있습니다. 확인할 것은 활성 해싱 스레드 수와 작업 완료 여부입니다.

## 메모리가 스레드 수를 제한하는 이유는요?

활성 CPU 스레드는 Argon2id용 2 GiB 영역을 각각 사용합니다. 자동 산정은 가용 메모리와 시스템 여유를 고려합니다. 설치 RAM을 나눈 값을 보장 용량으로 삼지 말고 실제 수와 메시지를 읽으세요. [RAM 가이드](/ko/blog/how-much-ram-to-mine-blocknet/)는 예산, 여유분, 할당을 설명합니다.

용량은 담을 수 있는 영역 수, 대역폭은 동시 데이터 이동 효율을 결정합니다. 메모리를 기다리는 스레드도 사용 중으로 집계될 수 있습니다. 낮은 사용률만으로 대역폭 병목을 증명할 수 없고 100%도 최고 H/s를 증명하지 않습니다. [Argon2id 가이드](/ko/blog/argon2id-proof-of-work-explained/)를 보세요.

## 자동 변화와 명시적 설정을 읽으세요

자동 CPU 튜닝은 측정한 작업으로 스레드와 계산 커널을 비교합니다. 적은 수가 유효한 결과일 수 있고 가용 메모리 변화도 영향을 줍니다. 시험이 안정될 때까지 기다리고 메시지를 읽으세요. [튜닝 가이드](/ko/blog/seine-automatic-cpu-tuning/)는 결정과 캐시 재사용을 설명합니다.

실제 실행 명령을 보세요. `--threads`, 튜닝 상한, CPU 프로필은 탐색이나 수를 바꾸고 선호도 설정은 배치를 바꿉니다. 컨테이너, 가상 머신, OS 제한으로 호스트보다 적은 실행 자원이 보일 수 있습니다. 구성을 기록하고 늘리기 전에 제한을 확인하세요.

## 사용률과 H/s가 모두 떨어진다면?

CPU 백엔드가 활성이고 작업이 있는지 확인하세요. 현재 작업, 연결, 메모리 조정, 백엔드 오류를 로그에서 찾습니다. 시작이나 새 튜닝 시험의 맥락은 OS 미터에 없습니다. GPU가 계속 작동하면 장치 상태를 따로 보세요.

같은 버전, 백엔드, 설정의 안정된 기간을 비교하세요. 다른 앱, 메모리, 전원 설정과 시간을 기록합니다. 반복 가능한 비교에는 [벤치마크 가이드](/ko/blog/benchmark-seine-miner/)를 따르고 보고서를 보관하세요. 짧은 최고치나 한 비율은 하드웨어 측정 결과가 아닙니다.

## 완료 및 승인된 작업으로 마무리하세요

일반 채굴에서 CPU 해시 진행과 셰어 승인 응답을 확인하세요. 셰어는 간격을 두고 오며 고정 카운트다운은 없습니다. 풀은 시간에 따른 제출로 해시레이트를 추정합니다. [추적 가이드](https://bntpool.com/blog/ko/track-your-miner-on-bntpool/)는 이 관측과 연결을 설명합니다.

버전, 명령, 백엔드, CPU 스레드, CPU H/s, OS 도구와 보기, 메모리, 풀 관측 기간을 기록하세요. 작업이 진행되면 전체 비율은 맥락입니다. 한 단계가 멈추면 해당 가이드를 따르세요. 각 변경에 구체적 질문과 비교 가능한 결과를 갖출 수 있습니다.
