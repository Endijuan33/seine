อ่านการใช้ CPU ร่วมกับเธรดที่ทำงาน H/s ในเครื่อง และแชร์ที่ยอมรับขณะขุด Blocknet ด้วย seine v0.2.36 ตรวจตามลำดับนี้ก่อนเปลี่ยนค่า การติดตั้งเริ่มจาก[คู่มือขุด](/th/blog/how-to-mine-blocknet/)

## ใช้ CPU น้อยแปลว่างานที่มีประโยชน์น้อยหรือไม่?

<Answer>
เปอร์เซ็นต์ CPU อย่างเดียวไม่บอกปริมาณงานที่มีประโยชน์ซึ่งเสร็จแล้ว ตรวจแบ็กเอนด์ CPU ที่เลือก เธรดที่ทำงาน แฮชเรตในเครื่อง และงานที่รับเข้า seine อาจเลือกเธรดขุดน้อยกว่าจำนวนหน่วยประมวลผลเชิงตรรกะ เปรียบเทียบงานที่เสร็จในสภาวะเดียวกันก่อนเปลี่ยนจำนวน
</Answer>

## ดูขอบเขตของเปอร์เซ็นต์ก่อน

บน Windows แยกโปรเซส seine ออกจากทั้งเครื่อง ค้นหาใน Task Manager แล้วเปิด Performance และ CPU กราฟหน่วยประมวลผลเชิงตรรกะแสดงการกระจายโหลด ส่วนค่ารวมครอบคลุมเครื่อง [คู่มือ Microsoft](https://learn.microsoft.com/en-us/troubleshoot/windows-server/support-tools/support-tools-task-manager) อธิบายมุมมองเหล่านี้ จดว่าคุณใช้มุมมองใด

บน Linux เปอร์เซ็นต์โปรเซสใน `top` อาจใช้สเกลต่างจากสรุประบบ โหมด Irix อาจแสดงโปรเซสหลายเธรดเกิน 100%; Solaris หารด้วยจำนวนโปรเซสเซอร์ มุมมองเธรดเปลี่ยนแถวที่แสดง อ่าน[คู่มือ](https://man7.org/linux/man-pages/man1/top.1.html) การเปลี่ยนสเกลไม่ใช่ผลวัดว่าความเร็วขุดเปลี่ยน

## ตรวจว่าอุปกรณ์ใดกำลังทำงาน

อ่าน H/s และเธรดในแถว CPU ของ[แดชบอร์ด seine](/th/blog/seine-dashboard-explained/) ค่ารวม CPU/GPU มีทั้งสองอุปกรณ์ จึงต้องเทียบอุปกรณ์เดียวกัน หากคำสั่งเลือกเฉพาะ NVIDIA โหลดขุด CPU ต่ำเป็นสิ่งที่คาดได้ ดู[คู่มือ NVIDIA](/th/blog/mine-blocknet-nvidia-gpu/)

จำนวนเธรดขุดต่างจากจำนวนเธรดโปรเซสที่ OS แสดง seine ยังมีงานเครือข่าย ควบคุม และรายงาน โปรเซสจึงอาจมีเธรดมากกว่าแถว CPU สิ่งที่ต้องดูคือเธรดคำนวณแฮชที่ทำงานและงานที่เสร็จ

## ทำไมหน่วยความจำจำกัดจำนวนเธรด?

เธรด CPU ที่ทำงานแต่ละเธรดใช้พื้นที่ 2 GiB สำหรับ Argon2id การกำหนดอัตโนมัติคำนึงถึงหน่วยความจำที่ว่างและเผื่อระบบ อ่านจำนวนจริงและข้อความ อย่าหาร RAM ที่ติดตั้งแล้วถือเป็นความจุที่รับประกัน [คู่มือ RAM](/th/blog/how-much-ram-to-mine-blocknet/) อธิบายงบ พื้นที่สำรอง และการจัดสรร

ความจุบอกว่ารองรับพื้นที่ได้กี่ชุด แบนด์วิดท์มีผลต่อการย้ายข้อมูลพร้อมกัน เธรดอาจยังถูกนับว่าใช้งานขณะรอหน่วยความจำ การใช้ต่ำจึงไม่พิสูจน์คอขวดแบนด์วิดท์ และ 100% ก็ไม่พิสูจน์ H/s ที่ดีที่สุด ดู[คู่มือ Argon2id](/th/blog/argon2id-proof-of-work-explained/)

## อ่านการเปลี่ยนอัตโนมัติและค่าที่กำหนดเอง

การปรับ CPU อัตโนมัติเปรียบเทียบเธรดและเคอร์เนลคำนวณด้วยงานที่วัดได้ จำนวนน้อยกว่าอาจถูกต้อง และหน่วยความจำที่เปลี่ยนก็มีผล รอการทดลองนิ่งแล้วอ่านข้อความ [คู่มือปรับแต่ง](/th/blog/seine-automatic-cpu-tuning/) อธิบายการตัดสินใจและแคช

ตรวจคำสั่งที่รันจริง `--threads` ค่าสูงสุดการปรับ หรือโปรไฟล์ CPU อาจเปลี่ยนขอบเขตค้นหาหรือจำนวน ส่วน affinity เปลี่ยนตำแหน่งรัน คอนเทนเนอร์ VM และข้อจำกัด OS อาจให้ทรัพยากรน้อยกว่าโฮสต์ บันทึกค่าและหาข้อจำกัดก่อนเพิ่มจำนวน

## ถ้าการใช้และ H/s ลดลงพร้อมกันล่ะ?

ตรวจว่าแบ็กเอนด์ CPU ทำงานและมีงาน ดูงานปัจจุบัน การเชื่อมต่อ การปรับหน่วยความจำ และข้อผิดพลาดในบันทึก ช่วงเริ่มต้นหรือทดลองปรับใหม่มีบริบทที่มิเตอร์ OS ไม่แสดง หาก GPU ยังทำงาน ให้ดูแต่ละอุปกรณ์แยกกัน

เปรียบเทียบช่วงนิ่งด้วยรุ่น แบ็กเอนด์ และค่าเดียวกัน จดแอปอื่น หน่วยความจำ พลังงาน และเวลา หากต้องการเทียบซ้ำได้ ให้ตาม[คู่มือเบนช์มาร์ก](/th/blog/benchmark-seine-miner/) และเก็บรายงาน ยอดชั่วครู่หรือเปอร์เซ็นต์เดียวไม่ใช่ผลทดสอบฮาร์ดแวร์

## จบด้วยงานที่เสร็จและยอมรับ

ในการขุดปกติ ตรวจว่าแฮช CPU เดินหน้าและมีคำตอบยอมรับแชร์ แชร์มาถึงเป็นช่วง ไม่ใช่การนับถอยหลังคงที่ พูลประเมินแฮชเรตจากการส่งในช่วงเวลา [คู่มือติดตาม](https://bntpool.com/blog/th/track-your-miner-on-bntpool/) อธิบายมุมมองนี้และการเชื่อมต่อ

จดรุ่น คำสั่ง แบ็กเอนด์ เธรด CPU H/s CPU เครื่องมือและมุมมอง OS หน่วยความจำ และช่วงสังเกตพูล หากงานเดินหน้า เปอร์เซ็นต์รวมเป็นบริบท หากขั้นใดหยุดให้ตามคู่มือขั้นนั้น การเปลี่ยนค่าจึงตอบคำถามชัดเจนและเทียบผลได้
