Blocknet 지갑 잔액을 지연시키는 단계가 노드의 체인 다운로드인지, 지갑 출력 스캔인지, 아직 사용 불가능한 결제인지 확인하세요. 이 안내는 2026년 10월 27일 확인한 공식 CLI v1.2.0과 공개 core v0.22.0을 따릅니다. 생성 또는 복원한 지갑으로 시작하세요. 준비는 [지갑 설정 안내](/ko/blog/blocknet-wallet-for-mining/)에 있습니다.

## Blocknet 지갑은 왜 아직 동기화 중인가요?

<Answer>
노드의 체인 진행과 피어 연결을 확인한 뒤 불러온 지갑의 스캔을 보세요. 노드는 블록을 모으고 지갑은 그 안에서 결제를 찾습니다. 주소와 네트워크를 검증하고 진행 중인 스캔을 끝낸 뒤, 내역을 사용 가능·대기·미확인 잔액과 비교하여 필요한 조치를 판단하세요.
</Answer>

## 올바른 지갑과 네트워크로 시작하기

터미널에서 기존 mainnet 세션을 여세요.

```sh
blocknet attach mainnet
```

대화형 셸 안에서 지갑을 여세요.

```text
load
```

예상한 파일을 선택하세요. 불러왔지만 잠겼다면 클라이언트 프롬프트에서 비밀번호로 잠금을 해제하세요. 잠금 메시지는 접근 상태이며 노드가 블록 다운로드를 멈췄다는 뜻이 아닙니다.

셸에서 다음 명령을 각각 실행하세요.

```text
address
status
```

주소를 자신의 수취 기록과 비교하세요. Mainnet과 testnet은 별도 core와 지갑을 씁니다. 선택한 파일도 확인하세요. 새 빈 지갑을 열어도 옛 주소가 복원되지는 않습니다. Core가 실행되지 않거나 attach가 연결되지 않으면 [노드 안내](/ko/blog/run-blocknet-node/)를 따르세요.

## 노드와 지갑 스캔 중 무엇이 뒤처지나요?

노드 상태는 체인 진행과 네트워크 연결을 설명합니다. 지갑에는 자체 스캔 높이가 있습니다. [검토한 클라이언트](https://github.com/blocknetprivacy/blocknet/blob/948af4de8b7a3e3cddc86a329c7d2d003cb3fd6b/attach_wallet.go)의 잔액 경고는 스캔 위치를 체인이나 동기화 목표와 비교합니다. 따라서 로컬 체인이 최신이어도 지갑 잔액은 따라잡는 중일 수 있습니다. 상태 단어 하나 대신 두 단계를 읽으세요.

지갑 출력을 확인하세요.

```text
outputs
```

일치하는 출력이 없고 스캔이 뒤처지면 클라이언트가 체인 높이 대비 스캔 높이를 표시합니다. 나중 값을 이전 값과 비교하세요. 높이 증가는 진행을 뜻하며 빈 목록 하나로 결제가 없다고 판단할 수 없습니다. 비교를 위해 높이와 관측 시각을 기록하세요.

## 로컬 체인이 뒤처지면 연결 확인하기

노드 자체가 뒤처지면 연결된 피어를 보세요.

```text
peers
```

피어가 없으면 컴퓨터 인터넷과 노드 방화벽 설정을 확인하세요. 노드 안내와 [공식 문제 해결 참조](https://github.com/blocknetprivacy/blocknet/blob/948af4de8b7a3e3cddc86a329c7d2d003cb3fd6b/docs/troubleshooting.md)를 함께 사용하세요. 피어 수뿐 아니라 시간에 따른 체인 높이도 보세요. 피어 연결과 다운로드 완료는 서로 다른 질문에 답합니다.

기록에서 노드 시작과 지갑 스캔을 구분하세요. 새 노드가 과거 데이터를 받는다면 그 단계를 진행시킨 뒤 더 나중의 결제를 지갑이 스캔했는지 평가하세요. [체크포인트 안내](https://bntpool.com/blog/ko/blocknet-checkpoints-fast-sync/)는 기존 빠른 동기화 경로를 설명합니다. 지갑을 반복 생성하거나 체인 데이터를 삭제해도 어느 단계가 진행 중인지 파악하는 데 도움이 되지 않습니다.

## 지갑 sync는 언제 실행하나요?

올바른 지갑이 열려 있고 출력 기록이 다운로드된 블록을 따라잡아야 할 때 스캔 명령을 쓰세요.

```text
sync
```

[셸 참조](https://github.com/blocknetprivacy/blocknet/blob/948af4de8b7a3e3cddc86a329c7d2d003cb3fd6b/docs/reference-core.md)는 로컬 블록에서 자신의 출력을 찾는 스캔으로 설명합니다. 피어에서 블록을 받는 것과 별도인 지갑 작업입니다. 같은 값을 다시 확인하기 전에 스캔할 시간을 주세요.

명령은 스캔 높이와 발견한 출력 또는 이미 최신이라는 상태를 알려 줍니다. 완료 후 출력과 잔액을 다시 확인하세요. 클라이언트가 시간 초과를 알리면 재실행 전에 현재 진행을 확인하세요. 클라이언트 시간 초과만으로 스캐너의 최종 위치를 알 수는 없습니다. 진단 중 원본 지갑 파일과 복구 백업을 보관하세요.

## 기록으로 예상 결제 하나 추적하기

보내는 사람의 내역이나 풀의 전송된 지급 기록에서 전체 거래 ID를 사용하세요. [탐색기 안내](/ko/blog/blocknet-explorer-guide/)는 네트워크 상태와 포함 블록 확인 방법을 설명합니다. 공개 포함 기록은 거래 위치를, 받는 지갑은 비공개 출력을 식별합니다. 공개 주소 잔액 페이지를 기대하지 말고 수취 정보를 자신의 기록과 비교하세요.

이어서 지갑 자체 기록을 확인하세요.

```text
history
balance
```

대기 또는 미확인 금액은 사용 가능한 자금과 다릅니다. 그 범주에 있다면 없다고 판단하지 말고 확인 상태를 추적하세요. 채굴 수익의 경우 [풀에서 지갑까지의 안내](https://bntpool.com/blog/ko/pool-payout-missing-from-wallet/)가 미지급 풀 잔액, 실제 지급, 지갑 수취를 구분합니다.

## 스캔이 끝났는데 금액이 다르다면?

파일, 전체 수취 주소, 네트워크, 거래 ID를 함께 재확인하세요. 같은 결제와 잔액 범주를 비교하는지 확인하세요. 보기 전용 지갑은 입금 감시에, 전체 지갑은 사용 가능 자금 판단에 쓰세요. [보기 전용 설정 안내](/ko/blog/blocknet-view-only-wallet/)가 이 구분을 설명합니다. 스캔 완료는 지갑 유형을 바꾸지 않습니다.

올바른 전체 지갑이 최신인데도 기록이 맞지 않으면 공식 복구 절차 전에 파일과 백업을 보존하세요. [시드 안내](/ko/blog/seed-phrase-explained/)는 복구 자료를, 설정 안내는 가져오기를 설명합니다. 복구는 지갑 소프트웨어에서 해야 합니다. 시드, 개인 키, 지갑 파일, 비밀번호를 공개 지원 게시물에 넣지 마세요.

## 검증한 내용을 짧게 기록하기

후속 확인을 위해 클라이언트와 core 버전, 네트워크, 노드 높이, 스캔 높이, 피어 수, 정확한 오류를 적으세요. 관측 사이 값이 진행됐는지도 기록하세요. 로그를 공유한다면 질문에 불필요한 비공개 경로, 결제 정보, 인증 정보를 제거하세요. 간단한 기록은 지갑 접근을 노출하지 않고 필요한 단계를 설명합니다.

대상을 좁혀 확인한 뒤 같은 지갑의 내역과 잔액으로 돌아오세요. 원하는 결과는 의도한 결제가 실제 현재 상태로 나타나고 해당 스캔이 따라잡은 것입니다. [보내기와 받기 안내](/ko/blog/send-receive-blocknet/)는 최종 수취 확인을 원래 결제 흐름에 연결합니다. 이후 확인도 같은 작업을 추적하도록 거래 ID를 보관하세요.
