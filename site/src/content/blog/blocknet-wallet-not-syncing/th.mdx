หาว่าขั้นใดทำให้ยอด Blocknet ล่าช้า: โหนดดาวน์โหลดเชน กระเป๋าสแกนเอาต์พุต หรือเงินยังไม่พร้อมใช้ คู่มือนี้อ้างอิง CLI ทางการ v1.2.0 และ core สาธารณะ v0.22.0 ที่ตรวจเมื่อ 27 ตุลาคม 2026 เริ่มจากกระเป๋าที่สร้างหรือกู้คืนแล้ว [คู่มือตั้งค่ากระเป๋า](/th/blog/blocknet-wallet-for-mining/) อธิบายการเตรียมนี้

## ทำไมกระเป๋า Blocknet ยังซิงก์อยู่?

<Answer>
ตรวจความคืบหน้าเชนและเพียร์ของโหนด แล้วตรวจการสแกนกระเป๋าที่โหลด โหนดรวบรวมบล็อก กระเป๋าค้นหาการชำระเงินในบล็อกนั้น ตรวจที่อยู่กับเครือข่าย ปล่อยการสแกนที่คืบหน้าให้เสร็จ แล้วเทียบประวัติกับยอดใช้จ่ายได้ รอดำเนินการ และยังไม่ยืนยัน ก่อนตัดสินใจว่าต้องแก้ตรงไหน
</Answer>

## เริ่มด้วยกระเป๋าและเครือข่ายที่ถูกต้อง

เปิดเซสชัน mainnet ที่มีอยู่จากเทอร์มินัล:

```sh
blocknet attach mainnet
```

ในเชลล์โต้ตอบ เปิดกระเป๋า:

```text
load
```

เลือกไฟล์ที่คาดไว้ หากโหลดแล้วแต่ล็อก ให้ปลดล็อกด้วยรหัสผ่านที่พรอมต์ ข้อความว่ากระเป๋าล็อกบอกสถานะการเข้าถึง ไม่ได้ยืนยันว่าโหนดหยุดดาวน์โหลดบล็อก

เรียกคำสั่งเหล่านี้แยกกันในเชลล์:

```text
address
status
```

เทียบที่อยู่กับบันทึกรับเงินของคุณ Mainnet และ testnet ใช้ core และกระเป๋าแยกกัน ตรวจไฟล์ที่เลือกด้วย การเปิดกระเป๋าว่างใหม่ไม่กู้คืนที่อยู่เก่า ใช้ [คู่มือโหนด](/th/blog/run-blocknet-node/) หาก core ไม่ทำงานหรือ attach เชื่อมต่อไม่ได้

## โหนดช้าหรือการสแกนกระเป๋าช้า?

สถานะโหนดบอกความคืบหน้าเชนและเครือข่าย กระเป๋ามีความสูงที่สแกนของตัวเอง ใน [ไคลเอนต์ที่ตรวจสอบ](https://github.com/blocknetprivacy/blocknet/blob/948af4de8b7a3e3cddc86a329c7d2d003cb3fd6b/attach_wallet.go) คำเตือนยอดเปรียบเทียบตำแหน่งสแกนกับเชนหรือเป้าหมายซิงก์ ดังนั้นเชนในเครื่องอาจเป็นปัจจุบันแต่ยอดกระเป๋ายังตามอยู่ อ่านทั้งสองขั้นแทนการเชื่อคำสถานะคำเดียว

ตรวจเอาต์พุตกระเป๋า:

```text
outputs
```

หากไม่มีเอาต์พุตตรงกันและสแกนยังช้า ไคลเอนต์จะแสดงความสูงสแกนเทียบความสูงเชน เปรียบเทียบค่าครั้งหลังกับครั้งก่อน ความสูงสแกนที่เพิ่มแสดงความคืบหน้า รายการว่างครั้งเดียวไม่พอจะสรุปว่าเงินหาย จดความสูงและเวลาที่ดูเพื่อเปรียบเทียบ

## ตรวจการเชื่อมต่อเมื่อเชนตามไม่ทัน

ถ้าโหนดเองล่าช้า ให้ตรวจเพียร์ที่เชื่อมต่อ:

```text
peers
```

ไม่มีเพียร์ให้ตรวจอินเทอร์เน็ตและไฟร์วอลล์ของโหนด ใช้ [เอกสารแก้ปัญหาทางการ](https://github.com/blocknetprivacy/blocknet/blob/948af4de8b7a3e3cddc86a329c7d2d003cb3fd6b/docs/troubleshooting.md) คู่กับคู่มือโหนด ติดตามความสูงเชนตามเวลาอีกด้วย การมีเพียร์กับดาวน์โหลดครบตอบคนละคำถาม

จดแยกการเริ่มโหนดกับการสแกนกระเป๋า หากโหนดใหม่กำลังดาวน์โหลดประวัติ ให้ขั้นนั้นเดินหน้าก่อนตัดสินว่ากระเป๋าสแกนการชำระเงินภายหลังแล้วหรือยัง [คู่มือเช็กพอยต์](https://bntpool.com/blog/th/blocknet-checkpoints-fast-sync/) อธิบายวิธีซิงก์เร็วที่มีอยู่ การสร้างกระเป๋าหรือลบข้อมูลเชนซ้ำไม่ช่วยระบุว่าขั้นไหนกำลังคืบหน้า

## ควรใช้ sync ของกระเป๋าเมื่อไร?

ใช้คำสั่งสแกนเมื่อเปิดกระเป๋าที่ถูกต้องและบันทึกเอาต์พุตต้องตามบล็อกที่ดาวน์โหลดให้ทัน:

```text
sync
```

[เอกสารเชลล์](https://github.com/blocknetprivacy/blocknet/blob/948af4de8b7a3e3cddc86a329c7d2d003cb3fd6b/docs/reference-core.md) อธิบายว่าเป็นการสแกนบล็อกในเครื่องหาเอาต์พุตที่เป็นเจ้าของ เป็นงานกระเป๋าที่แยกจากการรับบล็อกจากเพียร์ ให้เวลาทำงานก่อนตรวจค่าเดิมอีกครั้ง

คำสั่งรายงานความสูงสแกนและเอาต์พุตที่พบ หรือว่ากระเป๋าเป็นปัจจุบันแล้ว ตรวจเอาต์พุตและยอดหลังเสร็จ หากไคลเอนต์แจ้งหมดเวลารอ ให้ดูความคืบหน้าก่อนเรียกซ้ำ การหมดเวลาฝั่งไคลเอนต์อย่างเดียวไม่บอกตำแหน่งสุดท้ายของตัวสแกน เก็บไฟล์เดิมและสำรองกู้คืนไว้ระหว่างวินิจฉัย

## ติดตามเงินที่คาดว่าจะได้รับผ่านบันทึก

ใช้ ID เต็มจากประวัติผู้ส่งหรือบันทึกจ่ายที่ส่งแล้วของพูล [คู่มือตัวสำรวจ](/th/blog/blocknet-explorer-guide/) แสดงการตรวจสถานะเครือข่ายและบล็อกที่บรรจุ บันทึกบรรจุสาธารณะบอกว่าธุรกรรมอยู่ไหน กระเป๋ารับระบุเอาต์พุตส่วนตัว เทียบรายละเอียดรับกับบันทึกของคุณ แทนการคาดหวังหน้าสาธารณะยอดตามที่อยู่

แล้วตรวจบันทึกของกระเป๋าเอง:

```text
history
balance
```

ยอดรอหรือยังไม่ยืนยันต่างจากเงินที่ใช้ได้ หากยอดอยู่ในหมวดนั้นให้ตามการยืนยันแทนการถือว่าไม่มี สำหรับรายได้ขุด [คู่มือจากพูลสู่กระเป๋า](https://bntpool.com/blog/th/pool-payout-missing-from-wallet/) แยกยอดพูลที่ยังไม่จ่าย การจ่ายจริง และการรับในกระเป๋า

## สแกนเสร็จแต่ยอดยังต่างล่ะ?

ตรวจไฟล์ ที่อยู่รับเต็ม เครือข่าย และ ID พร้อมกัน ยืนยันว่าเทียบเงินรายการเดียวกันและหมวดเดียวกัน หากเป็นกระเป๋าดูอย่างเดียว ใช้ติดตามเงินเข้าและใช้กระเป๋าเต็มในการตัดสินใจใช้จ่าย [คู่มือตั้งค่าดูอย่างเดียว](/th/blog/blocknet-view-only-wallet/) อธิบายการแยกนี้ การสแกนเสร็จไม่เปลี่ยนชนิดกระเป๋า

หากกระเป๋าเต็มที่ถูกต้องเป็นปัจจุบันแต่ยังเทียบบันทึกไม่ได้ ให้เก็บไฟล์กับสำรองก่อนทำตามขั้นตอนกู้คืนทางการ [คู่มือ seed](/th/blog/seed-phrase-explained/) อธิบายข้อมูลกู้คืน ส่วนคู่มือตั้งค่าอธิบายการนำเข้า กู้คืนในซอฟต์แวร์กระเป๋าเท่านั้น อย่าใส่ seed กุญแจส่วนตัว ไฟล์กระเป๋า หรือรหัสผ่านในโพสต์ขอความช่วยเหลือสาธารณะ

## จดสั้น ๆ ว่าตรวจอะไรแล้ว

สำหรับติดตามต่อ จดเวอร์ชันไคลเอนต์และ core เครือข่าย ความสูงโหนด ความสูงสแกน จำนวนเพียร์ และข้อความผิดพลาดตรงตัว ระบุว่าค่าเพิ่มระหว่างการดูหรือไม่ หากแชร์ล็อกให้ลบพาธส่วนตัว รายละเอียดชำระเงิน และข้อมูลเข้าสู่ระบบที่ไม่จำเป็น บันทึกสั้นช่วยอธิบายขั้นที่ต้องดูโดยไม่เปิดเผยสิทธิ์เข้ากระเป๋า

กลับมาประวัติและยอดกระเป๋าเดิมหลังตรวจตรงจุด ผลที่เป็นประโยชน์คือรายการที่ต้องการปรากฏด้วยสถานะจริงปัจจุบันและการสแกนที่เกี่ยวข้องตามทัน [คู่มือส่งและรับ](/th/blog/send-receive-blocknet/) เชื่อมการตรวจรับสุดท้ายกับขั้นตอนเดิม เก็บ ID ไว้เพื่อให้การตรวจครั้งต่อไปตามการดำเนินการเดียวกัน
