确定是什么阶段延迟了 Blocknet 钱包余额更新：节点下载链、钱包扫描输出，还是付款尚不可花费。本指南依据 2026 年 10 月 27 日检查的官方 CLI v1.2.0 和公开 core v0.22.0。请从已创建或恢复的钱包开始；[钱包设置指南](/zh-hans/blog/blocknet-wallet-for-mining/)介绍这项准备。

## 为什么 Blocknet 钱包仍在同步？

<Answer>
先检查节点的链进度和对等连接，再查看已加载钱包的扫描进度。节点收集区块，钱包在其中寻找您的付款。核实地址和网络，让正在推进的扫描完成，将历史与可花费、待处理和未确认余额比较，再决定需要处理哪一环节。
</Answer>

## 从正确的钱包和网络开始

在终端打开现有的 mainnet 会话：

```sh
blocknet attach mainnet
```

在交互式 shell 中打开钱包：

```text
load
```

选择预期的钱包文件。如果已加载但被锁定，请通过客户端提示输入密码解锁。钱包锁定消息描述的是访问状态，并不能证明节点停止下载区块。

在 shell 中分别执行这些命令：

```text
address
status
```

将地址与自己的收款记录比较。Mainnet 与 testnet 使用独立的 core 和钱包。也要检查所选文件：打开新的空钱包不会恢复旧地址。如果 core 未运行或 attach 无法连接，请按[节点指南](/zh-hans/blog/run-blocknet-node/)处理。

## 落后的是节点还是钱包扫描？

节点状态描述链进度和网络连接，钱包有自己的已扫描高度。在[已检查的客户端](https://github.com/blocknetprivacy/blocknet/blob/948af4de8b7a3e3cddc86a329c7d2d003cb3fd6b/attach_wallet.go)中，余额警告会将扫描位置与链或同步目标比较。因此，本地链已更新，钱包余额仍可能在追赶。请同时读取两个阶段，不要只依赖一个状态词。

检查钱包输出：

```text
outputs
```

当没有匹配输出且扫描落后时，客户端会报告扫描高度与链高度。比较前后两次读数。扫描高度增加表示在推进；一次空列表不足以判定付款缺失。记录高度和观察时间，才能进行有效比较。

## 本地链落后时检查连接

如果节点本身落后，请查看已连接的对等节点：

```text
peers
```

没有对等节点时，检查计算机的互联网连接和节点防火墙设置。结合节点指南使用[官方故障排查资料](https://github.com/blocknetprivacy/blocknet/blob/948af4de8b7a3e3cddc86a329c7d2d003cb3fd6b/docs/troubleshooting.md)。除了连接数，也要观察链高度随时间的变化：存在连接与下载完成回答的是不同问题。

在笔记中区分节点启动和钱包扫描。新节点正在下载历史时，先让这一阶段推进，再判断钱包是否扫描到了更晚的付款。[检查点指南](https://bntpool.com/blog/zh-hans/blocknet-checkpoints-fast-sync/)解释现有的快速同步路径。反复创建钱包或删除链数据无助于判断哪个阶段在推进。

## 何时运行钱包 sync 命令？

当目标钱包已打开，输出记录需要赶上已下载区块时，使用扫描命令：

```text
sync
```

[Shell 参考](https://github.com/blocknetprivacy/blocknet/blob/948af4de8b7a3e3cddc86a329c7d2d003cb3fd6b/docs/reference-core.md)将其描述为扫描本地区块以查找自有输出。这是钱包操作，与从对等节点获取区块分开。再次查看同一指标前，请给扫描留出运行时间。

命令会报告扫描高度与发现的输出，或说明钱包已是最新。完成后重新检查输出和余额。如果客户端报告超时，请先检查当前进度再重复操作；仅有客户端超时不能说明扫描器的最终位置。诊断期间保留原钱包文件和恢复备份。

## 通过记录追踪一笔预期付款

使用发送方历史或矿池已发送付款记录中的完整交易 ID。[浏览器指南](/zh-hans/blog/blocknet-explorer-guide/)介绍如何检查网络状态和所在区块。公开纳入记录说明交易在哪里，收款钱包识别其非公开输出。将收款信息与自己的付款记录比较，不要期待浏览器提供公开地址余额页面。

然后检查钱包自身记录：

```text
history
balance
```

待处理或未确认金额不同于可花费资金。如果金额已出现在这些类别中，请追踪其确认状态，不要把它当作缺失。对于挖矿收入，[从矿池到钱包的指南](https://bntpool.com/blog/zh-hans/pool-payout-missing-from-wallet/)区分矿池未付余额、实际付款与钱包收款。

## 扫描完成后金额仍不符怎么办？

一并重新检查钱包文件、完整收款地址、网络和交易 ID。确认比较的是同一笔付款和同一余额类别。如果是只读钱包，请用它监控入账，用完整钱包决定哪些资金可花费；[只读设置指南](/zh-hans/blog/blocknet-view-only-wallet/)解释这一区别。完成扫描不会改变钱包类型。

如果正确的完整钱包已经更新，但记录仍无法核对，请在按官方恢复流程操作前保存文件和备份。[种子指南](/zh-hans/blog/seed-phrase-explained/)解释恢复资料，设置指南负责导入步骤。恢复应在钱包软件中完成。切勿将种子、私钥、钱包文件或密码放入公开求助帖子。

## 简要记录已验证的内容

为后续检查记录客户端和 core 版本、所选网络、节点高度、扫描高度、对等节点数及准确错误文本。注明两次观察之间数值是否推进。共享日志时，删除问题不需要的私密路径、付款详情和凭据。简洁记录能说明需要处理的阶段，而不暴露钱包访问权限。

完成针对性检查后，返回同一钱包的历史和余额。有效结果是预期付款以真实当前状态出现，且相关扫描已赶上。[发送与接收指南](/zh-hans/blog/send-receive-blocknet/)将最后的收款检查连接到原始付款流程。保存交易 ID，让后续检查继续追踪同一操作。
