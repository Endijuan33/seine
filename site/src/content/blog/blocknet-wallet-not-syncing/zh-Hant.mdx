確定是哪個階段延遲了 Blocknet 錢包餘額更新：節點下載鏈、錢包掃描輸出，或付款尚不可花費。本指南依據 2026 年 10 月 27 日檢查的官方 CLI v1.2.0 和公開 core v0.22.0。請從已建立或還原的錢包開始；[錢包設定指南](/zh-hant/blog/blocknet-wallet-for-mining/)介紹這項準備。

## 為什麼 Blocknet 錢包仍在同步？

<Answer>
先檢查節點的鏈進度和對等連線，再查看已載入錢包的掃描進度。節點收集區塊，錢包在其中尋找您的付款。核實地址和網路，讓正在推進的掃描完成，將歷史與可花費、待處理和未確認餘額比較，再決定需要處理哪一環節。
</Answer>

## 從正確的錢包和網路開始

在終端機開啟現有的 mainnet 工作階段：

```sh
blocknet attach mainnet
```

在互動式 shell 中開啟錢包：

```text
load
```

選擇預期的錢包檔案。如果已載入但被鎖定，請透過用戶端提示輸入密碼解鎖。錢包鎖定訊息描述的是存取狀態，並不能證明節點停止下載區塊。

在 shell 中分別執行這些指令：

```text
address
status
```

將地址與自己的收款紀錄比較。Mainnet 與 testnet 使用獨立的 core 和錢包。也要檢查所選檔案：開啟新的空錢包不會還原舊地址。如果 core 未執行或 attach 無法連線，請按[節點指南](/zh-hant/blog/run-blocknet-node/)處理。

## 落後的是節點還是錢包掃描？

節點狀態描述鏈進度和網路連線，錢包有自己的已掃描高度。在[已檢查的用戶端](https://github.com/blocknetprivacy/blocknet/blob/948af4de8b7a3e3cddc86a329c7d2d003cb3fd6b/attach_wallet.go)中，餘額警告會將掃描位置與鏈或同步目標比較。因此，本機鏈已更新，錢包餘額仍可能在追趕。請同時讀取兩個階段，不要只依賴一個狀態詞。

檢查錢包輸出：

```text
outputs
```

當沒有相符輸出且掃描落後時，用戶端會報告掃描高度與鏈高度。比較前後兩次讀數。掃描高度增加表示在推進；一次空清單不足以判定付款缺失。記錄高度和觀察時間，才能進行有效比較。

## 本機鏈落後時檢查連線

如果節點本身落後，請查看已連線的對等節點：

```text
peers
```

沒有對等節點時，檢查電腦的網際網路連線和節點防火牆設定。搭配節點指南使用[官方疑難排解資料](https://github.com/blocknetprivacy/blocknet/blob/948af4de8b7a3e3cddc86a329c7d2d003cb3fd6b/docs/troubleshooting.md)。除了連線數，也要觀察鏈高度隨時間的變化：存在連線與下載完成回答的是不同問題。

在筆記中區分節點啟動和錢包掃描。新節點正在下載歷史時，先讓這一階段推進，再判斷錢包是否掃描到較晚的付款。[檢查點指南](https://bntpool.com/blog/zh-hant/blocknet-checkpoints-fast-sync/)解釋現有的快速同步途徑。反覆建立錢包或刪除鏈資料無助於判斷哪個階段在推進。

## 何時執行錢包 sync 指令？

當目標錢包已開啟，輸出紀錄需要趕上已下載區塊時，使用掃描指令：

```text
sync
```

[Shell 參考](https://github.com/blocknetprivacy/blocknet/blob/948af4de8b7a3e3cddc86a329c7d2d003cb3fd6b/docs/reference-core.md)將其描述為掃描本機區塊以尋找自有輸出。這是錢包操作，與從對等節點取得區塊分開。再次查看同一指標前，請給掃描留出執行時間。

指令會報告掃描高度與發現的輸出，或說明錢包已是最新。完成後重新檢查輸出和餘額。如果用戶端報告逾時，請先檢查目前進度再重複操作；僅有用戶端逾時不能說明掃描器的最終位置。診斷期間保留原錢包檔案和復原備份。

## 透過紀錄追蹤一筆預期付款

使用傳送方歷史或礦池已傳送付款紀錄中的完整交易 ID。[瀏覽器指南](/zh-hant/blog/blocknet-explorer-guide/)介紹如何檢查網路狀態和所在區塊。公開納入紀錄說明交易在哪裡，收款錢包識別其非公開輸出。將收款資訊與自己的付款紀錄比較，不要期待瀏覽器提供公開地址餘額頁面。

然後檢查錢包本身的紀錄：

```text
history
balance
```

待處理或未確認金額不同於可花費資金。如果金額已出現在這些類別中，請追蹤確認狀態，不要把它當作缺失。對於挖礦收入，[從礦池到錢包的指南](https://bntpool.com/blog/zh-hant/pool-payout-missing-from-wallet/)區分礦池未付餘額、實際付款與錢包收款。

## 掃描完成後金額仍不符怎麼辦？

一併重新檢查錢包檔案、完整收款地址、網路和交易 ID。確認比較的是同一筆付款和同一餘額類別。如果是唯讀錢包，請用它監控入帳，用完整錢包決定哪些資金可花費；[唯讀設定指南](/zh-hant/blog/blocknet-view-only-wallet/)解釋這個區別。完成掃描不會改變錢包類型。

如果正確的完整錢包已更新，但紀錄仍無法核對，請在按官方復原流程操作前儲存檔案和備份。[種子指南](/zh-hant/blog/seed-phrase-explained/)解釋復原資料，設定指南負責匯入步驟。復原應在錢包軟體中完成。切勿將種子、私鑰、錢包檔案或密碼放入公開求助貼文。

## 簡要記錄已驗證的內容

為後續檢查記錄用戶端和 core 版本、所選網路、節點高度、掃描高度、對等節點數及準確錯誤文字。註明兩次觀察之間數值是否推進。分享日誌時，刪除問題不需要的私密路徑、付款詳情和憑證。簡潔紀錄能說明需要處理的階段，而不暴露錢包存取權。

完成針對性檢查後，返回同一錢包的歷史和餘額。有效結果是預期付款以真實目前狀態出現，且相關掃描已趕上。[傳送與接收指南](/zh-hant/blog/send-receive-blocknet/)將最後的收款檢查連接到原始付款流程。儲存交易 ID，讓後續檢查繼續追蹤同一操作。
