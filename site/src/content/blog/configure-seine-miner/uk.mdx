Запускайте майнер Blocknet із передбачуваними налаштуваннями. Посібник для seine v0.2.37 пояснює місце збереження, пріоритет аргументів і постійні зміни. Почніть із робочої інсталяції; заміну програми описує [посібник оновлення](/uk/blog/update-seine-miner/).

## Як seine вибирає налаштування?

<Answer>
seine поєднує збережені параметри підключення з аргументами запуску. Явні аргументи переважають відповідні значення файлу. Каталог даних визначає файл для читання. Параметри обладнання та виконання залишаються аргументами запуску: зберігайте і конфігурацію, і звичайну команду.
</Answer>

## Знайдіть файл, який справді використовується

Типово це `./seine-data/seine.config.json` відносно робочого каталогу процесу, який може відрізнятися від папки програми. Перед редагуванням перевірте термінал, ярлик або службу. Різні запуски однієї програми можуть використовувати різні папки даних.

`--data-dir` вибирає базовий каталог; назва залишається `seine.config.json`. Для запусків із різних місць використовуйте сталий абсолютний шлях. Запишіть програму, робочий каталог, дані та всі аргументи. [Посібник запуску Windows](/uk/blog/start-miner-automatically-windows/) показує ці шляхи, зокрема з пробілами, у Планувальнику завдань.

## Які налаштування належать файлу?

Приклад показує основні поля підключення. Замініть `@yourname` своїм зареєстрованим Blocknet ID або повною адресою отримання. Це зразок формату, не команда. У наявній інсталяції змінюйте потрібні поля замість заміни всього файлу.

```json
{
  "schema_version": 1,
  "mode": "pool",
  "address": "@yourname",
  "pool_url": "stratum+tcp://bntpool.com:3333",
  "pool_worker": "desktop-01"
}
```

`mode`, `address`, `pool_url` і `pool_worker` визначають режим, отримувача, пул і назву машини. Збережіть `schema_version` та наявне `dev_fee_pool_worker`. Останнє — окрема згенерована мітка; для своєї машини використовуйте `pool_worker`. Не записуйте сюди сід-фразу й приватні ключі.

## Як зробити зміну постійною?

Зупиніть майнер і скопіюйте файл. Використовуйте текстовий редактор, правильний JSON із подвійними лапками та первинну назву без додаткового розширення. Змінюйте лише потрібне поле у правильному каталозі. Перевірте коми, уникайте коментарів і кінцевих ком; за можливості використайте перевірку JSON редактора. Копія дозволяє точно порівняти старі значення.

Перевірте запуск на аргументи, що перекривають це поле. Старий `--address` переважає нову адресу у файлі. Оновіть аргумент або видаліть для використання збереженого значення. Запустіть звичайним ярликом, скриптом чи завданням і перевірте дієві налаштування.

## Свідомо використовуйте тимчасові параметри

За наявної конфігурації наведена опція пулу задає назву машини для цього запуску. Наступного разу без неї повернеться збережена назва. Це зручно для контрольованої зміни; для постійного використання додайте опцію до звичайного запуску.

```text
--pool-worker desktop-02
```

Під час першого запуску без файлу seine створює його з початкових даних підключення. Це відрізняється від тимчасової заміни наявних значень. Пам’ятайте про це, копіюючи команду на інший комп’ютер, який створює першу конфігурацію. [Довідник налаштування](https://github.com/zpalmtree/seine/blob/v0.2.37/docs/guides/configuration.md) описує початкові запити й параметри.

## Тримайте параметри обладнання в команді

`--backend` і `--threads` — аргументи запуску. Схема підключення не є переліком усіх опцій. Подібне поле JSON не задає відповідний параметр виконання. Зберігайте вибір обладнання у скрипті, ярлику або службі.

Керування потоками на панелі змінює сеанс без збереження нового типового значення. Автоналаштування має власні кеші. Зберігайте їх окремо від змін підключення й дозволяйте кожній машині підлаштовуватися під обладнання. [Посібник автоналаштування](/uk/blog/seine-automatic-cpu-tuning/) пояснює кеш і явний вибір потоків.

## Чому налаштування наче скинулися?

Порівняйте шлях даних і аргументи з останнім успішним запуском. Нова папка розпакування, інший термінал чи старі аргументи завдання можуть пояснити різницю. За помилки розбору спочатку прочитайте файл і повідомлення. Відновіть копію або виправте JSON, потім запустіть один раз потрібним способом.

Перевірте отримувача, пул, назву та прийняті шари. Повторіть звичайний запуск для перевірки збереження; один запуск з аргументами підтверджує лише цю команду. Використовуйте [посібник панелі](/uk/blog/seine-dashboard-explained/) та [зміни адреси](https://bntpool.com/blog/uk/change-mining-wallet-address/) для майбутніх нарахувань. Зберігайте робочий запуск і копію конфігурації разом.
