seine를 실행하면 터미널이 실시간 대시보드로 채워집니다. 얼마나 빠르게 해시를 계산하고 있는지, 풀이 셰어를 몇 개 승인했는지, 받을 금액이 얼마인지, 그리고 seine가 하는 모든 일의 로그가 표시됩니다. 이 글은 seine v0.2.22의 대시보드를 패널별로 살펴보며 각 항목의 의미와 숫자의 출처를 설명하고, 채굴하는 동안 자동 튜닝과 키보드 조작이 어떻게 보이는지 보여 줍니다.

![bntpool.com에서 채굴 중인 Apple M4 Max의 seine 터미널 대시보드: 현재 해시레이트 30.63 H/s, 14스레드, 셰어 5개 제출, 거부 0개, 승인 5개, 아래에 풀 잔액과 작업 및 승인된 셰어 로그](/assets/blog/seine-dashboard.webp "Apple M4 Max에서 실행 중인 seine 대시보드")

스크린샷은 Apple M4 Max가 bntpool.com에서 채굴을 시작하고 약 10분이 지난 모습으로, 2026년 10월 seine README용으로 캡처한 것입니다. 이 글의 나머지 부분은 이 스크린샷을 기준으로 설명합니다.

## seine 대시보드에는 무엇이 표시됩니까?

<Answer>
seine 대시보드에는 실시간 및 평균 해시레이트, 완료한 해시 수, 체인 높이와 네트워크 해시레이트, 채굴기 상태, 제출·거부·승인된 셰어, 장치별 해시레이트, 풀 엔드포인트와 스레드 수, bntpool.com 잔액, 그리고 시간이 기록된 로그가 표시됩니다. 채굴하는 동안 약 1초마다 갱신됩니다.
</Answer>

위에서 아래로 헤더, 세 개의 통계 패널(`HASHRATE`, `NETWORK`, `MINING`), `DEVICES`, `CONFIG`, `POOL BALANCE`, `LOG` 순서로 패널이 배치됩니다. 너비가 148칸 이상인 터미널에서는 `CONFIG`와 잔액 패널이 나란히 표시됩니다.

## 헤더: 버전, 물결, 가동 시간

헤더 제목에는 `seine v0.2.22`처럼 seine 버전이 표시됩니다. 새 릴리스가 나오면 옆에 `update vX.Y.Z available` 배지가 강조되어 나타나고, 로그에 다운로드 링크가 담긴 줄이 하나 추가됩니다. seine는 시작할 때와 12시간마다 GitHub를 확인하며, 이 확인 때문에 채굴이 중단되는 일은 없습니다.

제목 아래에서는 두 줄의 물결이 매초 한 칸씩 흘러갑니다. 풀이 셰어를 승인할 때마다(솔로 모드에서는 노드가 블록을 승인할 때마다) 금색 다이아몬드가 윗줄 오른쪽 끝에 나타나 매초 한 칸씩 왼쪽으로 이동합니다. 너비가 약 130칸인 터미널에서는 화면에 보이는 다이아몬드가 최근 2분 정도 동안 승인된 작업입니다. `uptime`은 아랫줄 끝에 있습니다.

## seine는 해시레이트를 어떻게 측정합니까?

`HASHRATE` 패널에는 세 줄이 있습니다.

- **Current**는 최근 5초 구간의 해시레이트입니다. 여기서 해시 하나는 2 GiB Argon2id 계산 하나를 완료한 것이므로, H/s는 초당 완료한 해시 수입니다. NVIDIA GPU는 작업을 몰아서 끝내기 때문에, GPU의 현재 해시레이트는 안정적으로 보이도록 30초 구간을 사용합니다.
- **Average**는 이번 세션의 모든 해시를 채굴에 쓴 시간으로 나눈 값입니다. 노드 동기화, 지갑 비밀번호 입력, 잘못된 주소 이후처럼 기다리는 시간은 빠지며, 스레드 수를 바꿔도 평균은 이어집니다.
- **Total**은 seine를 시작한 이후 완료한 해시 수입니다.

스크린샷에서 Current는 30.63 H/s, Average는 29.33 H/s입니다. Average가 낮게 시작하는 이유는 모든 스레드가 첫 해시를 마무리하고 튜너가 최대 용량보다 낮은 수준에서 시작해 올라가는 처음 몇 분이 포함되기 때문입니다. seine를 오래 실행할수록 두 값이 가까워집니다.

## 네트워크와 상태

`NETWORK` 패널에는 채굴 중인 체인의 `Height`와 네트워크 전체 해시레이트인 `Global`이 표시됩니다. 풀 모드에서 seine는 bntpool.com의 공개 통계에서 네트워크 해시레이트를 읽으며, 30초에 최대 한 번 갱신합니다.

`State`는 채굴기가 무엇을 하고 있는지 알려 줍니다. 보고 싶은 것은 초록색 `working`입니다. 풀 모드에서는 시작하거나 다시 연결할 때 다음 상태도 볼 수 있습니다.

| 상태 | 의미 |
|---|---|
| `pool-connecting` | Stratum 연결을 여는 중 |
| `pool-connected` | 연결됨, 로그인 중 |
| `pool-authenticated` | 로그인 승인됨, 첫 작업을 기다리는 중 |
| `working` | 현재 작업으로 해시 계산 중 |
| `pool-disconnected` | 연결이 끊김, seine가 스스로 다시 연결함 |
| `pool-login-rejected` | 풀이 로그인을 거부함, 로그의 `AUTH` 줄에 이유가 표시됨 |

자신의 노드로 솔로 채굴할 때는 `daemon-syncing`, `stale-tip`(새 블록이 도착해 새 템플릿을 가져오는 중), `solved` 같은 상태가 추가됩니다. seine가 무언가를 기다리는 동안에는 Current가 0으로 떨어지므로, 실제로 내지 않는 해시레이트를 표시하는 일은 없습니다.

## Submitted, Rejected, Accepted는 무엇을 뜻합니까?

`MINING` 패널은 이번 세션의 셰어를 셉니다.

- **Submitted:** seine가 풀에 보낸 셰어입니다.
- **Rejected:** 풀이 승인하지 않은 셰어입니다. 솔로 모드에서는 이 줄이 `Stale`로 표시되며, 체인이 이미 다음 블록으로 넘어간 뒤 노드에 도착한 솔루션을 셉니다.
- **Accepted:** 풀이 나에게 반영한 셰어입니다.

bntpool.com은 연결마다 셰어 난이도를 조정해 5분에 약 10개의 셰어가 나오도록 맞추므로, 해시레이트와 관계없이 약 30초마다 셰어 하나가 나오는 것이 정상입니다. 스크린샷의 10분 동안 제출 5개, 승인 5개는 순조로운 출발입니다. 지급은 승인된 셰어를 따르며, Rejected가 0이라는 것은 보낸 모든 셰어가 반영되었다는 뜻입니다.

## 장치, 설정, 풀 잔액

`DEVICES`는 채굴 백엔드별로 현재 및 평균 해시레이트를 보여 줍니다. CPU는 `cpu#1`, NVIDIA GPU는 `nvidia#1`, `nvidia#2` 순으로 표시됩니다. 아직 시작 중인 GPU는 `starting CUDA runtime`부터 `preparing NVIDIA backend`까지 진행 상황을 대신 표시합니다. 첫 실행에서는 GPU 커널을 컴파일하고 튜닝하므로 이후 실행보다 시간이 더 걸립니다.

`CONFIG`는 이번 실행의 설정을 보여 줍니다.

- **Endpoint**는 풀 주소(기본값 `stratum+tcp://bntpool.com:3333`)이며, 솔로 모드에서는 노드의 API 주소입니다. 옆에는 이 리그가 풀에 로그인할 때 쓰는 이름이 표시됩니다.
- **Threads**는 CPU 채굴 스레드 수이며, 뒤에 키보드 조작을 위한 `[+] [-]` 안내가 붙습니다.
- **Backends**는 각 백엔드를 설명합니다. `cpu#1 (14 lanes, ~28.0 GiB RAM)`은 스레드 14개가 각각 2 GiB 영역을 차지한다는 뜻이므로 14 × 2 GiB = 28 GiB입니다.

풀에서 리그를 알아보기 쉬운 이름으로 표시하려면 시작할 때 이름을 지정하십시오.

```sh
./seine --pool-worker rig-01
```

`POOL BALANCE`는 몇 초마다 bntpool.com에서 잔액을 읽어 옵니다. `Pending`은 벌었지만 아직 지급되지 않은 금액, `Paid`는 풀이 주소로 보낸 금액이며, 오른쪽의 `Miner`는 앞뒤 여섯 글자로 줄인 내 주소입니다. bntpool.com은 잔액이 0.1 BNT에 도달하면 지급합니다. 솔로 모드에서는 이 패널이 `WALLET`으로 바뀌며, 노드 지갑의 `Pending`과 `Unlocked` 잔액을 보여 줍니다.

## 로그 읽기

`LOG`는 최근 200개 항목을 보관하며, 가장 새로운 항목이 맨 아래에 있고, 각 항목에는 레벨 배지, 태그, 경과 시간이 붙습니다. 배지는 `INFO`, `OK`(무언가가 성공함), `WARN`, `ERR`, 그리고 블록을 찾았을 때의 `**`입니다. 풀에서 가장 자주 보게 되는 태그는 다음과 같습니다.

- `AUTH`: `login accepted (protocol v2, required=submit_claimed_hash)` 같은 풀 로그인
- `JOB`: 풀에서 받은 새 작업과 그 높이 및 난이도
- `SHARE`: `submitted (backend=cpu#1)`, 이어서 `accepted (backend=cpu#1)`
- `VARDIFF`: 풀이 셰어 난이도를 변경함
- `MINER`: 자동 튜닝 결정

## seine 실행 중에 자동 튜닝은 어떻게 보입니까?

seine는 바로 채굴을 시작하고 실제 채굴 작업으로 튜닝하며, 그 과정을 로그에서 볼 수 있습니다. 첫 `MINER` 줄은 `cpu-autotune | starting with N threads`이고, 새 머신에서는 `initial estimate`, seine가 이미 아는 머신에서는 `cached starting point`가 이어집니다.

그다음 현재 스레드 수, 후보 값, 다시 현재 스레드 수 순서로 설정을 번갈아 비교합니다. 각 구간은 최소 30초 동안 이어지며 최소 20개의 해시를 모읍니다. `measuring useful mining work`, `checking baseline again` 같은 줄이 보이고, `CONFIG`의 Threads 값도 함께 바뀝니다. 튜닝이 끝나면 로그에 `done`과 함께 유지하기로 한 스레드 수가 표시됩니다.

CPU 커널도 `comparing avx2 and avx512 while mining`처럼 같은 방식으로 비교하며, seine는 두 번의 비교에서 향상이 확인된 뒤에만 전환합니다(`confirmed faster ... path in two comparisons`). 선택한 설정은 캐시되므로 다음 실행은 이번 실행이 끝난 지점에서 이어집니다. 튜닝 때문에 풀에 다시 연결하거나 GPU를 다시 시작하는 일은 없습니다. 자세한 내용은 [자동 튜닝 가이드](https://github.com/zpalmtree/seine/blob/master/docs/guides/autotuning.md)에서 다루며, 최적의 스레드 수가 메모리 대역폭에 따라 정해지는 이유는 [Argon2id 해설](/ko/blog/argon2id-proof-of-work-explained/)에서 설명합니다.

## 대시보드에서 스레드 수를 바꿀 수 있습니까?

<Answer>
네. +(또는 Shift 없이 =)를 누르면 CPU 백엔드마다 스레드가 하나씩 늘고, -를 누르면 하나씩 줄어듭니다. seine는 세션 통계, 가동 시간, 평균 해시레이트를 유지하면서 새 스레드 수로 채굴 백엔드를 다시 시작합니다. 종료하려면 q나 Ctrl+C를 누르십시오. 수동으로 바꾸면 해당 실행에서는 스레드 자동 튜닝이 꺼집니다.
</Answer>

변경이 적용되는 동안 `CONFIG`에 `Restarting: 14 -> 15 threads...`가 표시되며, 끝날 때까지 추가로 누른 키는 무시됩니다. 스레드는 CPU와 RAM에 따른 자동 상한까지만 늘릴 수 있고, 직접 고른 스레드 수는 새 기본값으로 저장되지 않습니다. 처음부터 스레드 수를 고정하려면 `--threads`를 사용하십시오.

## 작은 터미널과 일반 출력

너비가 80칸보다 좁은 터미널에서는 세 개의 통계 패널이 세로로 쌓입니다. 높이가 낮은 창에서는 Threads, State, Current, Average, 셰어 수, Height를 로그 위에 표시하는 간단한 보기로 바뀝니다. 기본값인 `--ui auto`는 대화형 터미널에서만 대시보드를 표시하며, `--ui plain`은 서버, 로그 파일, 프로세스 관리자를 위해 스크롤되는 일반 로그를 출력합니다.

아직 seine를 설정하지 않았다면 [Blocknet 채굴 가이드](/ko/blog/how-to-mine-blocknet/)에서 다운로드부터 첫 승인 셰어까지 안내합니다.
