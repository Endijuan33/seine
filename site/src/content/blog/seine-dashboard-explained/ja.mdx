seine を起動すると、ターミナルにライブのダッシュボードが表示されます。ハッシュ計算の速さ、プールが受理したシェアの数、受け取れる金額、そして seine が行うすべての操作のログです。このツアーでは seine v0.2.22 をパネルごとに見ていき、各ラベルの意味とその数値がどこから来るのかを説明し、マイニング中の自動チューニングとキーボード操作の様子を紹介します。

![bntpool.com でマイニング中の Apple M4 Max 上の seine のターミナルダッシュボード。現在のハッシュレート 30.63 H/s、14 スレッド、送信したシェア 5、拒否 0、受理 5、その下にプール残高とジョブや受理されたシェアのログ](/assets/blog/seine-dashboard.webp "Apple M4 Max 上の seine のダッシュボード")

このスクリーンショットは、bntpool.com でマイニングしている Apple M4 Max の起動から約 10 分後の画面で、2026 年 10 月に seine の README 用に撮影したものです。この記事の残りではこれを参照します。

## seine のダッシュボードには何が表示されますか？

<Answer>
seine のダッシュボードには、現在と平均のハッシュレート、完了したハッシュ数、チェーンの高さとネットワークハッシュレート、マイナーの状態、送信・拒否・受理されたシェア、各デバイスのハッシュレート、プールのエンドポイントとスレッド数、bntpool.com の残高、そしてタイムスタンプ付きのログが表示されます。マイニング中は約 1 秒ごとに更新されます。
</Answer>

上から順に、ヘッダー、3 つの統計パネルの行（`HASHRATE`、`NETWORK`、`MINING`）、`DEVICES`、`CONFIG`、`POOL BALANCE`、`LOG` のパネルが並びます。幅が 148 列以上のターミナルでは、`CONFIG` と残高パネルが横に並びます。

## ヘッダー：バージョン、波、稼働時間

ヘッダーのタイトルには、`seine v0.2.22` のように seine のバージョンが表示されます。新しいリリースが出ると、その横に強調表示された `update vX.Y.Z available` バッジが現れ、ログにダウンロードリンク付きの行が 1 行追加されます。seine は起動時と 12 時間ごとに GitHub を確認し、この確認でマイニングが中断されることはありません。

タイトルの下では、2 行の波が 1 秒に 1 ステップずつ流れていきます。プールがシェアを受理するたびに（ソロモードではノードがブロックを受理するたびに）、上の行の右端に金色のダイヤモンドが現れ、1 秒に 1 列ずつ左へスクロールします。幅が約 130 列のターミナルでは、見えているダイヤモンドは直近 2 分ほどの間に受理された作業ということになります。下の行の末尾には `uptime` が表示されます。

## seine はハッシュレートをどのように測定していますか？

`HASHRATE` パネルには 3 つの行があります。

- **Current** は、直近 5 秒間の移動ウィンドウでのハッシュレートです。ここでの 1 ハッシュは 2 GiB の Argon2id 計算 1 回分なので、H/s は 1 秒あたりに完了したハッシュ数を数えています。NVIDIA GPU は作業をまとめて完了させるので、値を安定させるために 30 秒のウィンドウを使います。
- **Average** は、このセッションのすべてのハッシュをマイニングに使った時間で割った値です。待機していた時間（ノードの同期、ウォレットのパスワード入力、無効なアドレスの後など）は除外され、スレッド数を変えても平均は引き継がれます。
- **Total** は、seine を起動してから完了したハッシュの数です。

スクリーンショットでは、Current が 30.63 H/s、Average が 29.33 H/s です。Average が低めから始まるのは、最初の数分間も含まれるからです。その間は各スレッドが最初のハッシュを仕上げている途中で、チューナーも最大能力より低い状態から始めて徐々に上げていきます。seine を長く動かすほど、2 つの値は近づきます。

## ネットワークと状態

`NETWORK` パネルには、マイニングしているチェーンの `Height`（高さ）と、ネットワーク全体のハッシュレート `Global` が表示されます。プールモードでは、seine は bntpool.com の公開統計からネットワークハッシュレートを読み取り、最短で 30 秒ごとに更新します。

`State` は、マイナーが何をしているかを示します。緑色の `working` が表示されていれば正常です。プールモードでは、起動時や再接続時に次の状態も表示されます。

| 状態 | 意味 |
|---|---|
| `pool-connecting` | Stratum 接続を開いています |
| `pool-connected` | 接続済みで、ログイン中です |
| `pool-authenticated` | ログインが受理され、最初のジョブを待っています |
| `working` | 現在のジョブでハッシュを計算しています |
| `pool-disconnected` | 接続が切れました。seine は自動で再接続します |
| `pool-login-rejected` | プールがログインを拒否しました。理由はログの `AUTH` の行に表示されます |

自分のノードに対するソロマイニングでは、`daemon-syncing`、`stale-tip`（新しいブロックが届き、新しいテンプレートを取得中）、`solved` などの状態が加わります。seine が何かを待っているあいだは Current がゼロになるので、実際に出していないハッシュレートが表示されることはありません。

## Submitted、Rejected、Accepted は何を意味しますか？

`MINING` パネルは、このセッションのシェアを数えています。

- **Submitted：** seine がプールに送信したシェア。
- **Rejected：** プールが受理しなかったシェア。ソロモードではこの行は `Stale` と表示され、チェーンが先に進んだ後にノードに届いたソリューションを数えます。
- **Accepted：** プールがあなたの分として記録したシェア。

bntpool.com は接続ごとにシェアの難易度を調整し、5 分ごとに約 10 シェアになるようにしているので、ハッシュレートに関係なく、30 秒ほどに 1 シェアが普通です。スクリーンショットの、10 分後に送信 5・受理 5 という数字は順調なスタートです。支払いは受理されたシェアに基づき、Rejected がゼロなら、送ったすべてのシェアが記録されたことを意味します。

## デバイス、設定、プール残高

`DEVICES` には、各マイニングバックエンドとその現在・平均のハッシュレートが一覧表示されます。CPU は `cpu#1`、NVIDIA GPU はそれぞれ `nvidia#1`、`nvidia#2` のように続きます。起動中の GPU は、代わりに `starting CUDA runtime` から `preparing NVIDIA backend` までの進行状況を表示します。初回の起動では GPU カーネルのコンパイルとチューニングを行うので、2 回目以降より時間がかかります。

`CONFIG` には、この実行の設定が表示されます。

- **Endpoint** はプールのアドレス（デフォルトは `stratum+tcp://bntpool.com:3333`）、ソロモードではノードの API アドレスです。その横には、このリグがプールにログインする名前が表示されます。
- **Threads** は CPU マイニングスレッドの数で、その後にキーボード操作のヒント `[+] [-]` が続きます。
- **Backends** は各バックエンドの説明です。`cpu#1 (14 lanes, ~28.0 GiB RAM)` は 14 スレッドがそれぞれ 2 GiB のアリーナを保持していることを意味し、14 × 2 GiB = 28 GiB になります。

プール上でリグにわかりやすい名前を付けるには、起動時に指定します。

```sh
./seine --pool-worker rig-01
```

`POOL BALANCE` は、数秒ごとに bntpool.com から残高を読み取ります。`Pending` は獲得済みでまだ支払われていない金額、`Paid` はプールがアドレスに送金した金額で、右側の `Miner` は、先頭と末尾の 6 文字に短縮したあなたのアドレスです。bntpool.com は残高が 0.1 BNT に達すると支払います。ソロモードではこのパネルは `WALLET` になり、ノードのウォレットの `Pending` と `Unlocked` の残高を表示します。

## ログの読み方

`LOG` は最新の 200 件を保持し、最も新しいものが一番下に表示されます。各行にはレベルのバッジ、タグ、そしてどれくらい前に起きたかが付きます。バッジは `INFO`、`OK`（何かが成功）、`WARN`、`ERR`、そして解いたブロックを示す `**` です。プールで最もよく見るタグは次のとおりです。

- `AUTH`：`login accepted (protocol v2, required=submit_claimed_hash)` のような、プールへのログイン
- `JOB`：プールからの新しいジョブと、その高さと難易度
- `SHARE`：`submitted (backend=cpu#1)`、続いて `accepted (backend=cpu#1)`
- `VARDIFF`：プールがシェアの難易度を変更した
- `MINER`：自動チューニングの判断

## seine の実行中、自動チューニングはどのように見えますか？

seine はすぐにマイニングを始め、実際のマイニング作業でチューニングを行います。その様子はログで確認できます。最初の `MINER` の行は `cpu-autotune | starting with N threads` で、新しいマシンでは `initial estimate`、seine がすでにマシンを知っている場合は `cached starting point` が続きます。

そこから、設定を順番に比較していきます。現在のスレッド数、候補、そして再び現在のスレッド数です。各ウィンドウは少なくとも 30 秒続き、少なくとも 20 ハッシュを集めます。`measuring useful mining work` や `checking baseline again` のような行が表示され、`CONFIG` の Threads の数もそれに合わせて変わります。設定が決まると、ログに `done` と表示され、採用したスレッド数が示されます。

CPU カーネルも、たとえば `comparing avx2 and avx512 while mining` のように同じ方法で比較され、seine は 2 回の比較で効果が確認できたときだけ切り替えます（`confirmed faster ... path in two comparisons`）。選択はキャッシュされるので、次回の起動では今回の続きから始まります。チューニングでプールに再接続したり GPU を再起動したりすることはありません。詳細は[自動チューニングガイド](https://github.com/zpalmtree/seine/blob/master/docs/guides/autotuning.md)にあります。最適なスレッド数がメモリ帯域幅で決まる理由は、[Argon2id の解説記事](/ja/blog/argon2id-proof-of-work-explained/)で説明しています。

## ダッシュボードからスレッド数を変更できますか？

<Answer>
はい。+（または =、Shift は不要）を押すと CPU バックエンドごとにスレッドが 1 つ増え、- を押すと 1 つ減ります。seine はセッションの統計、稼働時間、平均ハッシュレートを保持したまま、新しい数でマイニングバックエンドを再起動します。終了するには q または Ctrl+C を押します。手動で変更すると、その実行ではスレッドの自動チューニングがオフになります。
</Answer>

変更の適用中は `CONFIG` に `Restarting: 14 -> 15 threads...` と表示され、完了するまでそれ以上のキー入力は無視されます。増やせるのは CPU と RAM による自動の上限までで、選んだ数は新しいデフォルトとして保存されません。最初から固定の数を使うには `--threads` を使います。

## 小さなターミナルとシンプルな出力

幅が 80 列未満のターミナルでは、3 つの統計パネルが縦に積み重なります。高さが小さいウィンドウでは、seine はコンパクトな表示に切り替わり、Threads、State、Current、Average、シェアの数、Height をログの上に表示し続けます。デフォルトの `--ui auto` は対話型のターミナルでだけダッシュボードを表示し、`--ui plain` はサーバー、ログファイル、プロセスマネージャー向けにシンプルなスクロール式のログを出力します。

まだ seine を設定していない場合は、[Blocknet のマイニングガイド](/ja/blog/how-to-mine-blocknet/)でダウンロードから最初のシェアが受理されるまでを説明しています。
