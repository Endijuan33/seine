เมื่อเริ่ม seine เทอร์มินัลจะเต็มด้วยแดชบอร์ดสด แสดงว่าคุณแฮชเร็วเท่าไร พูลรับกี่แชร์ คุณมียอดรอรับเท่าไร และบันทึกทุกสิ่งที่โปรแกรมทำ บทความนี้พาชม seine v0.2.22 ทีละส่วน อธิบายความหมายของแต่ละป้ายและที่มาของตัวเลข พร้อมแสดงการปรับจูนอัตโนมัติและการควบคุมด้วยแป้นพิมพ์ระหว่างขุด

![แดชบอร์ดเทอร์มินัลของ seine บน Apple M4 Max ที่ขุดบน bntpool.com แฮชเรตปัจจุบัน 30.63 H/s, 14 เธรด, ส่ง 5 แชร์, ปฏิเสธ 0 และยอมรับ 5 พร้อมยอดคงเหลือในพูลและบันทึกงานกับแชร์ที่ได้รับการยอมรับด้านล่าง](/assets/blog/seine-dashboard.webp "แดชบอร์ดของ seine บน Apple M4 Max")

ภาพนี้เป็น Apple M4 Max ที่ขุดบน bntpool.com หลังเริ่มประมาณสิบนาที บันทึกสำหรับ README ของ seine ในเดือนตุลาคม 2026 และใช้เป็นตัวอย่างตลอดบทความ

## แดชบอร์ดของ seine แสดงอะไร?

<Answer>
แดชบอร์ดของ seine แสดงแฮชเรตสดและเฉลี่ย แฮชที่ทำเสร็จ ความสูงเชนและแฮชเรตเครือข่าย สถานะโปรแกรมขุด แชร์ที่ส่ง ถูกปฏิเสธ และได้รับการยอมรับ แฮชเรตแต่ละอุปกรณ์ endpoint พูลและจำนวนเธรด ยอดคงเหลือ bntpool.com และบันทึกพร้อมเวลา โดยรีเฟรชประมาณวินาทีละครั้งขณะขุด
</Answer>

จากบนลงล่างมีส่วนหัว แถวสถิติสามส่วน (`HASHRATE`, `NETWORK`, `MINING`), `DEVICES`, `CONFIG`, `POOL BALANCE` และ `LOG` บนเทอร์มินัลกว้างอย่างน้อย 148 คอลัมน์ `CONFIG` และส่วนยอดคงเหลืออยู่ข้างกัน

## ส่วนหัว: เวอร์ชัน คลื่น และเวลาทำงาน

ชื่อส่วนหัวแสดงเวอร์ชัน seine เช่น `seine v0.2.22` เมื่อมีรีลีสใหม่ ป้ายเน้น `update vX.Y.Z available` ปรากฏข้างๆ และบันทึกเพิ่มหนึ่งบรรทัดพร้อมลิงก์ดาวน์โหลด seine ตรวจ GitHub ตอนเริ่มและทุก 12 ชั่วโมง โดยไม่ขัดจังหวะการขุด

ใต้ชื่อมีคลื่นสองแถวเลื่อนหนึ่งจังหวะต่อวินาที ทุกครั้งที่พูลรับแชร์ของคุณ (หรือโหนดรับบล็อกในโหมดขุดเดี่ยว) เพชรสีทองจะปรากฏในแถวบนที่ขอบขวาแล้วเลื่อนซ้ายหนึ่งคอลัมน์ต่อวินาที บนเทอร์มินัลกว้างประมาณ 130 คอลัมน์ เพชรที่เห็นจึงเป็นงานที่ได้รับการยอมรับในช่วงประมาณสองนาทีล่าสุด ส่วน `uptime` อยู่ท้ายแถวล่าง

## seine วัดแฮชเรตอย่างไร?

ส่วน `HASHRATE` มีสามบรรทัด:

- **Current** คือแฮชเรตในหน้าต่างเลื่อนห้าวินาที แฮชหนึ่งครั้งคือการคำนวณ Argon2id 2 GiB ที่เสร็จสมบูรณ์ H/s จึงนับแฮชที่เสร็จต่อวินาที GPU ของ NVIDIA ทำงานเสร็จเป็นชุด อัตราปัจจุบันของ GPU จึงใช้หน้าต่าง 30 วินาทีเพื่อให้ค่านิ่ง
- **Average** คือแฮชทั้งหมดในเซสชันหารด้วยเวลาขุด ไม่นับเวลารอ เช่นรอโหนดซิงก์ รอรหัสผ่านกระเป๋าเงิน หรือหลังใส่ที่อยู่ไม่ถูกต้อง และค่าเฉลี่ยยังคงอยู่เมื่อคุณเปลี่ยนจำนวนเธรด
- **Total** คือจำนวนแฮชที่ทำเสร็จตั้งแต่เริ่ม seine

ในภาพ Current เป็น 30.63 H/s และ Average เป็น 29.33 H/s ค่าเฉลี่ยเริ่มต่ำกว่าเพราะรวมช่วงนาทีแรกที่แต่ละเธรดยังทำแฮชแรก และตัวปรับจูนเริ่มต่ำกว่ากำลังเต็มก่อนเพิ่มขึ้น ยิ่ง seine ทำงานนาน ทั้งสองค่ายิ่งใกล้กัน

## เครือข่ายและสถานะ

ส่วน `NETWORK` แสดง `Height` ของเชนที่คุณกำลังขุดและแฮชเรตเครือข่าย `Global` ในโหมดพูล seine อ่านแฮชเรตเครือข่ายจากสถิติสาธารณะของ bntpool.com และรีเฟรชไม่ถี่กว่าทุก 30 วินาที

`State` บอกว่าโปรแกรมขุดกำลังทำอะไร `working` สีเขียวคือสถานะที่ต้องการเห็น ในโหมดพูลคุณจะพบสถานะเหล่านี้ตอนเริ่มและเชื่อมต่อใหม่ด้วย:

| สถานะ | ความหมาย |
|---|---|
| `pool-connecting` | กำลังเปิดการเชื่อมต่อ Stratum |
| `pool-connected` | เชื่อมต่อแล้ว กำลังเข้าสู่ระบบ |
| `pool-authenticated` | เข้าสู่ระบบผ่านแล้ว รอรับงานแรก |
| `working` | กำลังคำนวณแฮชของงานปัจจุบัน |
| `pool-disconnected` | การเชื่อมต่อหลุด seine เชื่อมต่อใหม่เอง |
| `pool-login-rejected` | พูลปฏิเสธการเข้าสู่ระบบ บรรทัด `AUTH` ในบันทึกบอกสาเหตุ |

การขุดเดี่ยวกับโหนดของคุณเพิ่มสถานะอย่าง `daemon-syncing`, `stale-tip` (มีบล็อกใหม่ กำลังขอเทมเพลตใหม่) และ `solved` ขณะ seine รอบางสิ่ง Current ลดเป็นศูนย์เพื่อไม่แสดงอัตราที่ไม่ได้กำลังผลิต

## Submitted, Rejected และ Accepted หมายถึงอะไร?

ส่วน `MINING` นับแชร์ของเซสชันนี้:

- **Submitted:** แชร์ที่ seine ส่งให้พูลแล้ว
- **Rejected:** แชร์ที่พูลไม่รับ ในโหมดขุดเดี่ยวบรรทัดนี้ชื่อ `Stale` และนับคำตอบที่ถึงโหนดหลังเชนเดินต่อไปแล้ว
- **Accepted:** แชร์ที่พูลบันทึกให้คุณ

bntpool.com ปรับความยากแชร์ของแต่ละการเชื่อมต่อให้ได้ประมาณ 10 แชร์ทุกห้านาที แชร์ทุกประมาณ 30 วินาทีจึงเป็นเรื่องปกติไม่ว่าแฮชเรตเท่าไร ภาพที่ส่ง 5 แชร์และรับครบ 5 หลังสิบนาทีเป็นการเริ่มที่ปกติดี ยอดจ่ายขึ้นกับแชร์ที่ได้รับการยอมรับ และ Rejected เป็นศูนย์หมายถึงทุกแชร์ที่ส่งถูกนับให้

## อุปกรณ์ การตั้งค่า และยอดคงเหลือในพูล

`DEVICES` แสดงแต่ละ backend ขุดพร้อมแฮชเรตปัจจุบันและเฉลี่ย `cpu#1` สำหรับ CPU แล้วตามด้วย `nvidia#1`, `nvidia#2` เป็นต้นสำหรับ GPU ของ NVIDIA แต่ละตัว GPU ที่ยังเริ่มทำงานแสดงความคืบหน้าแทน ตั้งแต่ `starting CUDA runtime` ถึง `preparing NVIDIA backend` การเปิดครั้งแรกคอมไพล์และปรับจูนเคอร์เนล GPU จึงนานกว่าครั้งถัดไป

`CONFIG` แสดงการตั้งค่าของการรันนี้:

- **Endpoint** คือที่อยู่พูล (ค่าเริ่มต้น `stratum+tcp://bntpool.com:3333`) หรือที่อยู่ API ของโหนดในโหมดขุดเดี่ยว ถัดไปคือชื่อที่ริกนี้ใช้เข้าสู่พูล
- **Threads** คือจำนวนเธรดขุด CPU ตามด้วยคำใบ้ `[+] [-]` สำหรับปุ่มควบคุม
- **Backends** อธิบายแต่ละ backend โดย `cpu#1 (14 lanes, ~28.0 GiB RAM)` หมายถึง 14 เธรด แต่ละเธรดมีบล็อกหน่วยความจำ 2 GiB ดังนั้น 14 × 2 GiB = 28 GiB

ตั้งชื่อริกให้จำง่ายบนพูลโดยส่งตอนเริ่ม:

```sh
./seine --pool-worker rig-01
```

`POOL BALANCE` อ่านยอดคงเหลือจาก bntpool.com ทุกไม่กี่วินาที `Pending` คือยอดที่ได้แต่ยังไม่จ่าย `Paid` คือยอดที่พูลส่งไปยังที่อยู่แล้ว และ `Miner` ทางขวาคือที่อยู่ที่ย่อเหลือหกตัวแรกและหกตัวท้าย bntpool.com จ่ายเมื่อยอดคงเหลือถึง 0.1 BNT ในโหมดขุดเดี่ยวส่วนนี้เปลี่ยนเป็น `WALLET` พร้อมยอด `Pending` และ `Unlocked` ของกระเป๋าเงินในโหนด

## อ่านบันทึกการทำงาน

`LOG` เก็บ 200 รายการล่าสุด โดยใหม่สุดอยู่ล่าง แต่ละรายการมีป้ายระดับ แท็ก และเวลาที่ผ่านไป ป้ายได้แก่ `INFO`, `OK` (ทำสำเร็จ), `WARN`, `ERR` และ `**` สำหรับบล็อกที่แก้ได้ แท็กที่พบบ่อยที่สุดบนพูลคือ:

- `AUTH`: การเข้าสู่พูล เช่น `login accepted (protocol v2, required=submit_claimed_hash)`
- `JOB`: งานใหม่จากพูลพร้อมความสูงและความยาก
- `SHARE`: `submitted (backend=cpu#1)` แล้วตามด้วย `accepted (backend=cpu#1)`
- `VARDIFF`: พูลเปลี่ยนความยากแชร์ของคุณ
- `MINER`: การตัดสินใจปรับจูนอัตโนมัติ

## การปรับจูนอัตโนมัติแสดงอย่างไรขณะ seine ทำงาน?

seine เริ่มขุดทันทีและปรับจูนบนงานขุดจริง คุณดูได้ในบันทึก บรรทัด `MINER` แรกเป็น `cpu-autotune | starting with N threads` ตามด้วย `initial estimate` บนเครื่องใหม่ หรือ `cached starting point` เมื่อ seine รู้จักเครื่องแล้ว

จากนั้นเปรียบเทียบค่าตามลำดับ คือจำนวนเธรดปัจจุบัน ค่าทดลอง แล้วจำนวนปัจจุบันอีกครั้ง แต่ละหน้าต่างใช้เวลาอย่างน้อย 30 วินาทีและเก็บอย่างน้อย 20 แฮช คุณจะเห็นบรรทัดอย่าง `measuring useful mining work` และ `checking baseline again` และจำนวน Threads ใน `CONFIG` เปลี่ยนตาม เมื่อได้ข้อสรุป บันทึกระบุ `done` พร้อมจำนวนเธรดที่เก็บไว้

เคอร์เนล CPU ถูกเปรียบเทียบแบบเดียวกัน เช่น `comparing avx2 and avx512 while mining` และ seine เปลี่ยนต่อเมื่อสองการเปรียบเทียบยืนยันว่าเร็วขึ้น: `confirmed faster ... path in two comparisons` ค่าที่เลือกถูกแคช การเริ่มครั้งต่อไปจึงต่อจากผลครั้งนี้ การปรับจูนไม่เชื่อมต่อพูลใหม่หรือเริ่ม GPU ใหม่ [คู่มือปรับจูนอัตโนมัติ](https://github.com/zpalmtree/seine/blob/master/docs/guides/autotuning.md) มีรายละเอียด และ[บทความอธิบาย Argon2id](/th/blog/argon2id-proof-of-work-explained/) อธิบายว่าเหตุใดแบนด์วิดท์หน่วยความจำจึงกำหนดจำนวนเธรดที่ดีที่สุด

## เปลี่ยนเธรดจากแดชบอร์ดได้หรือไม่?

<Answer>
ได้ กด + (หรือ = ไม่ต้องกด Shift) เพื่อเพิ่มหนึ่งเธรดต่อ backend CPU และ - เพื่อลดหนึ่งเธรด seine เริ่ม backend ขุดใหม่ด้วยจำนวนใหม่ โดยเก็บสถิติเซสชัน เวลาทำงาน และแฮชเรตเฉลี่ยไว้ กด q หรือ Ctrl+C เพื่อออก การเปลี่ยนเองปิดการปรับจูนเธรดอัตโนมัติสำหรับการรันนั้น
</Answer>

ระหว่างปรับใช้ `CONFIG` แสดง `Restarting: 14 -> 15 threads...` และไม่รับการกดเพิ่มจนเสร็จ การเพิ่มหยุดที่เพดาน CPU และ RAM อัตโนมัติ และจำนวนที่คุณเลือกไม่ถูกบันทึกเป็นค่าเริ่มต้นใหม่ หากต้องการกำหนดคงที่ตั้งแต่เริ่ม ใช้ `--threads`

## เทอร์มินัลเล็กและผลลัพธ์ข้อความธรรมดา

ในเทอร์มินัลแคบกว่า 80 คอลัมน์ ส่วนสถิติทั้งสามเรียงแนวตั้ง ในหน้าต่างเตี้ย seine เปลี่ยนเป็นมุมมองกะทัดรัดที่ยังแสดง Threads, State, Current, Average, จำนวนแชร์ และ Height เหนือบันทึก ค่าเริ่มต้น `--ui auto` แสดงแดชบอร์ดเฉพาะในเทอร์มินัลแบบโต้ตอบ ส่วน `--ui plain` ให้บันทึกข้อความธรรมดาที่เลื่อนสำหรับเซิร์ฟเวอร์ ไฟล์บันทึก และตัวจัดการโปรเซส
