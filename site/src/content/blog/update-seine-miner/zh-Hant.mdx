更新 seine，同時保留已經正常運作的礦池連線和啟動設定。本指南以公開版本 v0.2.36 為依據，說明準備、檔案替換與驗證。首次安裝請參閱 [Windows](/zh-hant/blog/mine-blocknet-on-windows/)、[Linux](/zh-hant/blog/mine-blocknet-on-linux/) 或 [Mac](/zh-hant/blog/mine-blocknet-on-mac/) 指南。

## 如何更新 seine？

<Answer>
下載並驗證適合系統的官方壓縮檔，停止挖礦程式，保留資料目錄，再替換應用程式檔案。使用相同的工作目錄和參數重新啟動。更新另一台機器前，確認版本、收款地址、礦池連線和已接受的份額。
</Answer>

## 如何檢查目前版本？

對實際使用的執行檔執行版本命令。另一個資料夾中的舊副本可能與捷徑或服務啟動的版本不同。一起記錄程式路徑、工作目錄和參數，方便重複操作。在 Windows 中，於目前的挖礦程式目錄開啟 PowerShell：

```powershell
.\seine.exe --version
```

在 Linux 或 macOS 中，於該目錄開啟終端機：

```sh
./seine --version
```

將結果與[官方發行版本](https://github.com/zpalmtree/seine/releases)比較。seine 在啟動時及每隔 12 小時檢查更新，並在儀表板和日誌通知。提示提供下載連結，安裝時機由你選擇。閱讀涉及平台、執行階段程式庫和啟動選項的發行說明。

## 應保留哪些設定？

seine 預設讀取 `./seine-data/seine.config.json`。`./` 表示目前工作目錄，因此移動程式並從其他資料夾執行，可能改變設定查找位置。若使用 `--data-dir`，繼續指向同一目錄。絕對路徑能在捷徑、指令稿或服務管理員指定工作目錄時明確指出資料位置。

設定儲存挖礦模式、收款地址、礦池 URL 和機器名稱等連線資訊。保留整個資料目錄，包括調校檔案。同時儲存啟動命令、指令稿或服務定義：`--backend`、`--threads` 等選項獨立於已儲存的連線欄位。兩者都保留，才能在重新啟動後維持預期設定。

## 下載並驗證新檔案

透過[下載頁面](/zh-hant/#download)或官方發行頁選擇對應系統和 CPU 架構的壓縮檔，同時下載同一版本單獨提供的 `SHA256SUMS.txt`。比對校驗碼後，再解壓縮到獨立資料夾。[下載驗證指南](/zh-hant/blog/antivirus-flags-crypto-miner/)介紹 Windows 操作和下載警告處理。

將壓縮檔中的檔案保持在一起。Windows 套件在 `seine.exe` 旁附帶 NVIDIA 執行階段程式庫，只複製程式可能造成版本混用。[NVIDIA 指南](/zh-hant/blog/mine-blocknet-nvidia-gpu/)說明執行環境。[v0.2.36 設定參考](https://github.com/zpalmtree/seine/blob/v0.2.36/docs/guides/configuration.md)記錄本文使用的設定儲存和啟動行為。

## 停止、備份並替換

在互動介面用 `q` 或 `Ctrl+C` 結束，等待程序停止。對於服務，使用服務管理員停止，並在替換前考量自動重新啟動策略。程式停止後，在本機備份應用程式資料夾和資料目錄。備份與新解壓縮內容分開，方便辨認兩個版本。

將新應用程式檔案放入安裝位置，並保留原始資料目錄。若按版本使用不同資料夾，更新捷徑或服務中的程式路徑，同時明確保留工作目錄和資料路徑。以原有選項啟動一個執行個體。多台機器更新時，先完成一台的全部檢查。

## 如何確認更新成功？

再次查詢已安裝程式的版本，與下載的發行版本比較。啟動後核對收款地址、礦池、機器名稱，以及預期的 CPU 或 GPU 後端。相容的調校記錄可重新使用；評估算力前，等待啟動調校結束。[儀表板指南](/zh-hant/blog/seine-dashboard-explained/)解釋相關面板。

確認出現已接受的份額，再用相同地址查看 [My Stats](https://bntpool.com/stats)。礦池估算需要份額和時間來穩定，剛啟動時的算力差異本身不足以判斷更新問題。新程序也會開啟新的本機工作階段。比較短期計數前，先比較地址、機器和份額活動。

## 如果再次出現初始設定提示怎麼辦？

先檢查工作目錄和 `--data-dir`。新解壓縮目錄的預設相對路徑上往往沒有舊設定。停止該執行個體並指向原始資料目錄。若錯誤指出某個設定檔，保留檔案及確切訊息供排查。公開截圖或報告不要包含錢包助記詞、私鑰或控制 API 權杖。

啟動失敗時，記錄版本、作業系統、程式路徑和確切錯誤，再查閱相應平台指南。備份將舊應用程式及設定保存在一起。還原舊版本前，檢查新發行說明中的相容性要求。使用已知設定恢復後，再驗證份額；僅替換挖礦程式不需要重新建立錢包。
