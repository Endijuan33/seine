更新 seine，同时保留已经正常工作的矿池连接和启动设置。本指南以公开版本 v0.2.36 为依据，说明准备、文件替换与验证。首次安装请参阅 [Windows](/zh-hans/blog/mine-blocknet-on-windows/)、[Linux](/zh-hans/blog/mine-blocknet-on-linux/) 或 [Mac](/zh-hans/blog/mine-blocknet-on-mac/) 指南。

## 如何更新 seine？

<Answer>
下载并核验适合系统的官方压缩包，停止矿工程序，保留数据目录，再替换应用文件。使用相同的工作目录和参数重新启动。更新另一台机器前，确认版本、收款地址、矿池连接和已接受的份额。
</Answer>

## 如何检查当前版本？

对实际使用的可执行文件运行版本命令。另一个文件夹中的旧副本可能与快捷方式或服务启动的版本不同。一起记录程序路径、工作目录和参数，便于重复操作。在 Windows 中，于当前矿工目录打开 PowerShell：

```powershell
.\seine.exe --version
```

在 Linux 或 macOS 中，于该目录打开终端：

```sh
./seine --version
```

将结果与[官方发布版本](https://github.com/zpalmtree/seine/releases)比较。seine 在启动时及每隔 12 小时检查更新，并在仪表盘和日志中通知。提示提供下载链接，安装时机由你选择。阅读涉及平台、运行库和启动选项的发布说明。

## 应保留哪些设置？

seine 默认读取 `./seine-data/seine.config.json`。`./` 表示当前工作目录，因此移动程序并从其他文件夹运行，可能改变配置查找位置。若使用 `--data-dir`，继续指向同一目录。绝对路径能在快捷方式、脚本或服务管理器指定工作目录时明确数据位置。

配置保存挖矿模式、收款地址、矿池 URL 和机器名称等连接信息。保留整个数据目录，包括调优文件。同时保存启动命令、脚本或服务定义：`--backend`、`--threads` 等选项独立于已保存的连接字段。两者都保留，才能在重启后维持预期设置。

## 下载并核验新文件

通过[下载页面](/zh-hans/#download)或官方发布页选择对应系统和 CPU 架构的压缩包，同时下载同一版本单独提供的 `SHA256SUMS.txt`。比对校验和后，再解压到单独的文件夹。[下载核验指南](/zh-hans/blog/antivirus-flags-crypto-miner/)介绍 Windows 操作和下载警告处理。

将压缩包中的文件保持在一起。Windows 包在 `seine.exe` 旁附带 NVIDIA 运行库，只复制程序可能造成版本混用。[NVIDIA 指南](/zh-hans/blog/mine-blocknet-nvidia-gpu/)说明运行环境。[v0.2.36 配置参考](https://github.com/zpalmtree/seine/blob/v0.2.36/docs/guides/configuration.md)记录了本文使用的设置保存和启动行为。

## 停止、备份并替换

在交互界面用 `q` 或 `Ctrl+C` 退出，等待进程结束。对于服务，使用服务管理器停止，并在替换前考虑自动重启策略。程序停止后，在本地备份应用文件夹和数据目录。备份与新解压内容分开，便于辨认两个版本。

将新应用文件放入安装位置，并保留原始数据目录。若按版本使用不同文件夹，更新快捷方式或服务中的程序路径，同时明确保留工作目录和数据路径。以原有选项启动一个实例。多台机器更新时，先完成一台的全部检查。

## 如何确认更新成功？

再次查询已安装程序的版本，与下载的发布版本比较。启动后核对收款地址、矿池、机器名称，以及预期的 CPU 或 GPU 后端。兼容的调优记录可重新使用；评估算力前，等待启动调优结束。[仪表盘指南](/zh-hans/blog/seine-dashboard-explained/)解释相关面板。

确认出现已接受的份额，再用相同地址查看 [My Stats](https://bntpool.com/stats)。矿池估算需要份额和时间来稳定，刚启动时的算力差异本身不足以判断更新问题。新进程也会开启新本地会话。比较短期计数前，先比较地址、机器和份额活动。

## 如果再次出现初始设置提示怎么办？

先检查工作目录和 `--data-dir`。新解压目录的默认相对路径上往往没有旧配置。停止该实例并指向原始数据目录。若错误点名某个配置文件，保留文件及准确报错供排查。公开截图或报告中不要包含钱包助记词、私钥或控制 API 令牌。

启动失败时，记录版本、操作系统、程序路径和准确错误，再查阅相应平台指南。备份将旧应用及其设置保存在一起。恢复旧版本前，检查新发布说明中的兼容性要求。使用已知配置恢复后，再验证份额；仅替换矿工程序不需要重新创建钱包。
