Запустіть власний вузол Blocknet і перевірте його підключення та слідування ланцюгу. Посібник використовує офіційний клієнт командного рядка для core основної мережі й перевірки пірів, синхронізації та оновлень. Команди перевірено з клієнтом v1.2.0 26 жовтня 2026 року. Тримайте поруч [офіційний довідник](https://github.com/blocknetprivacy/blocknet/blob/948af4de8b7a3e3cddc86a329c7d2d003cb3fd6b/docs/reference-blocknet.md) установленої версії.

## Що потрібно для запуску вузла Blocknet?

<Answer>
Використайте офіційний клієнт для своєї ОС, комп’ютер із місцем для ланцюга та інтернет. Клієнт установлює й керує фоновим core. Після запуску перевірте піри та прогрес. Створення гаманця й майнінг — окремі завдання, які можна додати після налагодження вузла.
</Answer>

## Оберіть офіційний клієнт і мережу

Завантажте архів для системи й процесора з [офіційних випусків](https://github.com/blocknetprivacy/blocknet/releases/latest). Розпакуйте та відкрийте термінал із доступом до виконуваного файла. Приклади використовують `blocknet`, у Windows — `blocknet.exe`. Якщо файла немає в шляху пошуку команд, задайте справжній шлях, наприклад `./blocknet` у Linux або macOS.

Mainnet — звичайна мережа Blocknet. Testnet — окреме середовище з власними даними й конфігурацією. Запишіть обрану мережу, щоб не порівнювати висоту testnet з оглядачем mainnet. Тут ідеться про вузол; [посібник гаманця](/uk/blog/blocknet-wallet-for-mining/) охоплює створення, відновлення й адресу отримання.

## Установіть і запустіть фоновий core

Для першого налаштування запустіть майстер в інтерактивному терміналі:

```sh
blocknet setup
```

Читайте кожне запитання. Перевірений майстер зберігає конфігурацію, планує автооновлення, пропонує завантажити core за потреби та запустити його. Він також надає налаштування мережі й локального API. Збережіть локальну прив’язку для керування з цього комп’ютера.

Задокументований ручний шлях:

```sh
blocknet install latest
blocknet start mainnet
```

`latest` обирає стабільний core. Mainnet має бути ввімкнена в конфігурації. Клієнт запускає core у фоні й чекає API. Дайте старту завершитися: відкриття бази та повне наздоганяння ланцюга — різні етапи.

## Як перевірити піри й перебіг синхронізації?

Підключіться до активного core mainnet:

```sh
blocknet attach mainnet
```

В інтерактивному рядку вводьте окремо:

```text
status
peers
```

[Довідник оболонки](https://github.com/blocknetprivacy/blocknet/blob/948af4de8b7a3e3cddc86a329c7d2d003cb3fd6b/docs/reference-core.md) описує поля. Запишіть висоту, хеш останнього блока, кількість пірів і стан синхронізації. Список пірів допомагає підтвердити мережеві з’єднання.

Спостерігайте висоту з часом і порівняйте зі свіжим орієнтиром mainnet, як-от [офіційним оглядачем](https://explorer.blocknetcrypto.com/). Між блоками висота може стояти; спостереження можуть належати різним моментам. Оцінюйте поля разом замість одного числа. Поки вузол наздоганяє мережу, тримайте зв’язок і сховище доступними.

## Відрізняйте синхронізацію ланцюга від сканування гаманця

Синхронізація слідує блокам мережі. Сканування шукає в історії виходи завантаженого гаманця. Відновлений гаманець може сканувати й після того, як вузол наздогнав мережу. Його відомості в оболонці тому окремі від висоти вузла. Для конкретної майнінгової виплати використайте [посібник отримання](https://bntpool.com/blog/uk/pool-payout-missing-from-wallet/).

Поточний клієнт підтримує checkpoints для швидшої початкової синхронізації. [Посібник checkpoints](https://bntpool.com/blog/uk/blocknet-checkpoints-fast-sync/) пояснює джерело та обсяг перевірки; швидкі способи не однакові. Не видаляйте базу ланцюга як звичайну реакцію на нерухомий індикатор. Спочатку відрізніть завантаження, перевірку й сканування за станом і журналами.

## Де шукати, якщо запуск потребує уваги?

Поза attach стежте за журналом керованого core:

```sh
blocknet logs mainnet
```

Читайте останні повідомлення запуску й з’єднання. Ctrl-C завершує перегляд. Для конфігурації, шляхів, версій і зв’язку:

```sh
blocknet doctor
```

Задокументований doctor повідомляє результати без зміни налаштування. Збережіть точний текст перед вибором виправлення.

Перевірте потрібні core і мережу, установлений вибраний файл та адресу локального API. Зверніться до [офіційної діагностики](https://github.com/blocknetprivacy/blocknet/blob/948af4de8b7a3e3cddc86a329c7d2d003cb3fd6b/docs/troubleshooting.md) щодо повідомленого стану. Не розкривайте облікові дані API та матеріали гаманця в діагностиці. Версія, ОС і відповідна помилка зазвичай корисніші за весь каталог конфігурації.

## Зрозумійте оновлення й навмисну зупинку

У перевіреному клієнті планувальник та окремі керувальні команди шукають оновлення. Зовнішня `blocknet status` може запускати перевірку; вона відрізняється від `status` усередині attach. Оновлення можуть перезапускати core, що слідують `latest`; закріплені версії не змінюються. Для залежних служб прочитайте [довідник оновлень](https://github.com/blocknetprivacy/blocknet/blob/948af4de8b7a3e3cddc86a329c7d2d003cb3fd6b/docs/reference-upgrade.md).

Плануйте обслуговування з урахуванням користувачів API. Вийдіть з attach через `quit`; core працює далі. Для навмисної зупинки цього core mainnet виконайте `blocknet stop mainnet` у системному терміналі. Після оновлення чи перезапуску перевірте активну версію, зв’язок і прогрес. Резервну копію гаманця зберігайте окремо від файлів core.

## Використовуйте вузол за призначенням

Підключений вузол обслуговує гаманець і локальні запити без майнінгу. Для bntpool.com скористайтеся [посібником пулу](https://bntpool.com/blog/uk/mine-blocknet-on-bntpool/) та звичайним з’єднанням seine. Власний вузол — окремий вибір. Для прямого майнінгу прочитайте інструкції режиму daemon і перевірте API перед підключенням.

Ведіть короткий запис: мережа, версії клієнта/core, розташування даних, політика оновлень і перевірки прогресу. Це допоможе й для [Faraday](/uk/blog/blocknet-faraday-upgrade/), чиї майбутні вказівки активації мають походити з офіційного випуску. Після запланованої зміни знову перевірте стан, щоб описувати активний вузол, а не лише завантажену програму.
