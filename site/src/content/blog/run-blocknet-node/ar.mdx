شغّل عقدة Blocknet الخاصة بك وتعلم التأكد من اتصالها ومتابعتها للسلسلة. يستخدم الدليل العميل الرسمي لسطر الأوامر لإدارة core على mainnet وفحص الأقران والمزامنة والتحديثات. فُحصت الأوامر مع العميل v1.2.0 في 26 أكتوبر 2026. احتفظ بـ[مرجع الأوامر الرسمي](https://github.com/blocknetprivacy/blocknet/blob/948af4de8b7a3e3cddc86a329c7d2d003cb3fd6b/docs/reference-blocknet.md) للإصدار الذي تثبّته.

## ماذا تحتاج لتشغيل عقدة Blocknet؟

<Answer>
استخدم العميل الرسمي لنظامك وحاسوبًا بمساحة لبيانات السلسلة واتصال إنترنت. يثبّت العميل core ويديره في الخلفية. بعد التشغيل افحص الأقران والتقدم. إنشاء المحفظة والتعدين مهمتان منفصلتان يمكنك إضافتهما بعد عمل العقدة.
</Answer>

## اختر العميل الرسمي والشبكة

نزّل الأرشيف المناسب لنظامك ومعالجك من [الإصدارات الرسمية](https://github.com/blocknetprivacy/blocknet/releases/latest). فكّه وافتح طرفية يتاح فيها الملف التنفيذي. تستخدم الأمثلة `blocknet`؛ وعلى Windows استخدم `blocknet.exe`. إن لم يكن في مسار البحث عن الأوامر، استخدم مساره الفعلي، مثل `./blocknet` على Linux أو macOS.

استخدم mainnet لشبكة Blocknet المعتادة. Testnet بيئة منفصلة ببيانات وإعدادات خاصة. دوّن الشبكة كي لا تقارن ارتفاع testnet بمستكشف mainnet. يركز هذا الدليل على إدارة العقدة؛ ويغطي [دليل المحفظة](/ar/blog/blocknet-wallet-for-mining/) الإنشاء والاستعادة واختيار عنوان الاستلام.

## ثبّت core وشغّله في الخلفية

للإعداد الأول، شغّل المعالج في طرفية تفاعلية:

```sh
blocknet setup
```

اقرأ كل سؤال. يحفظ المعالج المفحوص الإعدادات ويجدول التحديثات التلقائية ويعرض تنزيل core عند الحاجة وبدءه. ويتيح أيضًا إعدادات الشبكة وAPI المحلية. احتفظ بالربط المحلي لعقدة تديرها على هذا الحاسوب.

مسار التثبيت اليدوي الموثق هو:

```sh
blocknet install latest
blocknet start mainnet
```

يختار `latest` إصدار core المستقر. يجب تفعيل mainnet في الإعدادات. يشغّل العميل core في الخلفية وينتظر API الخاصة به. دع البدء يكتمل؛ فبدء قاعدة البيانات واللحاق الكامل بالسلسلة مرحلتان مختلفتان.

## كيف تفحص الأقران وتقدم المزامنة؟

اتصل بعملية core العاملة على mainnet:

```sh
blocknet attach mainnet
```

أدخل هذين الأمرين منفصلين في الواجهة التفاعلية:

```text
status
peers
```

يشرح [مرجع الواجهة](https://github.com/blocknetprivacy/blocknet/blob/948af4de8b7a3e3cddc86a329c7d2d003cb3fd6b/docs/reference-core.md) الحقول. سجّل الارتفاع وتجزئة آخر كتلة وعدد الأقران وحالة المزامنة. تساعد قائمة الأقران على تأكيد اتصالات الشبكة.

راقب الارتفاع بمرور الوقت وقارنه بمرجع mainnet حديث مثل [المستكشف الرسمي](https://explorer.blocknetcrypto.com/). قد يتوقف الارتفاع بين الكتل، وقد تُؤخذ الملاحظات في أوقات مختلفة. اقرأ الحقول معًا بدل إعلان النجاح من رقم واحد. أثناء اللحاق بالسلسلة أبقِ الاتصال والتخزين متاحين.

## افصل مزامنة السلسلة عن مسح المحفظة

تتابع مزامنة السلسلة كتل الشبكة. ويبحث مسح المحفظة في التاريخ عن مخرجات تخص المحفظة المحمّلة. قد تستمر محفظة مستعادة في المسح بعد لحاق العقدة. معلومات المحفظة في الواجهة إذن ملاحظة منفصلة عن ارتفاع العقدة. لتتبع دفعة تعدين معينة، استخدم [دليل وصول الدفعات](https://bntpool.com/blog/ar/pool-payout-missing-from-wallet/).

يدعم العميل الحالي checkpoints لتسريع المزامنة الأولى. اتبع [دليل checkpoints](https://bntpool.com/blog/ar/blocknet-checkpoints-fast-sync/) لمعرفة المصدر ونطاق التحقق؛ ليست جميع طرق المزامنة السريعة متطابقة. لا تحذف قاعدة السلسلة روتينيًا بسبب هدوء مؤشر التقدم. ميّز أولًا بين التنزيل والتحقق والمسح عبر الحالة والسجلات.

## أين تبحث إذا احتاج البدء إلى متابعة؟

خارج attach، تابع سجل core المُدار:

```sh
blocknet logs mainnet
```

اقرأ رسائل البدء والاتصال الأخيرة. يوقف Ctrl-C متابعة السجل. لفحص الإعدادات والمسارات والإصدارات والاتصال:

```sh
blocknet doctor
```

يعرض أمر doctor الموثق النتائج دون تغيير الإعداد. احفظ الرسالة الدقيقة قبل اختيار إصلاح.

تحقق من core والشبكة المتوقعين وتثبيت الملف المختار وتطابق عنوان API المحلية. راجع [استكشاف الأخطاء الرسمي](https://github.com/blocknetprivacy/blocknet/blob/948af4de8b7a3e3cddc86a329c7d2d003cb3fd6b/docs/troubleshooting.md) للحالة المذكورة. أبقِ بيانات اعتماد API ومواد المحفظة خاصة عند مشاركة التشخيص. الإصدار والنظام والخطأ المعني عادة أنفع من مجلد الإعدادات بأكمله.

## افهم التحديثات والإيقاف المقصود

في العميل المفحوص، يفحص المجدول وبعض أوامر الإدارة التحديثات. يمكن للأمر الخارجي `blocknet status` بدء فحص؛ وهو مختلف عن `status` داخل attach. قد تعيد التحديثات تشغيل عمليات core التي تتبع `latest`، وتترك الإصدارات المثبتة على نسخة محددة. اقرأ [مرجع التحديث](https://github.com/blocknetprivacy/blocknet/blob/948af4de8b7a3e3cddc86a329c7d2d003cb3fd6b/docs/reference-upgrade.md) عند وجود خدمات تعتمد على العقدة.

خطط للصيانة بحسب ما يستخدم API العقدة. أدخل `quit` لمغادرة attach؛ يستمر core بالعمل. لإيقاف core mainnet هذا عمدًا، نفّذ `blocknet stop mainnet` من طرفية النظام. بعد تحديث أو إعادة تشغيل، تحقق من الإصدار العامل والاتصال والتقدم. احتفظ بنسخة المحفظة الاحتياطية مستقلة عن ملفات core.

## استخدم العقدة للمهمة المقصودة

يمكن للعقدة المتصلة دعم المحفظة واستعلامات السلسلة محليًا دون تفعيل التعدين. للتعدين في bntpool.com اتبع [دليل المجمع](https://bntpool.com/blog/ar/mine-blocknet-on-bntpool/) واتصال seine المعتاد. تشغيل عقدة خاصة خيار منفصل. للتعدين المباشر، اقرأ تعليمات وضع daemon وتحقق من إعداد API قبل الاتصال.

احتفظ بسجل مختصر: الشبكة وإصدارات العميل وcore ومكان البيانات وسياسة التحديث وفحوص التقدم السليم. يفيد ذلك أيضًا للتحضير لـ[Faraday](/ar/blog/blocknet-faraday-upgrade/)، التي يجب أخذ تعليمات تفعيلها المستقبلية من الإصدار الرسمي. افحص الحالة بعد تغيير مخطط كي يصف السجل العقدة العاملة، لا البرنامج المنزّل فقط.
