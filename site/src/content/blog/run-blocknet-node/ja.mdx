自分のBlocknetノードを動かし、接続してチェーンを追っているか確認しましょう。本ガイドは公式コマンドラインクライアントでmainnetのcoreを管理し、ピア、同期、更新を調べます。コマンドは2026年10月26日にクライアントv1.2.0で確認しました。導入する版の[公式コマンド一覧](https://github.com/blocknetprivacy/blocknet/blob/948af4de8b7a3e3cddc86a329c7d2d003cb3fd6b/docs/reference-blocknet.md)を手元に置いてください。

## Blocknetノードに必要なものは？

<Answer>
OSに対応する公式Blocknetクライアント、チェーンデータを保存する空き容量のあるPC、インターネット接続を用意します。クライアントがバックグラウンドのcoreを導入・管理します。起動したらピアとチェーン進捗を確認してください。ウォレット作成と採掘は別の作業で、ノード稼働後に追加できます。
</Answer>

## 公式クライアントとネットワークを選ぶ

[公式クライアントのリリース](https://github.com/blocknetprivacy/blocknet/releases/latest)からOSとプロセッサに合うアーカイブを取得します。展開し、実行ファイルを使える場所で端末を開いてください。以下では実行名 `blocknet` を使い、Windowsでは `blocknet.exe` を使います。コマンド検索パスにない場合は、LinuxやmacOSの `./blocknet` のように実際のファイルパスで起動します。

通常のBlocknetネットワークにはmainnetを使います。testnetは設定とデータが別の環境です。選択ネットワークを記録し、testnetの高さをmainnetのエクスプローラーと比較しないようにします。本ガイドはノード管理が対象です。ウォレット作成、復元、受取アドレス選択は[ウォレットガイド](/ja/blog/blocknet-wallet-for-mining/)を参照してください。

## バックグラウンドのcoreを導入・起動する

初回設定では対話型端末でウィザードを実行します。

```sh
blocknet setup
```

各質問を読んでください。確認したウィザードは設定を保存し、自動更新をスケジュールし、必要に応じてcoreのダウンロードと起動を提案します。ネットワークとローカルAPIの設定もあります。このPCで管理するノードはローカルのバインドを維持してください。

文書化された手動導入手順です。

```sh
blocknet install latest
blocknet start mainnet
```

`latest` は安定版coreを選びます。mainnet起動には設定で有効化されている必要があります。クライアントはcoreをバックグラウンドで実行し、APIを待ちます。起動作業が完了するのを待ってください。データベース初期起動とチェーンへの完全な追いつきは別の段階です。

## ピアと同期進捗をどう確認する？

稼働中のmainnet coreに接続します。

```sh
blocknet attach mainnet
```

対話プロンプトで次の確認コマンドを1つずつ入力します。

```text
status
peers
```

[シェルのリファレンス](https://github.com/blocknetprivacy/blocknet/blob/948af4de8b7a3e3cddc86a329c7d2d003cb3fd6b/docs/reference-core.md)に各項目の説明があります。高さ、最良ブロックのハッシュ、ピア数、同期状態を記録してください。ピア一覧はノードのネットワーク接続確認に役立ちます。

時間を置いて高さを観察し、[公式エクスプローラー](https://explorer.blocknetcrypto.com/)などmainnetの新しい参照値と比較します。ブロック間では高さが止まることがあり、観測時刻も異なり得ます。1つの数字で成功とせず、項目を合わせて判断してください。追いつき中ならネットワーク接続とストレージを利用可能な状態に保ちます。

## チェーン同期とウォレットスキャンを分ける

チェーン同期はネットワークのブロックを追います。ウォレットスキャンは、その履歴から読み込んだウォレットの出力を探します。ノードが追いついても復元ウォレットはスキャン中かもしれません。そのためシェルのウォレット情報が利用できる場合、それはノード高とは別の観測です。特定の採掘支払いを追うときは[ウォレット入金ガイド](https://bntpool.com/blog/ja/pool-payout-missing-from-wallet/)を使ってください。

現在のクライアントは初期同期を速めるチェックポイントもサポートします。すべての高速同期方式を同じとせず、[チェックポイントガイド](https://bntpool.com/blog/ja/blocknet-checkpoints-fast-sync/)で出所と検証範囲を確認してください。進捗表示が静かだからと通常の対処でチェーンDBを削除しないでください。先に状態とログでダウンロード、検証処理、ウォレットスキャンを区別します。

## 起動に問題があるときはどこを見る？

attachシェルの外で、管理対象coreのログを追います。

```sh
blocknet logs mainnet
```

最新の起動・接続メッセージを読んでください。ログ追跡を止めるにはCtrl-Cを押します。設定、パス、導入済み版、接続の確認には次を使います。

```sh
blocknet doctor
```

文書化されたdoctorコマンドは設定を変更せず所見を報告します。対処を選ぶ前に正確なメッセージを保存してください。

想定するcoreとネットワークが設定され、選択したバイナリが導入され、ローカルAPIアドレスが一致するか確認します。報告された状態は[公式トラブル対処ガイド](https://github.com/blocknetprivacy/blocknet/blob/948af4de8b7a3e3cddc86a329c7d2d003cb3fd6b/docs/troubleshooting.md)を参照してください。診断を共有する際はAPI認証情報とウォレット情報を非公開に保ちます。設定ディレクトリ全体より、版、OS、該当エラーが通常はよい出発点です。

## 更新と意図した停止を理解する

確認したクライアントは、スケジューラーと一部のライフサイクルコマンドで自動更新を確認します。外側の `blocknet status` は更新確認を起こすことがあり、attach内の `status` とは異なります。更新があると `latest` を追う管理対象coreを再起動する場合があり、固定版はそのままです。依存サービスがあるノードで使う前に[更新リファレンス](https://github.com/blocknetprivacy/blocknet/blob/948af4de8b7a3e3cddc86a329c7d2d003cb3fd6b/docs/reference-upgrade.md)を読んでください。

ノードAPIを使うものに合わせて保守を計画します。attachを抜けるには `quit` と入力し、coreは動き続けます。管理対象mainnet coreを意図して止めるには、OS端末から `blocknet stop mainnet` を実行します。予定した更新や再起動後は稼働版、接続、チェーン進捗を確認してください。ウォレットバックアップは導入済みcoreバイナリとは独立して保管します。

## 目的の作業にノードを使う

接続済みノードは採掘を有効にせずウォレットとローカルのチェーン照会に使えます。bntpool.comで採掘するなら[プール設定ガイド](https://bntpool.com/blog/ja/mine-blocknet-on-bntpool/)に従い、seineの通常のプール接続を使ってください。自前ノードの運用は別の選択です。直接採掘ではマイナーのデーモンモード手順を読み、接続前にAPI設定を確認します。

ネットワーク、クライアントとcoreの版、データ位置、更新方針、正常進捗を示した確認結果を短く記録します。[Faraday](/ja/blog/blocknet-faraday-upgrade/)への準備にも役立ちますが、将来の有効化手順は公式リリースから得てください。予定変更後は状態を再確認し、ダウンロードしたソフトではなく稼働ノードを表す記録にします。
