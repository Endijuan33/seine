Запустите собственный узел Blocknet и проверьте его подключение и следование цепочке. Руководство использует официальный клиент командной строки для управления core основной сети и проверки пиров, синхронизации и обновлений. Команды проверены на клиенте v1.2.0 26 октября 2026 года. Держите рядом [официальный справочник](https://github.com/blocknetprivacy/blocknet/blob/948af4de8b7a3e3cddc86a329c7d2d003cb3fd6b/docs/reference-blocknet.md) установленной версии.

## Что нужно для запуска узла Blocknet?

<Answer>
Используйте официальный клиент для своей ОС, компьютер с местом для данных цепочки и интернет. Клиент устанавливает и управляет фоновым core. После запуска проверьте пиры и прогресс. Создание кошелька и майнинг — отдельные задачи, которые можно добавить, когда узел работает.
</Answer>

## Выберите официальный клиент и сеть

Скачайте архив для своей системы и процессора из [официальных выпусков](https://github.com/blocknetprivacy/blocknet/releases/latest). Распакуйте и откройте терминал, где доступен исполняемый файл. Примеры используют `blocknet`; в Windows — `blocknet.exe`. Если файл отсутствует в пути поиска команд, укажите реальный путь, например `./blocknet` в Linux или macOS.

Для обычной сети Blocknet используйте mainnet. Testnet — отдельная среда со своими настройками и данными. Запишите выбранную сеть, чтобы не сравнивать высоту testnet с обозревателем mainnet. Здесь рассматривается узел; [руководство кошелька](/ru/blog/blocknet-wallet-for-mining/) отвечает за создание, восстановление и адрес получения.

## Установите и запустите фоновый core

Для первоначальной настройки запустите мастер в интерактивном терминале:

```sh
blocknet setup
```

Читайте каждый вопрос. Проверенный мастер сохраняет настройки, планирует автообновления, предлагает при необходимости скачать core и запустить его. Он также показывает настройки сети и локального API. Сохраните локальную привязку для узла, управляемого на этом компьютере.

Документированный ручной путь установки:

```sh
blocknet install latest
blocknet start mainnet
```

`latest` выбирает стабильный выпуск core. Mainnet должна быть включена в конфигурации. Клиент запускает core в фоне и ждёт API. Дайте запуску завершиться: открытие базы и полное достижение актуальной цепочки — разные этапы.

## Как проверить пиры и ход синхронизации?

Подключитесь к работающему core mainnet:

```sh
blocknet attach mainnet
```

В интерактивном приглашении вводите отдельно:

```text
status
peers
```

[Справочник оболочки](https://github.com/blocknetprivacy/blocknet/blob/948af4de8b7a3e3cddc86a329c7d2d003cb3fd6b/docs/reference-core.md) описывает поля. Запишите высоту, хеш последнего блока, число пиров и состояние синхронизации. Список пиров помогает подтвердить сетевые подключения.

Наблюдайте высоту со временем и сравните со свежим ориентиром mainnet, например [официальным обозревателем](https://explorer.blocknetcrypto.com/). Между блоками высота может стоять, а наблюдения относиться к разным моментам. Рассматривайте поля вместе, а не делайте вывод по одному числу. Во время догоняющей синхронизации сохраняйте доступ к сети и хранилищу.

## Различайте синхронизацию цепочки и сканирование кошелька

Синхронизация следует блокам сети. Сканирование ищет в этой истории выходы загруженного кошелька. Восстановленный кошелёк может продолжать сканирование, когда узел уже догнал сеть. Данные кошелька в оболочке поэтому отдельны от высоты узла. Для конкретной выплаты за майнинг используйте [руководство получения](https://bntpool.com/blog/ru/pool-payout-missing-from-wallet/).

Текущий клиент поддерживает checkpoints для ускорения первоначальной синхронизации. [Руководство checkpoints](https://bntpool.com/blog/ru/blocknet-checkpoints-fast-sync/) объясняет источник и объём проверок; быстрые методы не одинаковы. Не удаляйте базу цепочки как обычную реакцию на неподвижный индикатор. Сначала различите загрузку, проверку и сканирование по статусу и журналам.

## Куда смотреть, если запуск требует внимания?

Вне attach следите за журналом управляемого core:

```sh
blocknet logs mainnet
```

Читайте последние сообщения запуска и подключения. Ctrl-C прекращает просмотр. Для настроек, путей, установленных версий и связи:

```sh
blocknet doctor
```

Документированная команда doctor сообщает результаты без изменения настройки. Сохраните точное сообщение до выбора исправления.

Проверьте нужный core и сеть, установленный выбранный файл и адрес локального API. Обратитесь к [официальной диагностике](https://github.com/blocknetprivacy/blocknet/blob/948af4de8b7a3e3cddc86a329c7d2d003cb3fd6b/docs/troubleshooting.md) по указанному состоянию. Не раскрывайте учётные данные API и материалы кошелька при обмене диагностикой. Версия, ОС и нужная ошибка обычно полезнее целого каталога конфигурации.

## Разберитесь с обновлениями и намеренной остановкой

В проверенном клиенте планировщик и некоторые управляющие команды ищут обновления. Внешняя `blocknet status` может запустить проверку; она отличается от `status` внутри attach. Обновления могут перезапускать управляемые core, следующие `latest`; закреплённые версии остаются. Для узла с зависимыми службами прочтите [справочник обновлений](https://github.com/blocknetprivacy/blocknet/blob/948af4de8b7a3e3cddc86a329c7d2d003cb3fd6b/docs/reference-upgrade.md).

Планируйте обслуживание с учётом потребителей API. Для выхода из attach введите `quit`; core продолжает работу. Чтобы намеренно остановить этот core mainnet, выполните `blocknet stop mainnet` в системном терминале. После обновления или перезапуска проверьте активную версию, подключение и прогресс. Храните резервную копию кошелька независимо от файлов core.

## Используйте узел для выбранной задачи

Подключённый узел обслуживает кошелёк и локальные запросы без включения майнинга. Для bntpool.com следуйте [руководству пула](https://bntpool.com/blog/ru/mine-blocknet-on-bntpool/) и обычному подключению seine. Собственный узел — отдельный выбор. Для прямого майнинга прочтите инструкции режима daemon и проверьте API перед подключением.

Ведите краткую запись: сеть, версии клиента/core, расположение данных, политика обновления и проверки прогресса. Она поможет подготовиться к [Faraday](/ru/blog/blocknet-faraday-upgrade/), чьи будущие указания активации должны поступить с официальным выпуском. После запланированного изменения снова проверьте статус: запись должна описывать работающий узел, а не только скачанную программу.
