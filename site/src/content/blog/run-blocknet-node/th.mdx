รันโหนด Blocknet ของคุณและเรียนรู้วิธีตรวจว่าเชื่อมต่อและตามเชนอยู่ คู่มือนี้ใช้ไคลเอนต์บรรทัดคำสั่งทางการจัดการ core บน mainnet แล้วตรวจเพียร์ การซิงก์ และอัปเดต คำสั่งตรวจเทียบกับไคลเอนต์ v1.2.0 เมื่อ 26 ตุลาคม 2026 เปิด[เอกสารคำสั่งทางการ](https://github.com/blocknetprivacy/blocknet/blob/948af4de8b7a3e3cddc86a329c7d2d003cb3fd6b/docs/reference-blocknet.md)ของเวอร์ชันที่ติดตั้งไว้ประกอบ

## ต้องมีอะไรเพื่อรันโหนด Blocknet?

<Answer>
ใช้ไคลเอนต์ Blocknet ทางการที่ตรงระบบปฏิบัติการ คอมพิวเตอร์ที่มีที่ว่างเก็บเชน และอินเทอร์เน็ต ไคลเอนต์ติดตั้งและจัดการ core เบื้องหลัง เมื่อทำงานแล้วให้ตรวจเพียร์กับความคืบหน้าเชน การสร้างกระเป๋าและขุดเป็นอีกงานซึ่งเพิ่มหลังโหนดทำงานได้
</Answer>

## เลือกไคลเอนต์ทางการและเครือข่าย

ดาวน์โหลดไฟล์บีบอัดที่ตรงระบบและโปรเซสเซอร์จาก[รุ่นไคลเอนต์ทางการ](https://github.com/blocknetprivacy/blocknet/releases/latest) แตกไฟล์แล้วเปิดเทอร์มินัลในที่เรียกไฟล์รันได้ ตัวอย่างใช้ชื่อ `blocknet` ส่วน Windows ใช้ `blocknet.exe` หากไม่ได้อยู่ในพาธค้นหาคำสั่ง ให้เรียกพาธจริง เช่น `./blocknet` บน Linux หรือ macOS

ใช้ mainnet สำหรับเครือข่าย Blocknet ปกติ ส่วน testnet เป็นอีกสภาพแวดล้อมที่แยกค่าและข้อมูล จดเครือข่ายที่เลือกเพื่อไม่เทียบความสูง testnet กับตัวสำรวจ mainnet คู่มือนี้เน้นจัดการโหนด ส่วนสร้าง กู้คืน และเลือกที่อยู่รับดู[คู่มือกระเป๋า](/th/blog/blocknet-wallet-for-mining/)

## ติดตั้งและเริ่ม core เบื้องหลัง

ตั้งค่าครั้งแรกให้เปิดตัวช่วยในเทอร์มินัลแบบโต้ตอบ:

```sh
blocknet setup
```

อ่านแต่ละคำถาม ตัวช่วยที่ตรวจจะบันทึกค่า ตั้งเวลาอัปเกรดอัตโนมัติ เสนอดาวน์โหลด core เมื่อจำเป็น และเสนอเริ่มทำงาน มีค่าเครือข่ายกับ API ในเครื่องด้วย คงการผูกแบบ local สำหรับโหนดที่จัดการบนคอมพิวเตอร์นี้

ขั้นติดตั้งเองตามเอกสารคือ:

```sh
blocknet install latest
blocknet start mainnet
```

`latest` เลือก core รุ่นเสถียร การเปิด mainnet ต้องเปิดใช้ในค่า ไคลเอนต์รัน core เบื้องหลังแล้วรอ API ให้เวลางานเริ่มต้นเสร็จ การเริ่มฐานข้อมูลครั้งแรกกับเชนตามทันทั้งหมดเป็นคนละจุดหมาย

## ตรวจเพียร์และความคืบหน้าซิงก์อย่างไร?

เชื่อมไปยัง mainnet core ที่ทำงานอยู่:

```sh
blocknet attach mainnet
```

ในพรอมป์ต์โต้ตอบ ให้ป้อนคำสั่งตรวจทีละคำสั่ง:

```text
status
peers
```

[เอกสารเชลล์](https://github.com/blocknetprivacy/blocknet/blob/948af4de8b7a3e3cddc86a329c7d2d003cb3fd6b/docs/reference-core.md)อธิบายช่องของโหนด จดความสูง แฮชบล็อกที่ดีที่สุด จำนวนเพียร์ และสถานะซิงก์ รายชื่อเพียร์ช่วยยืนยันการเชื่อมต่อเครือข่าย

ดูความสูงตามเวลาและเทียบข้อมูล mainnet ล่าสุด เช่น [ตัวสำรวจทางการ](https://explorer.blocknetcrypto.com/) ความสูงอาจนิ่งระหว่างบล็อกและการสังเกตอาจเกิดคนละเวลา ใช้หลายช่องร่วมกัน ไม่ประกาศสำเร็จจากเลขเดียว หากโหนดกำลังตามให้ทัน ให้คงเครือข่ายและพื้นที่เก็บข้อมูลพร้อมใช้

## แยกซิงก์เชนจากสแกนกระเป๋า

การซิงก์เชนตามบล็อกของเครือข่าย ส่วนสแกนกระเป๋าค้นหาประวัตินั้นเพื่อหาเอาต์พุตของกระเป๋าที่โหลด กระเป๋ากู้คืนอาจยังสแกนหลังโหนดทันแล้ว ดังนั้นข้อมูลกระเป๋าในเชลล์เมื่อมีจึงเป็นข้อสังเกตแยกจากความสูงโหนด ใช้[คู่มือเงินเข้ากระเป๋า](https://bntpool.com/blog/th/pool-payout-missing-from-wallet/)เมื่อตามการจ่ายขุดรายการเฉพาะ

ไคลเอนต์ปัจจุบันรองรับเช็กพอยต์เพื่อซิงก์เริ่มต้นเร็วขึ้นด้วย ดู[คู่มือเช็กพอยต์](https://bntpool.com/blog/th/blocknet-checkpoints-fast-sync/)สำหรับแหล่งที่มาและขอบเขตตรวจสอบ ไม่ถือว่าซิงก์เร็วทุกวิธีเหมือนกัน อย่าลบฐานข้อมูลเชนเป็นวิธีปกติเพียงเพราะหน้าคืบหน้านิ่ง แยกการดาวน์โหลด การตรวจสอบ และสแกนกระเป๋าด้วยสถานะและล็อกก่อน

## ถ้าเริ่มทำงานมีปัญหาควรดูที่ไหน?

นอกเชลล์ attach ให้ติดตามล็อก core ที่จัดการ:

```sh
blocknet logs mainnet
```

อ่านข้อความเริ่มต้นและเชื่อมต่อล่าสุด กด Ctrl-C เพื่อเลิกตามล็อก หากตรวจค่า พาธ รุ่นที่ติดตั้ง และการเชื่อมต่อ ใช้:

```sh
blocknet doctor
```

คำสั่ง doctor ตามเอกสารรายงานสิ่งที่พบโดยไม่เปลี่ยนชุดตั้งค่า เก็บข้อความตรงตามจริงก่อนเลือกแก้

ตรวจ core และเครือข่ายที่ตั้งว่าเป็นตัวที่ต้องการ ไบนารีที่เลือกติดตั้งแล้ว และที่อยู่ API ในเครื่องตรงกัน ดู[คู่มือแก้ปัญหาทางการ](https://github.com/blocknetprivacy/blocknet/blob/948af4de8b7a3e3cddc86a329c7d2d003cb3fd6b/docs/troubleshooting.md)ตามอาการที่รายงาน เก็บข้อมูลรับรอง API และข้อมูลกระเป๋าเป็นส่วนตัวเมื่อแชร์วินิจฉัย เวอร์ชัน ระบบ และข้อผิดพลาดที่เกี่ยวข้องมักเป็นจุดเริ่มดีกว่าโฟลเดอร์ค่าทั้งหมด

## เข้าใจอัปเดตและการหยุดโดยตั้งใจ

ในไคลเอนต์ที่ตรวจ การเช็กอัปเกรดอัตโนมัติทำผ่านตัวตั้งเวลาและบางคำสั่งจัดการวงจร คำสั่งภายนอก `blocknet status` อาจกระตุ้นตรวจอัปเดต ซึ่งต่างจาก `status` ภายใน attach อัปเดตที่พบอาจรีสตาร์ต core ที่ตาม `latest` แต่ไม่แตะรุ่นที่ปักไว้ อ่าน[เอกสารอัปเกรด](https://github.com/blocknetprivacy/blocknet/blob/948af4de8b7a3e3cddc86a329c7d2d003cb3fd6b/docs/reference-upgrade.md)ก่อนใช้กับโหนดที่มีบริการพึ่งพา

วางแผนบำรุงรักษาตามสิ่งที่ใช้ API ของโหนด ออกจาก attach ด้วย `quit` โดย core ยังทำงาน หากตั้งใจหยุด mainnet core ที่จัดการ ให้เรียก `blocknet stop mainnet` จากเทอร์มินัลระบบ หลังอัปเดตหรือรีสตาร์ตตามแผน ตรวจรุ่นที่ทำงาน การเชื่อมต่อ และความคืบหน้าเชน เก็บสำรองกระเป๋าแยกอิสระจากไบนารี core ที่ติดตั้ง

## ใช้โหนดกับงานที่ตั้งใจ

โหนดที่เชื่อมต่อรองรับกระเป๋าและสอบถามเชนในเครื่องได้โดยไม่เปิดขุด หากขุดผ่าน bntpool.com ให้ทำตาม[คู่มือตั้งค่าพูล](https://bntpool.com/blog/th/mine-blocknet-on-bntpool/)และใช้การเชื่อมต่อพูลปกติของ seine การรันโหนดเองเป็นอีกทางเลือก สำหรับขุดตรง อ่านคำแนะนำโหมด daemon ของโปรแกรมและตรวจค่า API ก่อนเชื่อม

เก็บบันทึกสั้น ๆ: เครือข่าย รุ่นไคลเอนต์และ core ที่เก็บข้อมูล นโยบายอัปเดต และการตรวจที่ยืนยันความคืบหน้าปกติ สิ่งนี้ช่วยเตรียม [Faraday](/th/blog/blocknet-faraday-upgrade/) ด้วย โดยคำแนะนำเปิดใช้ในอนาคตควรมาจากรุ่นทางการ ตรวจสถานะใหม่หลังเปลี่ยนตามแผน เพื่อให้บันทึกอธิบายโหนดที่ทำงาน ไม่ใช่แค่ซอฟต์แวร์ที่โหลดมา
