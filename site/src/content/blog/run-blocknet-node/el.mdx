Τρέξτε δικό σας κόμβο Blocknet και ελέγξτε ότι συνδέεται και ακολουθεί την αλυσίδα. Ο οδηγός χρησιμοποιεί τον επίσημο πελάτη γραμμής εντολών για core mainnet, peers, συγχρονισμό και ενημερώσεις. Οι εντολές ελέγχθηκαν με πελάτη v1.2.0 στις 26 Οκτωβρίου 2026. Κρατήστε διαθέσιμη την [επίσημη αναφορά](https://github.com/blocknetprivacy/blocknet/blob/948af4de8b7a3e3cddc86a329c7d2d003cb3fd6b/docs/reference-blocknet.md) της εγκατεστημένης έκδοσης.

## Τι χρειάζεται για έναν κόμβο Blocknet;

<Answer>
Χρησιμοποιήστε τον επίσημο πελάτη του λειτουργικού σας, υπολογιστή με χώρο για δεδομένα αλυσίδας και διαδίκτυο. Ο πελάτης εγκαθιστά και διαχειρίζεται το core στο παρασκήνιο. Μετά ελέγξτε peers και πρόοδο. Δημιουργία πορτοφολιού και εξόρυξη είναι χωριστές εργασίες που προσθέτετε αφού λειτουργήσει ο κόμβος.
</Answer>

## Επιλέξτε επίσημο πελάτη και δίκτυο

Κατεβάστε το αρχείο για σύστημα και επεξεργαστή από τις [επίσημες εκδόσεις](https://github.com/blocknetprivacy/blocknet/releases/latest). Αποσυμπιέστε και ανοίξτε τερματικό όπου είναι διαθέσιμο το εκτελέσιμο. Τα παραδείγματα χρησιμοποιούν `blocknet`· στα Windows, `blocknet.exe`. Αν δεν είναι στη διαδρομή αναζήτησης, δώστε την πραγματική διαδρομή, όπως `./blocknet` σε Linux ή macOS.

Το mainnet είναι το κανονικό δίκτυο Blocknet. Το testnet είναι χωριστό περιβάλλον με δικά του δεδομένα και ρυθμίσεις. Σημειώστε το δίκτυο για να μη συγκρίνετε ύψος testnet με explorer mainnet. Εδώ διαχειριζόμαστε κόμβο· ο [οδηγός πορτοφολιού](/el/blog/blocknet-wallet-for-mining/) καλύπτει δημιουργία, ανάκτηση και διεύθυνση λήψης.

## Εγκαταστήστε και ξεκινήστε το core

Για πρώτη ρύθμιση, τρέξτε τον βοηθό σε διαδραστικό τερματικό:

```sh
blocknet setup
```

Διαβάστε κάθε ερώτηση. Ο εξετασμένος βοηθός αποθηκεύει ρυθμίσεις, προγραμματίζει αυτόματες ενημερώσεις και προτείνει λήψη core όταν χρειάζεται και εκκίνησή του. Παρέχει ρυθμίσεις δικτύου και τοπικού API. Κρατήστε τοπική δέσμευση για κόμβο που διαχειρίζεστε σε αυτόν τον υπολογιστή.

Η τεκμηριωμένη χειροκίνητη εγκατάσταση είναι:

```sh
blocknet install latest
blocknet start mainnet
```

Το `latest` επιλέγει σταθερή έκδοση core. Το mainnet πρέπει να είναι ενεργό στις ρυθμίσεις. Ο πελάτης τρέχει το core στο παρασκήνιο και περιμένει το API. Αφήστε την εκκίνηση να ολοκληρωθεί· έναρξη βάσης και πλήρης ενημέρωση αλυσίδας είναι διαφορετικά ορόσημα.

## Πώς ελέγχετε peers και συγχρονισμό;

Συνδεθείτε στο ενεργό core mainnet:

```sh
blocknet attach mainnet
```

Στη διαδραστική προτροπή εισαγάγετε χωριστά:

```text
status
peers
```

Η [αναφορά κελύφους](https://github.com/blocknetprivacy/blocknet/blob/948af4de8b7a3e3cddc86a329c7d2d003cb3fd6b/docs/reference-core.md) εξηγεί τα πεδία. Καταγράψτε ύψος, hash τελευταίου μπλοκ, πλήθος peers και κατάσταση συγχρονισμού. Η λίστα peers βοηθά στην επιβεβαίωση συνδέσεων.

Παρακολουθήστε το ύψος με τον χρόνο και συγκρίνετε με πρόσφατη αναφορά mainnet, όπως τον [επίσημο explorer](https://explorer.blocknetcrypto.com/). Το ύψος μπορεί να μένει σταθερό μεταξύ μπλοκ και οι παρατηρήσεις να γίνονται σε διαφορετικές στιγμές. Συνδυάστε τα πεδία αντί να κρίνετε από έναν αριθμό. Όσο ενημερώνεται, διατηρήστε διαθέσιμα σύνδεση και αποθήκευση.

## Ξεχωρίστε συγχρονισμό αλυσίδας και σάρωση

Ο συγχρονισμός ακολουθεί τα μπλοκ του δικτύου. Η σάρωση πορτοφολιού ψάχνει στο ιστορικό τις εξόδους του φορτωμένου πορτοφολιού. Ένα αποκατεστημένο πορτοφόλι μπορεί να σαρώνει αφού ο κόμβος ενημερωθεί. Τα στοιχεία του στο κέλυφος είναι χωριστή παρατήρηση από το ύψος κόμβου. Για συγκεκριμένη πληρωμή εξόρυξης, δείτε τον [οδηγό λήψης](https://bntpool.com/blog/el/pool-payout-missing-from-wallet/).

Ο τρέχων πελάτης υποστηρίζει checkpoints για ταχύτερο αρχικό συγχρονισμό. Ο [οδηγός checkpoints](https://bntpool.com/blog/el/blocknet-checkpoints-fast-sync/) εξηγεί πηγή και εύρος επαλήθευσης· οι γρήγορες μέθοδοι δεν είναι ίδιες. Μη διαγράφετε συνήθως τη βάση επειδή ο δείκτης δεν κινείται. Ξεχωρίστε πρώτα λήψη, επαλήθευση και σάρωση μέσω κατάστασης και καταγραφών.

## Πού κοιτάτε αν η εκκίνηση χρειάζεται προσοχή;

Έξω από attach, ακολουθήστε την καταγραφή του core:

```sh
blocknet logs mainnet
```

Διαβάστε πρόσφατα μηνύματα εκκίνησης και σύνδεσης. Το Ctrl-C σταματά την παρακολούθηση. Για ρυθμίσεις, διαδρομές, εκδόσεις και συνδεσιμότητα:

```sh
blocknet doctor
```

Η τεκμηριωμένη εντολή doctor αναφέρει ευρήματα χωρίς αλλαγές. Κρατήστε το ακριβές μήνυμα πριν επιλέξετε διόρθωση.

Ελέγξτε αναμενόμενο core και δίκτυο, εγκατάσταση επιλεγμένου εκτελέσιμου και διεύθυνση τοπικού API. Συμβουλευτείτε την [επίσημη αντιμετώπιση προβλημάτων](https://github.com/blocknetprivacy/blocknet/blob/948af4de8b7a3e3cddc86a329c7d2d003cb3fd6b/docs/troubleshooting.md). Κρατήστε ιδιωτικά διαπιστευτήρια API και υλικό πορτοφολιού όταν μοιράζεστε διάγνωση. Έκδοση, λειτουργικό και σχετικό σφάλμα συνήθως βοηθούν περισσότερο από ολόκληρο κατάλογο ρυθμίσεων.

## Κατανοήστε ενημερώσεις και σκόπιμη διακοπή

Στον εξετασμένο πελάτη, ο προγραμματιστής και επιλεγμένες εντολές διαχείρισης ελέγχουν ενημερώσεις. Η εξωτερική `blocknet status` μπορεί να ξεκινήσει έλεγχο· διαφέρει από `status` μέσα στο attach. Ενημερώσεις μπορούν να επανεκκινήσουν core που ακολουθούν `latest`, ενώ οι καρφιτσωμένες εκδόσεις μένουν. Διαβάστε την [αναφορά ενημερώσεων](https://github.com/blocknetprivacy/blocknet/blob/948af4de8b7a3e3cddc86a329c7d2d003cb3fd6b/docs/reference-upgrade.md) για εξαρτώμενες υπηρεσίες.

Σχεδιάστε συντήρηση γύρω από όσους χρησιμοποιούν το API. Με `quit` βγαίνετε από attach· το core συνεχίζει. Για σκόπιμη διακοπή του core mainnet, τρέξτε `blocknet stop mainnet` στο τερματικό συστήματος. Μετά από ενημέρωση ή επανεκκίνηση ελέγξτε ενεργή έκδοση, σύνδεση και πρόοδο. Κρατήστε αντίγραφο πορτοφολιού ανεξάρτητα από τα εκτελέσιμα core.

## Χρησιμοποιήστε τον κόμβο για την εργασία σας

Συνδεδεμένος κόμβος υποστηρίζει πορτοφόλι και τοπικά ερωτήματα χωρίς εξόρυξη. Για bntpool.com ακολουθήστε τον [οδηγό pool](https://bntpool.com/blog/el/mine-blocknet-on-bntpool/) και την κανονική σύνδεση seine. Ο δικός σας κόμβος είναι χωριστή επιλογή. Για άμεση εξόρυξη διαβάστε τη λειτουργία daemon και ελέγξτε το API πριν συνδεθείτε.

Κρατήστε σύντομο αρχείο: δίκτυο, εκδόσεις πελάτη/core, θέση δεδομένων, πολιτική ενημέρωσης και ελέγχους προόδου. Βοηθά και για το [Faraday](/el/blog/blocknet-faraday-upgrade/), του οποίου οι μελλοντικές οδηγίες ενεργοποίησης πρέπει να προέλθουν από την επίσημη έκδοση. Μετά από προγραμματισμένη αλλαγή ελέγξτε ξανά ώστε το αρχείο να περιγράφει ενεργό κόμβο, όχι μόνο ληφθέν λογισμικό.
