ส่งการชำระ Blocknet จากกระเป๋าที่เตรียมพร้อม แล้วติดตามจากหน้าทบทวนของผู้ส่งถึงประวัติของผู้รับ ขั้นตอนนี้ใช้ไคลเอนต์บรรทัดคำสั่งอย่างเป็นทางการ v1.2.0 ที่ตรวจสอบเมื่อ 26 ตุลาคม 2026 โดยเชื่อมที่อยู่ ภาพตัวอย่างการชำระเงิน และบันทึกธุรกรรมเป็นกระบวนการเดียว หากยังต้องสร้างหรือกู้คืนกระเป๋า ให้เริ่มด้วย [คู่มือตั้งค่ากระเป๋า](/th/blog/blocknet-wallet-for-mining/)

## ส่งและรับ Blocknet อย่างไร?

<Answer>
เมื่อต้องการรับ ให้แชร์ที่อยู่รับของกระเป๋าหรือชื่อย่อที่ตรวจสอบแล้ว เมื่อต้องการส่ง ให้กรอกผู้รับและจำนวนเงินในกระเป๋า ทบทวนปลายทางกับค่าธรรมเนียม แล้วยืนยันการชำระเงินที่ตั้งใจไว้ เก็บ ID ธุรกรรมหลังจากนั้น ผู้รับตรวจประวัติกระเป๋าของตนและยอดที่ใช้จ่ายได้ระหว่างที่ธุรกรรมดำเนินไป
</Answer>

## เปิดกระเป๋าที่ถูกต้องก่อนเตรียมชำระ

เชื่อมต่อ core บน mainnet ที่กำลังทำงานด้วยไคลเอนต์อย่างเป็นทางการ:

```sh
blocknet attach mainnet
```

ที่พรอมต์โต้ตอบ ใช้คำสั่งต่อไปนี้เพื่อเปิดกระเป๋าที่มีอยู่:

```text
load
```

เลือกไฟล์กระเป๋าที่ต้องการแล้วกรอกรหัสผ่านเมื่อระบบถาม [คู่มือโหนด](/th/blog/run-blocknet-node/) อธิบายการเริ่มและตรวจ core ที่ทำงานเบื้องหลัง

ตรวจที่อยู่รับและยอดคงเหลือด้วยคำสั่งแยกกันดังนี้:

```text
address
balance
```

ยืนยันว่าคุณใช้กระเป๋าและเครือข่ายที่ตั้งใจไว้ เมื่อเตรียมส่งให้อ่านจำนวนที่ใช้จ่ายได้ [เอกสารเชลล์อย่างเป็นทางการ](https://github.com/blocknetprivacy/blocknet/blob/948af4de8b7a3e3cddc86a329c7d2d003cb3fd6b/docs/reference-core.md) อธิบายคำสั่งเหล่านี้ กระเป๋าแบบกราฟิกอาจนำเสนองานเดียวกันด้วยปุ่มและชื่อที่ต่างกัน

## ควรแชร์อะไรกับผู้ส่ง?

คัดลอกที่อยู่เต็มจากคำสั่ง address ของกระเป๋าแล้วส่งผ่านช่องทางชำระเงินที่ตกลงกัน หากใช้ [Blocknet ID](/th/blog/blocknet-id-pay-by-name/) ให้แชร์ชื่อย่อที่ถูกต้องและให้ผู้ส่งตรวจที่อยู่ที่แปลงได้ ตรวจการสะกดกับผู้รับเมื่อเตรียมการชำระเงินใหม่ ชื่อแสดงผลที่คุ้นเคยอย่างเดียวไม่เท่ากับการตรวจรายละเอียดรับเงินจริง

[ลิงก์ชำระเงิน](/th/blog/blocknet-payment-links/) สามารถใส่ยอดที่ร้องขอและบันทึกช่วยจำเพิ่มเติมได้ ใช้เพื่อลดการพิมพ์ซ้ำแล้วทบทวนข้อมูลที่เติมในกระเป๋า คำกู้คืนและกุญแจส่วนตัวไม่ใช่รายละเอียดรับเงิน อย่าใส่ไว้ในข้อความ ใบแจ้งหนี้ หรือภาพหน้าจอ ข้อมูลที่ขั้นตอนนี้ต้องการคือที่อยู่รับ

## กรอกผู้รับและยอดที่ต้องการ

ต่อไปนี้เป็นตัวอย่างรูปแบบคำสั่งภายใน attach แทนข้อความตัวพิมพ์ใหญ่ด้วยที่อยู่ผู้รับจริง และแทนจำนวนตัวอย่างด้วยยอดที่คุณต้องการชำระ:

```text
send RECIPIENT_ADDRESS 1.25
```

ข้อความแทนที่ไม่ใช่ที่อยู่สำหรับชำระ ไคลเอนต์ที่ตรวจสอบยังรับชื่อย่อ Blocknet ID ในตำแหน่งผู้รับด้วย

หากต้องอ้างอิงใบแจ้งหนี้หรือคำสั่งซื้อ ให้เพิ่มบันทึกตาม [คู่มือบันทึกช่วยจำที่เข้ารหัส](/th/blog/blocknet-encrypted-memos/) ตรวจข้อความที่ผู้รับขอก่อนเตรียม ขั้นตอนแรกนี้เน้นยอดคงที่ การส่งทั้งหมดเป็นอีกการดำเนินการที่คิดค่าธรรมเนียมต่างกัน [คู่มือค่าธรรมเนียม](/th/blog/blocknet-transaction-fees/) อธิบายความต่างและวิธีที่เงินทอนกลับเข้ากระเป๋า

## ทบทวนภาพตัวอย่างก่อนยืนยัน

[ไคลเอนต์ที่ตรวจสอบ](https://github.com/blocknetprivacy/blocknet/blob/948af4de8b7a3e3cddc86a329c7d2d003cb3fd6b/attach_wallet.go) ขอภาพตัวอย่างแบบทดลองก่อนส่ง โดยแสดงจำนวนเงิน ปลายทาง ค่าธรรมเนียม และเงินทอนถ้ามี หากแปลงชื่อย่อแล้ว หน้าทบทวนจะแสดงที่อยู่ด้วย หากใส่บันทึกช่วยจำให้ตรวจด้วย เปรียบเทียบข้อมูลเหล่านี้กับคำขอที่คุณตั้งใจชำระก่อนตัดสินใจที่พรอมต์

ที่ `Confirm [y/N]:` ให้กรอก `y` เฉพาะการชำระเงินที่ตั้งใจทำ กด Enter หรือตอบ no เพื่อยกเลิกภาพตัวอย่าง สำหรับการส่งยอดคงที่ทั่วไป จำนวนของผู้รับและค่าธรรมเนียมเครือข่ายเป็นคนละส่วนของการคำนวณในกระเป๋า ใช้ค่าจากภาพตัวอย่างปัจจุบันแทนการคัดลอกค่าธรรมเนียมจากตัวอย่างหรือภาพเก่า

## เก็บ ID ธุรกรรมหลังส่ง

หลังยืนยันและส่งสำเร็จ CLI จะพิมพ์ ID ธุรกรรมกับลิงก์ตัวสำรวจ บันทึกตัวระบุนั้นกับรายการชำระเงินของคุณเพื่อค้นหาธุรกรรมเดิมอีกครั้ง วิธีนี้มีประโยชน์ในการตรวจความคืบหน้ามากกว่าภาพที่ตัดเฉพาะข้อความสำเร็จ เก็บผู้รับ ยอดที่ตั้งใจ และเลขอ้างอิงใบแจ้งหนี้ในบันทึกส่วนตัวตามความเหมาะสม

ใช้คำสั่งประวัติกระเป๋าเพื่อทบทวนกิจกรรม:

```text
history
```

ไคลเอนต์ปัจจุบันรวมเอาต์พุตที่กระเป๋ารับเข้ากับรายการส่งออกที่บันทึกไว้ รวมถึงรายการส่งที่ยังอยู่ใน mempool หากการดำเนินการแจ้งผลไม่ชัดเจน ให้ตรวจประวัติเดิมและตัวระบุก่อนเตรียมการชำระเงินอีกครั้ง การส่งซ้ำเป็นคำสั่งชำระเงินใหม่ จึงต้องทราบก่อนว่ารายการแรกเกิดอะไรขึ้น

## ยืนยันการรับในกระเป๋าผู้รับ

ผู้รับตรวจประวัติในกระเป๋าของตนที่โหลดไว้และจับคู่รายการรับกับธุรกรรมที่กำลังตรวจ การสแกนกระเป๋าจะระบุเอาต์พุตที่เป็นของกระเป๋านั้น หน้าธุรกรรมสาธารณะให้ข้อมูลเครือข่าย ส่วนกระเป๋าผู้รับให้รายละเอียดการชำระเงินส่วนตัว [คู่มือตัวสำรวจ](/th/blog/blocknet-explorer-guide/) อธิบายการอ่านบันทึกสาธารณะควบคู่กับการตรวจนี้

ตรวจยอดกระเป๋าอีกครั้งระหว่างที่การชำระเงินดำเนินไป ใช้จ่ายได้ รอดำเนินการ และยังไม่ยืนยันเป็นคนละสถานะ กระเป๋าที่กู้คืนหรือเพิ่งเปิดอาจยังสแกนประวัติแม้โหนดเชื่อมต่อแล้ว ปล่อยให้งานเดินหน้าจากนั้นตรวจอีกครั้ง หากเป็นการจ่ายจากการขุด [คู่มือจากพูลสู่กระเป๋า](https://bntpool.com/blog/th/pool-payout-missing-from-wallet/) อธิบายขั้นตอนเพิ่มจากบันทึกจ่ายของพูลจนถึงการรับในกระเป๋า

## สร้างขั้นตอนชำระเงินที่ทำซ้ำได้

สำหรับแต่ละการชำระเงิน เริ่มด้วยกระเป๋าและเครือข่ายที่ถูกต้อง ตรวจรายละเอียดรับเงิน ทบทวนภาพตัวอย่างปัจจุบัน แล้วเก็บ ID ธุรกรรมที่ได้ จากนั้นผู้รับตรวจประวัติและยอดของตน สิ่งที่สังเกตเหล่านี้อธิบายคนละขั้น จึงควรบันทึกขั้นที่ตรวจจริง แทนการถือว่าทุกหน้าสำเร็จคือการรับขั้นสุดท้าย

ใช้คำแนะนำอย่างเป็นทางการของไคลเอนต์ที่ติดตั้งต่อไปเมื่อชื่อหรือขั้นตอนเปลี่ยน คู่มือนี้อธิบายขั้นตอน CLI ที่ตรวจสอบ ส่วนลิงก์อื่นให้รายละเอียดชื่อ บันทึก ค่าธรรมเนียม และการสแกน หากคุณขุดกับ [bntpool.com](https://bntpool.com/blog/th/mine-blocknet-on-bntpool/) ด้วย ให้ผูกที่อยู่รับเงินจากพูลกับกระเป๋าที่คุณเปิดและตรวจได้ด้วยขั้นตอนรับแบบเดียวกัน
