從已準備好的錢包傳送一筆 Blocknet 付款，然後從付款方的核對畫面一路追蹤到收款方的歷史紀錄。本指南使用官方命令列用戶端 v1.2.0，核對日期為 2026年10月26日，將地址、付款預覽與交易紀錄串成一個流程。如果還需要建立或復原錢包，請先閱讀[錢包設定指南](/zh-hant/blog/blocknet-wallet-for-mining/)。

## 如何傳送與接收 Blocknet？

<Answer>
接收 Blocknet 時，分享錢包收款地址或已驗證的短名稱。傳送時，在錢包中輸入收款方與金額，核對目標地址和手續費，再確認要進行的付款。隨後保留交易 ID。隨著交易推進，收款方檢查自己的錢包歷史與可花費餘額。
</Answer>

## 準備付款前先開啟正確的錢包

使用官方用戶端連線至正在執行的主網 core：

```sh
blocknet attach mainnet
```

在互動式提示下，用以下指令開啟現有錢包：

```text
load
```

選擇要使用的錢包檔案，並依提示輸入密碼。[節點指南](/zh-hant/blog/run-blocknet-node/)介紹背景 core 的啟動與檢查方法。

分別輸入以下指令，查看收款地址與餘額：

```text
address
balance
```

確認使用的是預期的錢包與網路。準備轉出付款時，應查看可花費金額。[官方互動終端機參考](https://github.com/blocknetprivacy/blocknet/blob/948af4de8b7a3e3cddc86a329c7d2d003cb3fd6b/docs/reference-core.md)記載這些指令；圖形錢包可能使用不同控制項與標籤完成相同任務。

## 應該向付款方分享哪些資訊？

複製地址指令回傳的完整地址，透過約定的付款管道提供給對方。如果使用 [Blocknet ID](/zh-hant/blog/blocknet-id-pay-by-name/)，分享正確的短名稱，並請付款方檢查解析出的地址。準備新付款時，與收款方核對名稱拼寫。看到熟悉的顯示名稱，不等於已核實實際收款資訊。

[付款連結](/zh-hant/blog/blocknet-payment-links/)可以攜帶要求的金額與選用備註，減少重複輸入。使用後仍須檢查錢包填入的詳情。復原助記詞與私密金鑰不是收款資訊，不應放進訊息、發票或螢幕截圖。此步驟需要的是收款地址。

## 輸入收款方與計畫支付的金額

以下是 attach 內的語法範例。請將大寫預留位置替換為實際收款地址，將示例金額替換為你打算支付的金額：

```text
send RECIPIENT_ADDRESS 1.25
```

預留位置不是可用於付款的地址。本文核對的用戶端也支援在收款方位置填寫 Blocknet ID 短名稱。

若需要發票或訂單參考資訊，可依[加密備註指南](/zh-hant/blog/blocknet-encrypted-memos/)新增備註。準備前先核對收款方要求的文字。本次入門流程只介紹固定金額付款；傳送全部餘額是另一種操作，手續費的計入方式不同。[手續費指南](/zh-hant/blog/blocknet-transaction-fees/)解釋此差異，以及找零如何回到錢包。

## 確認前檢查預覽

[已核對的用戶端](https://github.com/blocknetprivacy/blocknet/blob/948af4de8b7a3e3cddc86a329c7d2d003cb3fd6b/attach_wallet.go)會在傳送前要求試算預覽，顯示金額、目標、手續費與可能的找零。若使用解析後的短名稱，核對畫面還會列出對應地址。如果填寫了備註，也要一併檢查。回答確認提示前，將這些詳情與原本要支付的要求進行比對。

在 `Confirm [y/N]:` 處，僅對確實要進行的付款輸入 `y`。按 Enter 或回答否可取消預覽。一般固定金額付款中，收款金額與網路手續費是錢包計算的不同部分。應使用目前預覽中的數值，不要照抄舊範例或截圖裡的手續費。

## 傳送後保留交易 ID

確認傳送並成功後，CLI 會顯示交易 ID 與瀏覽器連結。將識別碼與自己的付款紀錄一併保存，以便再次找到同一筆交易。它比裁切後的成功提示截圖更適合檢查進度。依需要在私人紀錄中保留收款方、計畫金額與發票參考資訊。

使用歷史指令查看活動：

```text
history
```

目前的用戶端會合併錢包收到的輸出與已記錄的轉出付款，包括仍在記憶池中的轉出紀錄。如果某次操作回傳的結果不明確，先檢查既有歷史與識別碼，再準備另一筆付款。重複傳送是新的付款指令，因此應先查明第一筆發生了什麼。

## 在收款方錢包中確認入帳

收款方在自己已載入的錢包中查看歷史，將轉入紀錄與正在核查的交易對應起來。錢包掃描會識別屬於該錢包的輸出。公開交易頁面提供網路資訊，收款錢包則提供付款的私密檢視。[瀏覽器指南](/zh-hant/blog/blocknet-explorer-guide/)解釋如何搭配此步驟閱讀公開紀錄。

隨著付款推進，再次檢查錢包餘額。可花費、待處理與未確認是不同狀態。剛復原或剛開啟的錢包，即使節點已連線，也可能仍在掃描歷史。讓掃描繼續後再檢查。若是挖礦付款，[礦池到錢包指南](https://bntpool.com/blog/zh-hant/pool-payout-missing-from-wallet/)還會追蹤從礦池付款紀錄到錢包入帳的額外步驟。

## 建立可重複使用的付款流程

每筆計畫付款都從正確的錢包與網路開始：核實收款資訊、檢查目前預覽，並保留產生的交易 ID。隨後由收款方檢查歷史與餘額。這些觀察對應不同階段，因此應記錄實際核實的階段，不要把每個成功畫面都當成最終入帳。

當標籤或流程改變時，繼續遵循已安裝用戶端的官方說明。本文介紹核對過的 CLI 操作，連結中的指南進一步說明名稱、備註、手續費與掃描。如果也在 [bntpool.com](https://bntpool.com/blog/zh-hant/mine-blocknet-on-bntpool/) 挖礦，請將付款地址連結至你能開啟、並透過相同收款流程檢查的錢包。
