从已准备好的钱包发送一笔 Blocknet 付款，然后从付款方的核对界面一路追踪到收款方的历史记录。本指南使用官方命令行客户端 v1.2.0，核对日期为 2026年10月26日，将地址、付款预览和交易记录串成一个流程。如果还需要创建或恢复钱包，请先阅读[钱包设置指南](/zh-hans/blog/blocknet-wallet-for-mining/)。

## 如何发送和接收 Blocknet？

<Answer>
接收 Blocknet 时，分享钱包收款地址或已验证的短名称。发送时，在钱包中输入收款方和金额，核对目标地址与手续费，再确认要进行的付款。随后保留交易 ID。随着交易推进，收款方检查自己的钱包历史和可花费余额。
</Answer>

## 准备付款前先打开正确的钱包

使用官方客户端连接正在运行的主网 core：

```sh
blocknet attach mainnet
```

在交互式提示符下，用以下命令打开已有钱包：

```text
load
```

选择要使用的钱包文件，并按提示输入密码。[节点指南](/zh-hans/blog/run-blocknet-node/)介绍了后台 core 的启动和检查方法。

分别输入以下命令，查看收款地址和余额：

```text
address
balance
```

确认使用的是预期的钱包和网络。准备转出付款时，应查看可花费金额。[官方交互终端参考](https://github.com/blocknetprivacy/blocknet/blob/948af4de8b7a3e3cddc86a329c7d2d003cb3fd6b/docs/reference-core.md)记录了这些命令；图形钱包可能使用不同的控件和标签完成相同任务。

## 应该向付款方分享哪些信息？

复制地址命令返回的完整地址，通过约定的付款渠道提供给对方。如果使用 [Blocknet ID](/zh-hans/blog/blocknet-id-pay-by-name/)，分享正确的短名称，并让付款方检查解析出的地址。准备新付款时，与收款方核对名称拼写。看到熟悉的显示名称，并不等于已经核实实际收款信息。

[付款链接](/zh-hans/blog/blocknet-payment-links/)可以携带请求的金额和可选备注，减少重复输入。使用后仍需检查钱包填入的详情。恢复助记词和私钥不是收款信息，不应放进消息、发票或截图。此步骤需要的是收款地址。

## 输入收款方和计划支付的金额

下面是 attach 内的语法示例。请将大写占位符替换为实际收款地址，将示例金额替换为你打算支付的金额：

```text
send RECIPIENT_ADDRESS 1.25
```

占位符不是可用于付款的地址。本文核对的客户端也支持在收款方位置填写 Blocknet ID 短名称。

如果需要发票或订单参考信息，可按[加密备注指南](/zh-hans/blog/blocknet-encrypted-memos/)添加备注。准备前先核对收款方要求的文字。本次入门流程只讲固定金额付款；发送全部余额是另一种操作，手续费的计入方式不同。[手续费指南](/zh-hans/blog/blocknet-transaction-fees/)解释了这个区别，以及找零如何回到钱包。

## 确认前检查预览

[已核对的客户端](https://github.com/blocknetprivacy/blocknet/blob/948af4de8b7a3e3cddc86a329c7d2d003cb3fd6b/attach_wallet.go)会在发送前请求试算预览，显示金额、目标、手续费和可能的找零。若使用解析后的短名称，核对界面还会列出对应地址。如果填写了备注，也要一起检查。回答确认提示前，将这些详情与原本要支付的请求进行比对。

在 `Confirm [y/N]:` 处，仅对确实要进行的付款输入 `y`。按 Enter 或回答否可取消预览。普通固定金额付款中，收款金额与网络手续费是钱包计算的不同部分。应使用当前预览中的数值，不要照抄旧示例或截图里的手续费。

## 发送后保留交易 ID

确认发送并成功后，CLI 会显示交易 ID 和浏览器链接。将标识符与自己的付款记录一起保存，以便再次找到同一笔交易。它比裁剪后的成功提示截图更适合用来检查进度。根据需要，在私人记录中保留收款方、计划金额和发票参考信息。

使用历史命令查看活动：

```text
history
```

当前客户端会合并钱包收到的输出和已记录的转出付款，包括仍在内存池中的转出记录。如果某次操作返回的结果不明确，先检查已有历史和标识符，再准备另一笔付款。重复发送是新的付款指令，因此应先查清第一笔发生了什么。

## 在收款方钱包中确认到账

收款方在自己已加载的钱包中查看历史，将转入记录与正在核查的交易对应起来。钱包扫描会识别属于该钱包的输出。公共交易页面提供网络信息，收款钱包则提供付款的私密视图。[浏览器指南](/zh-hans/blog/blocknet-explorer-guide/)解释了如何结合这一步阅读公共记录。

随着付款推进，再次检查钱包余额。可花费、待处理和未确认是不同状态。刚恢复或刚打开的钱包，即使节点已连接，也可能仍在扫描历史。让扫描继续后再检查。若是挖矿付款，[矿池到钱包指南](https://bntpool.com/blog/zh-hans/pool-payout-missing-from-wallet/)还会追踪从矿池付款记录到钱包到账的额外步骤。

## 建立可重复使用的付款流程

每笔计划付款都从正确的钱包和网络开始：核实收款信息，检查当前预览，保留生成的交易 ID。随后由收款方检查历史和余额。这些观察对应不同阶段，因此应记录实际核实的阶段，而不是把每个成功界面都当成最终到账。

当标签或流程发生变化时，继续遵循已安装客户端的官方说明。本文介绍核对过的 CLI 操作，链接中的指南进一步说明名称、备注、手续费和扫描。如果也在 [bntpool.com](https://bntpool.com/blog/zh-hans/mine-blocknet-on-bntpool/) 挖矿，请将付款地址关联到你能打开、并通过同样收款流程检查的钱包。
