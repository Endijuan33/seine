了解 seine 在挖矿期间改变 CPU 线程数时做了什么。本指南依据公开版本 v0.2.36，解释边挖矿边调优、保存选择及内存调整。安装请从[挖矿指南](/zh-hans/blog/how-to-mine-blocknet/)开始，各面板含义见[仪表盘导览](/zh-hans/blog/seine-dashboard-explained/)。

## CPU 自动调优如何工作？

<Answer>
启用调优后，seine 从兼容的已保存线程数或基于硬件的估计值开始挖矿，再用真实挖矿工作比较设置。它先测基准设置，再试候选设置，然后再次测基准。可用 RAM 和配置的范围共同约束搜索，逐步找到适合机器的选择。
</Answer>

## 搜索结束之前，挖矿已经开始

不设置 `--threads` 即可使用自动线程调优。正常挖矿会在当前资源预算内选择初始数量，无需离线遍历线程数就开始有效工作。兼容缓存可以提供起点。新机器则从程序的估计值开始，通过后续比较改进选择。

每次试验按经过的时间统计已完成的哈希。新内存区域先完成首个哈希，再进入测量窗口。基准—候选—基准顺序帮助区分设置效果与环境变化。明显的基准漂移、内存限制改变或持续丢失工作都可能使本次比较被丢弃。因此，仪表盘上短暂的峰值只是较长决策过程中的一次观察。

## 为什么更多线程不一定有帮助？

每个活跃 CPU 线程使用较大的内存区域，并共享机器的内存带宽。增加线程带来更多并行工作，但效果取决于整个系统。调优器比较 CPU 总 H/s，而不是认定线程最多就最快。[RAM 指南](/zh-hans/blog/how-much-ram-to-mine-blocknet/)解释了内存预算。

默认配置档是 `balanced`。配置档控制调优策略和运行默认值；`efficiency` 是可能偏向较少线程的显式选项。评估期间保持同一配置档。线程数、CPU 放置方式和内存页类型相互影响，所以其他机器或配置的结果只能作为参考，不应直接照搬。

## 其他程序需要 RAM 时会怎样？

自动内存预算随可用资源变化。内存紧张时，CPU 线程可以完成当前哈希、暂停并释放内存区域。持续恢复余量后，程序可以激活可用槽位并继续探索。这让同时运行其他应用的电脑，在同一会话里按环境调整工作线程数。

临时降低数量不一定要抹掉先前学到的较高数量。缓存与当前活跃数的用途不同。Linux 上释放的显式 HugeTLB 区域会回到预留的大页池；seine 不会调整操作系统这个池的大小。修改预留请看[大页指南](/zh-hans/blog/huge-pages-blocknet-mining/)，并将它与普通空闲 RAM 区分。

## seine 也会调优 CPU 计算内核吗？

符合条件的 CPU 除了比较线程数，还可以比较支持的哈希代码路径。这里的内核指哈希计算的软件实现。程序检查处理器支持的指令，通过重复挖矿采样比较可用路径。内核与线程数试验轮流进行，内存管理始终继续。[技术调优指南](https://github.com/zpalmtree/seine/blob/v0.2.36/docs/guides/autotuning.md)列出该版本的候选路径。

自动 CPU 调整保留矿池连接，不会重启 GPU 后端。内核切换发生在完整哈希之间，保留已分配的内存区域。手动在仪表盘按 `+` 或 `-` 则不同：它会重启挖矿后端、重新连接矿池，并关闭本次运行的 CPU 自动调整。可通过日志确认发生了哪种变化。

## 保存的调优结果如何复用？

默认线程缓存是 `--data-dir` 下的 `seine.cpu-autotune.json`，配套内核缓存是 `seine.cpu-autotune.json.kernels.json`。它们将学习结果与矿池连接设置分开保存。每次启动保持相同数据目录，程序才能找到这些文件。[更新指南](/zh-hans/blog/update-seine-miner/)解释了替换应用时如何保留目录。

复用取决于硬件和构建标识、放置方式、内存页设置等兼容性。当前资源上限仍会约束启动时的活跃数量。重要配置变化后不能命中缓存属于可能的正常情况，让程序重新收集合适的证据。不要复制其他矿机的缓存或手动修改测量值。认定重新搜索有问题之前，先阅读启动和调优日志。

## 什么时候应固定线程数？

明确需要可重复配置时可以固定数量。例如 `--threads 4` 请求四个 CPU 线程，通常关闭线程和内核自动调优。`--cpu-autotune-threads` 即使指定数量也会显式启用调优；`--disable-cpu-autotune-threads` 则禁用自动调整。[参数参考](https://github.com/zpalmtree/seine/blob/v0.2.36/docs/MINER_FLAGS.md)说明搜索边界及其相互作用。

日常挖矿从默认设置开始，给实际工作比较留出完成时间。结合 CPU 设备行、调优消息和接受的份额观察，在相似负载与内存条件下比较。矿池算力由到达的份额估计，所以用程序的 CPU 测量理解调优试验，用[矿池统计](https://bntpool.com/blog/zh-hans/track-your-miner-on-bntpool/)跟踪计入的挖矿活动。
