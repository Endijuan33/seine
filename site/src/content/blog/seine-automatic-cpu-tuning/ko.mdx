채굴 중 seine의 CPU 스레드 수가 바뀔 때 무슨 일이 일어나는지 알아보세요. 이 가이드는 공개 버전 v0.2.36을 기준으로 채굴 중 튜닝, 저장된 선택, 메모리 조정을 설명합니다. 설치는 [채굴 가이드](/ko/blog/how-to-mine-blocknet/), 각 패널의 의미는 [대시보드 안내](/ko/blog/seine-dashboard-explained/)를 참고하세요.

## CPU 자동 튜닝은 어떻게 작동하나요?

<Answer>
튜닝이 켜져 있으면 seine는 호환되는 저장 스레드 수나 하드웨어 기반 추정값으로 채굴을 시작하고 실제 채굴 작업으로 설정을 비교합니다. 기준 설정, 후보 설정, 다시 기준 설정을 측정합니다. 가용 RAM과 설정된 범위 안에서 해당 컴퓨터에 맞는 선택을 찾습니다.
</Answer>

## 탐색이 끝나기 전에 채굴이 시작됩니다

자동 스레드 튜닝을 쓰려면 `--threads`를 지정하지 마세요. 일반 채굴은 현재 자원 범위 안에서 초기 수를 선택하고 오프라인 스레드 수 탐색 없이 유효한 작업을 시작합니다. 호환 캐시가 있으면 시작점으로 쓸 수 있습니다. 새 컴퓨터는 추정값에서 시작해 이후 비교로 선택을 개선합니다.

각 시험은 경과 시간 동안 완료한 해시를 측정합니다. 새 메모리 아레나는 첫 해시를 마친 뒤 측정 구간에 들어갑니다. 기준–후보–기준 순서는 설정 효과와 환경 변화를 구분하는 데 도움이 됩니다. 큰 기준 변동, 메모리 한도 변경, 지속적인 작업 손실이 있으면 비교를 폐기할 수 있습니다. 대시보드의 짧은 급등은 긴 판단 과정의 관측 하나일 뿐입니다.

## 스레드를 늘려도 도움이 안 될 수 있는 이유는 무엇인가요?

활성 CPU 스레드마다 큰 메모리 아레나를 쓰며 메모리 대역폭을 공유합니다. 스레드가 늘면 동시 작업은 늘지만 결과는 시스템 전체에 달려 있습니다. 튜너는 최대 스레드 수가 가장 빠르다고 가정하지 않고 전체 CPU H/s를 비교합니다. [RAM 가이드](/ko/blog/how-much-ram-to-mine-blocknet/)에서 메모리 예산을 설명합니다.

기본 프로필은 `balanced`입니다. 프로필은 튜닝 정책과 실행 기본값을 제어하며, `efficiency`는 더 적은 스레드를 선호할 수 있는 명시적 선택입니다. 평가 중에는 같은 프로필을 유지하세요. 스레드 수, CPU 배치, 메모리 페이지 설정이 상호 작용하므로 다른 컴퓨터의 결과는 참고 자료이지 그대로 복사할 설정이 아닙니다.

## 다른 프로그램이 RAM을 필요로 하면 어떻게 되나요?

자동 메모리 예산은 가용 자원에 따라 변합니다. 메모리 압박이 생기면 CPU 스레드가 현재 해시를 마친 뒤 대기하고 아레나를 해제할 수 있습니다. 여유가 안정적으로 돌아오면 사용 가능한 슬롯을 활성화하고 탐색을 재개할 수 있습니다. 다른 앱도 실행하는 컴퓨터에서 같은 세션 중에 작동 수를 상황에 맞출 수 있습니다.

일시적인 감소가 전에 학습한 더 높은 수를 지울 필요는 없습니다. 캐시와 활성 수는 목적이 다릅니다. Linux에서 명시적 HugeTLB 아레나를 해제하면 예약된 huge page 풀로 돌아가며 seine는 운영체제 풀의 크기를 바꾸지 않습니다. 예약 변경은 [huge pages 가이드](/ko/blog/huge-pages-blocknet-mining/)를 참고하고 일반 여유 RAM과 구분하세요.

## CPU 커널도 튜닝하나요?

지원되는 CPU는 스레드 수뿐 아니라 지원되는 해시 계산 코드 경로도 비교할 수 있습니다. 여기서 커널은 해시 계산의 소프트웨어 구현입니다. 채굴기는 프로세서 명령 지원을 확인하고 반복 채굴 샘플로 적합한 경로를 비교합니다. 커널과 스레드 시험은 번갈아 진행되며 메모리 관리는 계속됩니다. 해당 버전의 후보는 [기술 가이드](https://github.com/zpalmtree/seine/blob/v0.2.36/docs/guides/autotuning.md)에 있습니다.

자동 CPU 변경은 풀 연결을 유지하고 GPU 백엔드를 재시작하지 않습니다. 커널은 완성된 해시 사이에서 바뀌며 할당된 아레나를 유지합니다. 반면 대시보드에서 `+` 또는 `-`를 수동으로 누르면 채굴 백엔드가 재시작되고 풀에 재연결되며 해당 실행의 CPU 자동 조정이 꺼집니다. 로그로 변경 종류를 확인하세요.

## 저장한 튜닝 결과는 어떻게 재사용하나요?

기본 스레드 캐시는 `--data-dir`의 `seine.cpu-autotune.json`, 보조 커널 캐시는 `seine.cpu-autotune.json.kernels.json`입니다. 학습 결과는 풀 연결 설정과 별도로 저장됩니다. 실행할 때 같은 데이터 디렉터리를 유지하세요. 앱을 교체할 때 이를 보존하는 방법은 [업데이트 가이드](/ko/blog/update-seine-miner/)에 있습니다.

재사용에는 하드웨어와 빌드 식별 정보, 배치, 페이지 설정 등의 호환성이 필요합니다. 현재 자원 한도는 시작 시 활성 수를 여전히 제한합니다. 중요한 설정 변경 후 캐시를 쓰지 못하는 것은 정상일 수 있습니다. 새 근거를 수집하게 두고 다른 장비의 캐시를 복사하거나 측정값을 직접 수정하지 마세요. 새 탐색을 문제로 판단하기 전에 시작 및 튜닝 로그를 읽으세요.

## 언제 스레드 수를 고정해야 하나요?

재현 가능한 구성이 의도적으로 필요할 때 고정 수를 사용하세요. 예를 들어 `--threads 4`는 CPU 스레드 4개를 요청하며 보통 스레드와 커널 자동 튜닝을 끕니다. `--cpu-autotune-threads`는 수가 지정되어도 튜닝을 명시적으로 켜고, `--disable-cpu-autotune-threads`는 자동 조정을 끕니다. 탐색 범위와 조합은 [플래그 참고 문서](https://github.com/zpalmtree/seine/blob/v0.2.36/docs/MINER_FLAGS.md)에 있습니다.

일상적인 채굴은 기본값으로 시작하고 비교가 끝날 시간을 주세요. CPU 행, 튜닝 메시지, 승인된 셰어를 함께 확인하고 비슷한 부하와 메모리 조건에서 비교하세요. 풀 해시레이트는 도착한 셰어로 추정합니다. 튜닝 시험에는 채굴기의 CPU 측정을, 인정된 활동에는 [풀 통계](https://bntpool.com/blog/ko/track-your-miner-on-bntpool/)를 사용하세요.
