了解 seine 在挖礦期間改變 CPU 執行緒數時做了什麼。本指南依據公開版本 v0.2.36，說明邊挖礦邊調校、儲存選擇及記憶體調整。安裝請從[挖礦指南](/zh-hant/blog/how-to-mine-blocknet/)開始，各面板意義見[儀表板導覽](/zh-hant/blog/seine-dashboard-explained/)。

## CPU 自動調校如何運作？

<Answer>
啟用調校後，seine 從相容的已儲存執行緒數或硬體估計值開始挖礦，再用實際挖礦工作比較設定。它先測基準設定，再試候選設定，然後再次測基準。可用 RAM 與設定範圍共同限制搜尋，逐步找出適合機器的選擇。
</Answer>

## 搜尋結束前，挖礦已經開始

不設定 `--threads` 即可使用自動執行緒調校。一般挖礦在目前資源預算內選擇初始數量，不必離線逐一測試執行緒數便開始有效工作。相容快取可以提供起點。新機器則從程式估計值開始，透過後續比較改善選擇。

每次試驗依經過時間統計已完成的雜湊。新的記憶體區域先完成第一個雜湊，再進入測量區間。基準—候選—基準的順序有助於區分設定效果與環境變化。基準大幅漂移、記憶體限制改變或持續失去工作，都可能使比較被捨棄。因此，儀表板的短暫尖峰只是較長決策過程中的一次觀察。

## 為什麼更多執行緒不一定有幫助？

每個作用中的 CPU 執行緒使用大型記憶體區域，並共享機器的記憶體頻寬。增加執行緒帶來更多平行工作，但成效取決於整個系統。調校器比較 CPU 總 H/s，而非假定數量最多就最快。[RAM 指南](/zh-hant/blog/how-much-ram-to-mine-blocknet/)說明記憶體預算。

預設設定檔為 `balanced`。設定檔控制調校策略與執行預設值；`efficiency` 是可能偏向較少執行緒的明確選項。評估期間請維持同一設定檔。執行緒數、CPU 配置位置與記憶體分頁類型會互相影響，因此其他機器或設定的結果只能參考，不宜直接照搬。

## 其他程式需要 RAM 時會怎樣？

自動記憶體預算隨可用資源改變。記憶體吃緊時，CPU 執行緒可以完成目前雜湊、暫停並釋放其區域。餘裕持續恢復後，程式可以啟用可用槽位並繼續探索。這讓同時執行其他應用程式的電腦，在同一工作階段內依環境調整運作數量。

暫時降低數量不一定要清除先前學到的較高數量。快取與目前作用中的數量用途不同。Linux 上釋放的明確 HugeTLB 區域會回到預留的大型分頁集區；seine 不會調整作業系統這個集區的大小。修改預留請看[大型分頁指南](/zh-hant/blog/huge-pages-blocknet-mining/)，並將它與一般可用 RAM 區分。

## seine 也會調校 CPU 計算核心嗎？

符合條件的 CPU 除了比較執行緒數，也能比較支援的雜湊程式碼路徑。此處的核心是雜湊計算的軟體實作。程式檢查處理器支援的指令，透過重複挖礦取樣比較可用路徑。核心與執行緒試驗輪流進行，記憶體管理持續運作。[技術調校指南](https://github.com/zpalmtree/seine/blob/v0.2.36/docs/guides/autotuning.md)列出該版本的候選路徑。

自動 CPU 調整保留礦池連線，不會重新啟動 GPU 後端。核心切換發生在完整雜湊之間，保留已配置的記憶體區域。手動在儀表板按 `+` 或 `-` 則會重新啟動挖礦後端、重新連接礦池，並停用這次執行的 CPU 自動調整。可透過紀錄確認變更類型。

## 已儲存的調校結果如何重用？

預設執行緒快取是 `--data-dir` 下的 `seine.cpu-autotune.json`，配套核心快取是 `seine.cpu-autotune.json.kernels.json`。它們將學習結果與礦池連線設定分開儲存。每次啟動維持相同資料目錄，程式才能找到檔案。[更新指南](/zh-hant/blog/update-seine-miner/)說明替換應用程式時如何保留目錄。

重用取決於硬體與建置識別、配置位置、分頁設定等相容性。目前資源上限仍會約束啟動時的作用中數量。重要設定改變後無法使用快取可能是正常情況，讓程式重新收集合適證據即可。不要複製別台礦機的快取或手動修改測量值。認定重新搜尋有問題前，先閱讀啟動與調校紀錄。

## 何時應固定執行緒數？

明確需要可重現的設定時可固定數量。例如 `--threads 4` 要求四個 CPU 執行緒，通常會停用執行緒與核心自動調校。`--cpu-autotune-threads` 即使已指定數量也會明確啟用調校；`--disable-cpu-autotune-threads` 則停用自動調整。[參數參考](https://github.com/zpalmtree/seine/blob/v0.2.36/docs/MINER_FLAGS.md)說明搜尋邊界及其相互作用。

日常挖礦從預設值開始，給實際工作比較足夠的完成時間。搭配 CPU 裝置列、調校訊息與已接受份額觀察，在相近負載及記憶體條件下比較。礦池雜湊率由抵達的份額估計，因此用程式的 CPU 測量理解調校試驗，用[礦池統計](https://bntpool.com/blog/zh-hant/track-your-miner-on-bntpool/)追蹤已計入的活動。
