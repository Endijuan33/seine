Цей посібник допоможе запустити seine на настільному комп’ютері чи сервері з Linux: від вибору архіву до перевірки прийнятих пулом шар. Як перевірений приклад використано офіційний випуск v0.2.26. Підготуйте адресу отримання Blocknet; де її знайти, пояснює [посібник із гаманця](/uk/blog/blocknet-wallet-for-mining/). Уводьте публічну адресу або зареєстроване `@name`, але ніколи не фразу відновлення гаманця.

## Як почати майнінг Blocknet на Linux?

<Answer>
Виберіть архів Linux для свого процесора, перевірте його контрольну суму SHA-256 і розпакуйте в папку, доступну для запису. Запустіть `./seine`, уведіть адресу виплат і прийміть стандартне підключення до bntpool.com. seine автоматично визначає кількість потоків CPU, а також може використовувати підтримувані карти NVIDIA на Linux x86_64, якщо встановлено потрібні бібліотеки середовища виконання.
</Answer>

## Крок 1: перевірте архітектуру та glibc

Відкрийте термінал і виконайте ці дві перевірки лише для читання. Перша визначає архітектуру машини; друга виводить версію бібліотеки GNU C у системі на основі glibc. Вони не запускають майнінг і не змінюють конфігурацію комп’ютера.

```sh
uname -m
getconf GNU_LIBC_VERSION
```

Зіставте архітектуру з архівом у таблиці нижче. Обидва пакети Linux версії v0.2.26 потребують glibc 2.39 або новішої. Установлюючи пізнішу версію, знову перевірте вимоги випуску. Якщо ваша система використовує іншу бібліотеку C або старішу glibc, скористайтеся сумісним середовищем дистрибутива або дотримуйтеся [інструкції зі збирання з вихідного коду](https://github.com/zpalmtree/seine/blob/master/docs/BUILDING.md).

| Вивід команди | Архів випуску | Бекенди |
|---|---|---|
| `x86_64` | `seine-linux-x86_64.tar.gz` | CPU та NVIDIA |
| `aarch64` | `seine-linux-aarch64.tar.gz` | CPU |

Кожному потоку майнінгу CPU потрібен блок пам’яті розміром 2 GiB. seine вибирає початкову кількість потоків відповідно до доступної пам’яті та ресурсів CPU, а потім налаштовує її під час майнінгу. Для першого запуску не задавайте перевизначення потоків і обчислювального ядра: спочатку можна встановити робоче підключення, а вже потім змінювати параметри продуктивності.

## Крок 2: завантажте та перевірте архів

Виберіть Linux або Linux ARM64 у [розділі завантаження](/uk/#download). На сторінці того самого [офіційного випуску](https://github.com/zpalmtree/seine/releases/latest) також завантажте окремий файл `SHA256SUMS.txt` зі списку файлів випуску. Зберігайте разом архів і файл контрольних сум тієї самої версії. У прикладах нижче використано x86_64; для ARM64 замініть у командах `seine-linux-x86_64.tar.gz` на `seine-linux-aarch64.tar.gz`.

<img src="/assets/blog/linux-download.png" alt="Офіційна таблиця завантажень з архівами Linux і Linux ARM64" width="1200" height="900" loading="lazy" />

У терміналі перейдіть до каталогу, у якому браузер зберіг файли, і обчисліть контрольну суму архіву. У цьому прикладі передбачається папка Downloads у домашньому каталозі; якщо ваша папка завантажень має іншу назву, використовуйте її фактичну назву.

```sh
cd "$HOME/Downloads"
sha256sum seine-linux-x86_64.tar.gz
```

Порівняйте повний шістнадцятковий хеш із рядком саме цього архіву в завантаженому `SHA256SUMS.txt`. Перш ніж розпаковувати або запускати файл, переконайтеся, що всі цифри збігаються. Для цього порівняння використовуйте файл контрольних сум, опублікований окремо з випуском: архів також містить маніфест для розпакованих файлів. Збіг контрольної суми підтверджує відповідність опублікованому значенню; обидва файли завантажуйте з офіційного джерела.

## Крок 3: розпакуйте та перевірте виконуваний файл

Створіть окрему папку в домашньому каталозі, розпакуйте в неї архів і попросіть програму вивести довідку. Архів v0.2.26 містить `./seine` у корені, тому ці команди розміщують виконуваний файл безпосередньо в новій папці. Команда довідки завершується без запуску сеансу майнінгу.

```sh
mkdir -p "$HOME/seine"
tar -xzf seine-linux-x86_64.tar.gz -C "$HOME/seine"
cd "$HOME/seine"
chmod u+x ./seine
./seine --help
```

Виконуйте ці кроки від свого облікового запису. `chmod u+x` надає власнику файлу право виконання; встановлення для всієї системи не потрібне. Префікс `./` указує оболонці запускати файл із поточного каталогу. Зберігайте розпаковану документацію та файли ліцензій разом із програмою.

## Крок 4: уведіть адресу та підключіться

Запустіть програму з папки з розпакованими файлами:

```sh
./seine
```

Уведіть адресу отримання або зареєстроване `@name`, прийміть `stratum+tcp://bntpool.com:3333` і виберіть упізнавану назву установки, коли з’явиться запит. Під час наступних запусків seine використовує `seine-data/seine.config.json` відносно робочого каталогу. Запускаючи програму з тієї самої папки, ви зможете легко знайти ці налаштування. Запити програми та каталог даних описано в [довіднику конфігурації](https://github.com/zpalmtree/seine/blob/v0.2.26/docs/guides/configuration.md).

Стежте за хешрейтом майнера та лічильником прийнятих шар. Потім відкрийте [My Stats](https://bntpool.com/stats) і знайдіть ту саму адресу отримання. Прийняті шари підтверджують, що пул отримує роботу; виплата відбувається в межах окремого процесу нарахування та переказу винагород. Панелі майнера пояснює [посібник з інтерфейсу](/uk/blog/seine-dashboard-explained/). Для коректної зупинки натисніть `q` або `Ctrl+C`.

## Що потрібно для майнінгу на NVIDIA в Linux?

Для майнінгу на GPU в Linux x86_64 потрібні драйвер NVIDIA та сумісні бібліотеки середовища виконання NVRTC. NVRTC компілює обчислювальні ядра GPU під час запуску. Установіть середовище виконання та відповідну бібліотеку builtins із пакетів вашого дистрибутива або NVIDIA, дотримуючись [посібника з налаштування NVIDIA](/uk/blog/mine-blocknet-nvidia-gpu/). Назви пакетів залежать від дистрибутива та версії CUDA, тому використовуйте інструкції для своєї системи.

За наявності цих бібліотек стандартний режим дозволяє одночасно майнити на CPU та підтримуваних картах NVIDIA. Щоб налаштувати майнінг на CPU, поки готуєте середовище GPU, виберіть його явно:

```sh
./seine --backend cpu
```

Це вибір лише CPU для цього запуску. Щодо вибору пристроїв GPU і прийнятих GPU-шар продовжуйте читати посібник NVIDIA. Описаний тут випуск ARM64 містить бекенд CPU; встановлення CUDA не додає бекенд NVIDIA до цього архіву.

## Як усунути помилку запуску в Linux?

Вибирайте наступну перевірку за першим повідомленням про помилку. Помилка архітектури або середовища виконання виникає до прийняття шар, тому зміна адрес пула чи кількості потоків не виправить цей етап. Збережіть перевірений архів, поки перевіряєте виконуваний файл і середовище.

| Повідомлення або симптом | Що перевірити |
|---|---|
| `Exec format error` | Неправильна архітектура: порівняйте `uname -m` з іменем файлу архіву. |
| `GLIBC_2.39 not found` | Програмі потрібна новіша glibc. Використовуйте сумісну систему або збирайте з вихідного коду; залиште керування системною бібліотекою C своєму дистрибутиву. |
| `Permission denied` | Перевірте право користувача на виконання та використовуйте папку на файловій системі, що дозволяє виконання програм. |
| `libnvrtc` / `libnvrtc-builtins` | Установіть сумісне середовище виконання NVIDIA і відповідну бібліотеку builtins або використовуйте `--backend cpu`, поки готуєте їх. |

Коли шари почнуть прийматися, [посібник із huge pages](/uk/blog/huge-pages-blocknet-mining/) допоможе з необов’язковим налаштуванням сторінок пам’яті Linux. [Посібник із серверів](/uk/blog/mine-blocknet-on-servers/) описує роботу без монітора та розміщення NUMA. Жодна з цих підготовчих процедур не обов’язкова для першого запуску за цією інструкцією; вносьте зміни окремо, щоб розуміти, що саме змінилося на вашій машині.
