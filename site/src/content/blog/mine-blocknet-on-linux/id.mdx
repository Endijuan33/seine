Panduan ini menjalankan seine di desktop atau server Linux, mulai dari memilih arsip hingga memeriksa share yang diterima pool. Rilis resmi v0.2.26 menjadi contoh yang sudah diverifikasi. Siapkan alamat penerimaan Blocknet; [panduan dompet](/id/blog/blocknet-wallet-for-mining/) menjelaskan tempat menemukannya. Masukkan alamat publik atau `@name` terdaftar, jangan pernah frasa pemulihan dompet.

## Bagaimana memulai penambangan Blocknet di Linux?

<Answer>
Pilih arsip Linux sesuai prosesor, verifikasi checksum SHA-256, lalu ekstrak ke folder yang dapat ditulis. Jalankan `./seine`, masukkan alamat pembayaran, dan terima koneksi bawaan bntpool.com. seine menentukan thread CPU secara otomatis dan juga dapat memakai kartu NVIDIA yang didukung di Linux x86_64 jika pustaka runtime-nya sudah terpasang.
</Answer>

## Langkah 1: periksa arsitektur dan glibc

Buka terminal dan jalankan dua pemeriksaan baca-saja ini. Yang pertama mengenali arsitektur mesin; yang kedua menampilkan versi pustaka GNU C pada sistem berbasis glibc. Keduanya tidak memulai penambangan atau mengubah konfigurasi komputer.

```sh
uname -m
getconf GNU_LIBC_VERSION
```

Cocokkan arsitektur dengan arsip di bawah. Kedua paket Linux v0.2.26 memerlukan glibc 2.39 atau lebih baru. Periksa lagi persyaratan rilis saat memasang versi berikutnya. Jika sistem menggunakan pustaka C lain atau glibc lebih lama, gunakan lingkungan distribusi yang kompatibel atau ikuti [petunjuk kompilasi dari sumber](https://github.com/zpalmtree/seine/blob/master/docs/BUILDING.md).

| Keluaran perintah | Arsip rilis | Backend |
|---|---|---|
| `x86_64` | `seine-linux-x86_64.tar.gz` | CPU dan NVIDIA |
| `aarch64` | `seine-linux-aarch64.tar.gz` | CPU |

Setiap thread penambangan CPU membutuhkan blok memori 2 GiB. seine memilih jumlah thread awal berdasarkan memori dan sumber daya CPU yang tersedia, kemudian menyesuaikannya selama menambang. Jangan tetapkan penggantian thread dan kernel saat pertama mulai; buat koneksi berfungsi dahulu sebelum mengubah pengaturan performa.

## Langkah 2: unduh dan verifikasi arsip

Pilih Linux atau Linux ARM64 di [bagian unduhan](/id/#download). Dari [rilis resmi](https://github.com/zpalmtree/seine/releases/latest) yang sama, unduh juga aset terpisah `SHA256SUMS.txt`. Simpan arsip dan checksum dari versi yang sama bersama-sama. Contoh menggunakan x86_64; di ARM64, ganti `seine-linux-x86_64.tar.gz` dengan `seine-linux-aarch64.tar.gz` dalam perintah.

<img src="/assets/blog/linux-download.png" alt="Tabel unduhan resmi dengan arsip Linux dan Linux ARM64" width="1200" height="900" loading="lazy" />

Di terminal, buka direktori tempat peramban menyimpan berkas dan hitung checksum arsip. Contoh ini mengasumsikan folder Downloads di direktori pengguna; gunakan direktori unduhan sebenarnya jika namanya berbeda.

```sh
cd "$HOME/Downloads"
sha256sum seine-linux-x86_64.tar.gz
```

Bandingkan hash heksadesimal lengkap dengan baris untuk arsip tersebut dalam `SHA256SUMS.txt` yang diunduh. Semua digit harus cocok sebelum diekstrak atau dijalankan. Gunakan berkas checksum yang disediakan terpisah pada rilis: arsip juga memuat manifes untuk berkas hasil ekstraksi. Checksum yang cocok memverifikasi berkas terhadap nilai terbitan; dapatkan kedua unduhan dari sumber resmi.

## Langkah 3: ekstrak dan periksa program

Buat folder khusus di direktori pengguna, ekstrak arsip ke sana, lalu minta biner menampilkan bantuan. Arsip v0.2.26 berisi `./seine` di tingkat teratas, sehingga perintah ini menaruh program langsung di folder baru. Perintah bantuan keluar tanpa memulai sesi penambangan.

```sh
mkdir -p "$HOME/seine"
tar -xzf seine-linux-x86_64.tar.gz -C "$HOME/seine"
cd "$HOME/seine"
chmod u+x ./seine
./seine --help
```

Jalankan langkah ini dengan akun Anda sendiri. `chmod u+x` memberi izin eksekusi kepada pemilik berkas; instalasi seluruh sistem tidak diperlukan. Awalan `./` memberi tahu shell untuk menjalankan berkas di direktori saat ini. Simpan dokumentasi dan lisensi hasil ekstraksi bersama biner.

## Langkah 4: masukkan alamat dan hubungkan

Mulai dari folder hasil ekstraksi:

```sh
./seine
```

Masukkan alamat penerimaan atau `@name` terdaftar, terima `stratum+tcp://bntpool.com:3333`, dan pilih nama rig yang mudah dikenali saat diminta. Saat mulai berikutnya, seine memakai kembali `seine-data/seine.config.json` relatif terhadap direktori kerja. Memulai dari folder yang sama membuat pengaturan mudah ditemukan. [Referensi konfigurasi](https://github.com/zpalmtree/seine/blob/v0.2.26/docs/guides/configuration.md) menjelaskan pertanyaan dan direktori data.

Amati hashrate dan penghitung share diterima pada penambang. Kemudian buka [My Stats](https://bntpool.com/stats) dan cari alamat penerimaan yang sama. Share diterima memastikan pool menerima pekerjaan; pembayaran mengikuti proses imbalan dan pembayaran tersendiri. [Panduan dasbor](/id/blog/seine-dashboard-explained/) menjelaskan panel penambang. Tekan `q` atau `Ctrl+C` untuk berhenti dengan benar.

## Apa yang dibutuhkan untuk menambang dengan NVIDIA di Linux?

Penambangan GPU di Linux x86_64 memerlukan driver NVIDIA dan pustaka runtime NVRTC yang kompatibel. NVRTC mengompilasi kernel GPU saat startup. Instal runtime dan pustaka builtins yang cocok melalui distribusi atau paket NVIDIA sesuai [panduan NVIDIA](/id/blog/mine-blocknet-nvidia-gpu/). Nama paket bergantung pada distribusi dan versi CUDA; ikuti petunjuk untuk sistem Anda.

Dengan pustaka tersebut, mode bawaan bisa menambang dengan CPU dan kartu NVIDIA yang didukung secara bersamaan. Untuk mulai menambang dengan CPU sambil menyiapkan runtime GPU, pilih secara eksplisit:

```sh
./seine --backend cpu
```

Pilihan ini hanya memakai CPU untuk pemanggilan tersebut. Untuk memilih perangkat GPU dan memeriksa share GPU diterima, lanjutkan ke panduan NVIDIA. Rilis ARM64 yang dibahas memuat backend CPU; memasang CUDA tidak menambahkan backend NVIDIA ke arsip itu.

## Bagaimana mengatasi kesalahan startup Linux?

Gunakan pesan kesalahan pertama untuk memilih pemeriksaan berikutnya. Kesalahan arsitektur atau runtime terjadi sebelum share diterima, sehingga mengganti alamat pool atau jumlah thread tidak menyelesaikan tahap itu. Simpan arsip terverifikasi selama memeriksa program dan lingkungannya.

| Pesan atau gejala | Yang perlu diperiksa |
|---|---|
| `Exec format error` | Arsitektur salah: bandingkan `uname -m` dengan nama arsip. |
| `GLIBC_2.39 not found` | Biner memerlukan glibc lebih baru. Gunakan sistem yang kompatibel atau kompilasi dari sumber; biarkan distribusi mengelola pustaka C sistem. |
| `Permission denied` | Periksa izin eksekusi pengguna dan gunakan folder pada sistem berkas yang mengizinkan eksekusi. |
| `libnvrtc` / `libnvrtc-builtins` | Instal runtime NVIDIA kompatibel dan pustaka builtins yang cocok, atau gunakan `--backend cpu` sambil menyiapkannya. |

Setelah share diterima, [panduan huge pages](/id/blog/huge-pages-blocknet-mining/) membahas pengaturan halaman opsional di Linux. [Panduan server](/id/blog/mine-blocknet-on-servers/) mencakup operasi tanpa antarmuka grafis dan penempatan NUMA. Keduanya tidak diperlukan untuk mengikuti langkah awal ini; lakukan setiap perubahan secara terpisah agar efeknya pada mesin dapat diketahui.
