Questa guida avvia seine su un desktop o server Linux, dalla scelta dell’archivio al controllo delle share accettate dal pool. Usa la versione ufficiale v0.2.26 come esempio verificato. Tieni pronto il tuo indirizzo di ricezione Blocknet; la [guida al wallet](/it/blog/blocknet-wallet-for-mining/) spiega dove trovarlo. Inserisci un indirizzo pubblico o un `@name` registrato, mai una frase di recupero.

## Come si inizia a minare Blocknet su Linux?

<Answer>
Scegli l’archivio Linux adatto al processore, verificane il checksum SHA-256 ed estrailo in una cartella scrivibile. Esegui `./seine`, inserisci l’indirizzo di pagamento e accetta la connessione predefinita a bntpool.com. seine dimensiona automaticamente i thread CPU e può usare anche schede NVIDIA supportate su Linux x86_64, quando le relative librerie runtime sono installate.
</Answer>

## Passaggio 1: controlla architettura e glibc

Apri un terminale ed esegui questi due controlli in sola lettura. Il primo identifica l’architettura; il secondo mostra la versione della libreria GNU C su un sistema basato su glibc. Non avviano il mining e non modificano la configurazione del computer.

```sh
uname -m
getconf GNU_LIBC_VERSION
```

Abbina l’architettura all’archivio seguente. Entrambi i pacchetti Linux v0.2.26 richiedono glibc 2.39 o successiva. Ricontrolla i requisiti quando installi versioni più recenti. Se il sistema usa un’altra libreria C o una glibc precedente, usa un ambiente di distribuzione compatibile oppure segui le [istruzioni di compilazione dai sorgenti](https://github.com/zpalmtree/seine/blob/master/docs/BUILDING.md).

| Output del comando | Archivio della versione | Backend |
|---|---|---|
| `x86_64` | `seine-linux-x86_64.tar.gz` | CPU e NVIDIA |
| `aarch64` | `seine-linux-aarch64.tar.gz` | CPU |

Ogni thread di mining CPU richiede un blocco di memoria da 2 GiB. seine sceglie il numero iniziale di thread in base alla memoria e alle risorse CPU disponibili, poi lo ottimizza durante il mining. Al primo avvio non forzare thread e kernel: stabilisci una connessione funzionante prima di modificare le prestazioni.

## Passaggio 2: scarica e verifica l’archivio

Scegli Linux o Linux ARM64 nella [sezione download](/it/#download). Dalla stessa [versione ufficiale](https://github.com/zpalmtree/seine/releases/latest), scarica anche il file separato `SHA256SUMS.txt`. Conserva insieme archivio e checksum della stessa versione. Gli esempi usano x86_64; su ARM64 sostituisci `seine-linux-x86_64.tar.gz` con `seine-linux-aarch64.tar.gz` nei comandi.

<img src="/assets/blog/linux-download.png" alt="Tabella ufficiale dei download con archivi Linux e Linux ARM64" width="1200" height="900" loading="lazy" />

Nel terminale apri la cartella in cui il browser ha salvato i file e calcola il checksum dell’archivio. L’esempio presuppone una cartella Downloads nella directory personale; usa la cartella effettiva se ha un altro nome.

```sh
cd "$HOME/Downloads"
sha256sum seine-linux-x86_64.tar.gz
```

Confronta l’intero hash esadecimale con la riga di quell’esatto archivio in `SHA256SUMS.txt`. Ogni cifra deve coincidere prima di estrarre o eseguire. Usa il file dei checksum pubblicato con la versione: l’archivio contiene anche un manifesto dei file estratti. Un checksum coincidente verifica il file rispetto al valore pubblicato; scarica entrambi dalla fonte ufficiale.

## Passaggio 3: estrai e controlla l’eseguibile

Crea una cartella dedicata nella directory personale, estrai l’archivio al suo interno e chiedi al binario di mostrare la guida. L’archivio v0.2.26 contiene `./seine` nella radice, quindi questi comandi collocano l’eseguibile direttamente nella nuova cartella. Il comando di aiuto termina senza avviare il mining.

```sh
mkdir -p "$HOME/seine"
tar -xzf seine-linux-x86_64.tar.gz -C "$HOME/seine"
cd "$HOME/seine"
chmod u+x ./seine
./seine --help
```

Esegui i passaggi con il tuo account. `chmod u+x` concede l’esecuzione al proprietario del file; non serve un’installazione globale. Il prefisso `./` indica alla shell di eseguire il file nella cartella corrente. Conserva documentazione e licenze estratte insieme al binario.

## Passaggio 4: inserisci l’indirizzo e connettiti

Avvia dalla cartella di estrazione:

```sh
./seine
```

Inserisci l’indirizzo di ricezione o il tuo `@name` registrato, accetta `stratum+tcp://bntpool.com:3333` e scegli un nome riconoscibile per la macchina quando richiesto. Agli avvii successivi seine riutilizza `seine-data/seine.config.json`, relativo alla directory di lavoro. Avviare dalla stessa cartella rende facile ritrovare le impostazioni. Il [riferimento di configurazione](https://github.com/zpalmtree/seine/blob/v0.2.26/docs/guides/configuration.md) documenta le domande e la directory dati.

Osserva hashrate e contatore delle share accettate. Apri quindi [My Stats](https://bntpool.com/stats) e cerca lo stesso indirizzo. Le share accettate confermano che il pool riceve lavoro; il pagamento segue il processo separato di ricompense e pagamenti. La [guida alla dashboard](/it/blog/seine-dashboard-explained/) spiega i pannelli del miner. Premi `q` o `Ctrl+C` per arrestarlo correttamente.

## Cosa serve per minare con NVIDIA su Linux?

Il mining GPU su Linux x86_64 richiede un driver NVIDIA e librerie runtime NVRTC compatibili. NVRTC compila i kernel GPU all’avvio. Installa il runtime e la relativa libreria builtins tramite la distribuzione o i pacchetti NVIDIA, seguendo la [guida NVIDIA](/it/blog/mine-blocknet-nvidia-gpu/). I nomi dei pacchetti dipendono da distribuzione e versione CUDA: segui le istruzioni per il tuo sistema.

Con queste librerie, la modalità predefinita può minare contemporaneamente con CPU e schede NVIDIA supportate. Per avviare il mining CPU mentre prepari il runtime GPU, selezionalo esplicitamente:

```sh
./seine --backend cpu
```

Questa scelta usa solo la CPU per quell’esecuzione. Per selezionare i dispositivi GPU e controllarne le share accettate, continua con la guida NVIDIA. La versione ARM64 qui descritta contiene il backend CPU; installare CUDA non aggiunge un backend NVIDIA a quell’archivio.

## Come risolvere un errore di avvio su Linux?

Usa il primo messaggio di errore per scegliere il controllo successivo. Un errore di architettura o runtime avviene prima delle share accettate: cambiare indirizzo del pool o numero di thread non risolve quella fase. Conserva l’archivio verificato mentre controlli eseguibile e ambiente.

| Messaggio o sintomo | Cosa controllare |
|---|---|
| `Exec format error` | Architettura errata: confronta `uname -m` con il nome dell’archivio. |
| `GLIBC_2.39 not found` | Il binario richiede una glibc più recente. Usa un sistema compatibile o compila dai sorgenti; lascia la gestione della libreria C di sistema alla distribuzione. |
| `Permission denied` | Controlla i permessi di esecuzione dell’utente e usa una cartella su un filesystem che consenta l’esecuzione. |
| `libnvrtc` / `libnvrtc-builtins` | Installa il runtime NVIDIA compatibile e la libreria builtins corrispondente, oppure usa `--backend cpu` mentre lo prepari. |

Quando le share vengono accettate, la [guida alle huge pages](/it/blog/huge-pages-blocknet-mining/) descrive la configurazione facoltativa su Linux. La [guida ai server](/it/blog/mine-blocknet-on-servers/) tratta il funzionamento senza interfaccia grafica e il posizionamento NUMA. Nessuna delle due preparazioni serve per questo primo avvio; separa le modifiche per identificarne gli effetti sulla macchina.
