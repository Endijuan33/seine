Esta guía te ayuda a iniciar seine en un escritorio o servidor Linux, desde elegir el archivo hasta comprobar los shares aceptados por el pool. Usa la versión oficial v0.2.26 como ejemplo verificado. Ten preparada tu dirección de recepción de Blocknet; la [guía de la billetera](/es/blog/blocknet-wallet-for-mining/) explica dónde encontrarla. Introduce una dirección pública o un `@name` registrado, nunca una frase de recuperación.

## ¿Cómo se empieza a minar Blocknet en Linux?

<Answer>
Elige el archivo Linux correspondiente a tu procesador, verifica su suma SHA-256 y extráelo en una carpeta con permiso de escritura. Ejecuta `./seine`, introduce tu dirección de pago y acepta la conexión predeterminada a bntpool.com. seine ajusta automáticamente los hilos de CPU y también puede usar tarjetas NVIDIA compatibles en Linux x86_64 si están instaladas sus bibliotecas de ejecución.
</Answer>

## Paso 1: comprueba la arquitectura y glibc

Abre una terminal y ejecuta estas dos comprobaciones de solo lectura. La primera identifica la arquitectura; la segunda muestra la versión de la biblioteca GNU C en un sistema basado en glibc. No inician la minería ni cambian la configuración del equipo.

```sh
uname -m
getconf GNU_LIBC_VERSION
```

Relaciona la arquitectura con el archivo de la tabla. Ambos paquetes Linux v0.2.26 requieren glibc 2.39 o posterior. Vuelve a comprobar los requisitos al instalar una versión más reciente. Si tu sistema utiliza otra biblioteca C o una glibc anterior, usa un entorno de distribución compatible o sigue las [instrucciones para compilar desde el código fuente](https://github.com/zpalmtree/seine/blob/master/docs/BUILDING.md).

| Salida del comando | Archivo de la versión | Backends |
|---|---|---|
| `x86_64` | `seine-linux-x86_64.tar.gz` | CPU y NVIDIA |
| `aarch64` | `seine-linux-aarch64.tar.gz` | CPU |

Cada hilo de minería de CPU necesita un bloque de memoria de 2 GiB. seine elige un número inicial de hilos según la memoria y los recursos de CPU disponibles y después ajusta mientras mina. Deja sin definir los ajustes manuales de hilos y kernels en el primer inicio; establece primero una conexión funcional.

## Paso 2: descarga y verifica el archivo

Elige Linux o Linux ARM64 en la [sección de descargas](/es/#download). Descarga también el recurso `SHA256SUMS.txt` de esa misma [versión oficial](https://github.com/zpalmtree/seine/releases/latest). Conserva juntos el archivo y la suma de la misma versión. Los ejemplos usan x86_64; en ARM64, sustituye `seine-linux-x86_64.tar.gz` por `seine-linux-aarch64.tar.gz` en los comandos.

<img src="/assets/blog/linux-download.png" alt="Tabla oficial de descargas con archivos para Linux y Linux ARM64" width="1200" height="900" loading="lazy" />

En la terminal, abre la carpeta donde el navegador guardó los archivos y calcula la suma del archivo. El ejemplo supone una carpeta Downloads dentro de tu directorio personal; utiliza la ubicación real si tiene otro nombre.

```sh
cd "$HOME/Downloads"
sha256sum seine-linux-x86_64.tar.gz
```

Compara el hash hexadecimal completo con la línea de ese archivo exacto en `SHA256SUMS.txt`. Todos los dígitos deben coincidir antes de extraerlo o ejecutarlo. Usa el archivo de sumas publicado con la versión: el archivo comprimido también contiene un manifiesto de los archivos extraídos. La coincidencia verifica el archivo frente al valor publicado; descarga ambos desde la fuente oficial.

## Paso 3: extrae y comprueba el ejecutable

Crea una carpeta dedicada en tu directorio personal, extrae allí el archivo y pide al binario que muestre su ayuda. El archivo v0.2.26 contiene `./seine` en la raíz, por lo que estos comandos colocan el ejecutable directamente en la carpeta nueva. El comando de ayuda termina sin iniciar la minería.

```sh
mkdir -p "$HOME/seine"
tar -xzf seine-linux-x86_64.tar.gz -C "$HOME/seine"
cd "$HOME/seine"
chmod u+x ./seine
./seine --help
```

Realiza estos pasos con tu propia cuenta. `chmod u+x` concede permiso de ejecución al propietario del archivo; no hace falta una instalación global. El prefijo `./` indica al shell que ejecute el archivo de la carpeta actual. Conserva la documentación y las licencias extraídas junto al binario.

## Paso 4: introduce tu dirección y conecta

Inicia desde la carpeta donde extrajiste el archivo:

```sh
./seine
```

Introduce tu dirección de recepción o `@name` registrado, acepta `stratum+tcp://bntpool.com:3333` y elige un nombre reconocible para el equipo cuando se solicite. En los siguientes inicios, seine reutiliza `seine-data/seine.config.json`, relativo al directorio de trabajo. Iniciar desde la misma carpeta facilita encontrar esos ajustes. La [referencia de configuración](https://github.com/zpalmtree/seine/blob/v0.2.26/docs/guides/configuration.md) documenta las preguntas y el directorio de datos.

Observa la tasa de hash y el contador de shares aceptados. Después abre [My Stats](https://bntpool.com/stats) y busca la misma dirección. Los shares aceptados confirman que el pool recibe trabajo; el pago sigue un proceso separado de recompensas y pagos. La [guía del panel](/es/blog/seine-dashboard-explained/) explica sus secciones. Pulsa `q` o `Ctrl+C` para detenerlo correctamente.

## ¿Qué necesitas para minar con NVIDIA en Linux?

La minería GPU en Linux x86_64 necesita un controlador NVIDIA y bibliotecas NVRTC compatibles. NVRTC compila los kernels GPU al iniciar. Instala el entorno y su biblioteca builtins correspondiente mediante tu distribución o los paquetes NVIDIA, siguiendo la [guía de NVIDIA](/es/blog/mine-blocknet-nvidia-gpu/). Los nombres de los paquetes dependen de la distribución y de la versión de CUDA; sigue las instrucciones para tu sistema.

Con esas bibliotecas disponibles, el modo predeterminado puede minar simultáneamente con CPU y tarjetas NVIDIA compatibles. Para empezar con CPU mientras preparas la GPU, selecciónala expresamente:

```sh
./seine --backend cpu
```

Esta opción usa solo CPU en esa ejecución. Para seleccionar dispositivos GPU y comprobar sus shares aceptados, continúa con la guía NVIDIA. La versión ARM64 descrita aquí contiene el backend CPU; instalar CUDA no añade un backend NVIDIA a ese archivo.

## ¿Cómo se resuelve un error de inicio en Linux?

Usa el primer mensaje de error para elegir la siguiente comprobación. Un error de arquitectura o bibliotecas ocurre antes de enviar shares aceptados; cambiar direcciones del pool o hilos no lo soluciona. Conserva el archivo verificado mientras revisas el ejecutable y el entorno.

| Mensaje o síntoma | Qué comprobar |
|---|---|
| `Exec format error` | Arquitectura incorrecta: compara `uname -m` con el nombre del archivo. |
| `GLIBC_2.39 not found` | El binario requiere una glibc más reciente. Usa un sistema compatible o compila desde el código fuente; deja que tu distribución gestione la biblioteca C del sistema. |
| `Permission denied` | Comprueba el permiso de ejecución del usuario y usa una carpeta en un sistema de archivos que permita ejecutar. |
| `libnvrtc` / `libnvrtc-builtins` | Instala el entorno NVIDIA compatible y su biblioteca builtins correspondiente, o usa `--backend cpu` mientras lo preparas. |

Cuando se acepten shares, la [guía de páginas grandes](/es/blog/huge-pages-blocknet-mining/) explica esa configuración opcional en Linux. La [guía de servidores](/es/blog/mine-blocknet-on-servers/) cubre el funcionamiento sin interfaz gráfica y la ubicación NUMA. Ninguna preparación es necesaria para este primer inicio; separa cada cambio para identificar su efecto en el equipo.
