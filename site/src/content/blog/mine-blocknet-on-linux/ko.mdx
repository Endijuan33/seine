이 가이드는 Linux 데스크톱이나 서버에서 seine를 실행하는 과정을 압축 파일 선택부터 풀에서 수락한 셰어 확인까지 설명합니다. 검증한 예시로 공식 v0.2.26 릴리스를 사용합니다. Blocknet 수신 주소를 준비하세요. 주소를 찾는 방법은 [지갑 가이드](/ko/blog/blocknet-wallet-for-mining/)에서 설명합니다. 공개 주소 또는 등록된 `@name`을 입력하며, 지갑 복구 문구는 절대 입력하지 않습니다.

## Linux에서 Blocknet 채굴을 시작하려면 어떻게 하나요?

<Answer>
프로세서에 맞는 Linux 압축 파일을 선택하고 SHA-256 체크섬을 검증한 뒤 쓰기 가능한 폴더에 압축을 풉니다. `./seine`를 실행하고 지급 주소를 입력한 다음 기본 bntpool.com 연결을 선택합니다. seine는 CPU 스레드 수를 자동으로 정하며, 런타임 라이브러리가 설치되어 있으면 Linux x86_64에서 지원되는 NVIDIA 카드도 사용할 수 있습니다.
</Answer>

## 1단계: 아키텍처와 glibc 확인

터미널을 열고 다음 두 가지 읽기 전용 확인 명령을 실행하세요. 첫 번째는 시스템 아키텍처를 식별하고, 두 번째는 glibc 기반 시스템에서 GNU C 라이브러리 버전을 출력합니다. 이 명령은 채굴을 시작하거나 컴퓨터 설정을 변경하지 않습니다.

```sh
uname -m
getconf GNU_LIBC_VERSION
```

아래 표에서 아키텍처에 맞는 압축 파일을 찾으세요. v0.2.26의 두 Linux 패키지 모두 glibc 2.39 이상이 필요합니다. 이후 버전을 설치할 때는 릴리스 요구 사항을 다시 확인하세요. 다른 C 라이브러리나 더 오래된 glibc를 사용하는 시스템이라면 호환되는 배포판 환경을 사용하거나 [소스 빌드 안내](https://github.com/zpalmtree/seine/blob/master/docs/BUILDING.md)를 따르세요.

| 명령 출력 | 릴리스 압축 파일 | 백엔드 |
|---|---|---|
| `x86_64` | `seine-linux-x86_64.tar.gz` | CPU 및 NVIDIA |
| `aarch64` | `seine-linux-aarch64.tar.gz` | CPU |

CPU 채굴 스레드마다 2 GiB 메모리 블록이 필요합니다. seine는 사용 가능한 메모리와 CPU 자원에 따라 초기 스레드 수를 선택한 뒤 채굴 중에 조정합니다. 처음 실행할 때는 스레드 및 커널 재정의 값을 지정하지 마세요. 성능 설정을 바꾸기 전에 정상적인 연결부터 확인할 수 있습니다.

## 2단계: 압축 파일 다운로드 및 검증

[다운로드 영역](/ko/#download)에서 Linux 또는 Linux ARM64를 선택하세요. 같은 [공식 릴리스](https://github.com/zpalmtree/seine/releases/latest)에서 릴리스 첨부 파일인 `SHA256SUMS.txt`도 다운로드합니다. 같은 버전의 압축 파일과 체크섬 파일을 함께 보관하세요. 아래 예시는 x86_64를 사용합니다. ARM64에서는 명령의 `seine-linux-x86_64.tar.gz`를 `seine-linux-aarch64.tar.gz`로 바꾸세요.

<img src="/assets/blog/linux-download.png" alt="Linux 및 Linux ARM64 압축 파일이 표시된 공식 다운로드 표" width="1200" height="900" loading="lazy" />

터미널에서 브라우저가 파일을 저장한 디렉터리로 이동한 뒤 압축 파일의 체크섬을 계산하세요. 이 예시는 홈 디렉터리 아래 Downloads 폴더를 가정합니다. 다른 이름을 사용하는 경우 실제 다운로드 디렉터리를 지정하세요.

```sh
cd "$HOME/Downloads"
sha256sum seine-linux-x86_64.tar.gz
```

전체 16진수 해시를 다운로드한 `SHA256SUMS.txt`에서 해당 압축 파일의 줄과 비교하세요. 압축을 풀거나 실행하기 전에 모든 자릿수가 일치해야 합니다. 이 비교에는 릴리스에 별도로 첨부된 체크섬 파일을 사용하세요. 압축 파일 내부에도 압축 해제된 파일용 매니페스트가 들어 있기 때문입니다. 체크섬 일치는 파일이 공개된 값과 같음을 확인합니다. 두 파일 모두 공식 출처에서 받으세요.

## 3단계: 압축 해제 및 실행 파일 확인

홈 디렉터리 안에 전용 폴더를 만들고 압축을 푼 다음 바이너리의 도움말을 출력하세요. v0.2.26 압축 파일은 루트에 `./seine`를 포함하므로, 다음 명령은 실행 파일을 새 폴더 바로 아래에 둡니다. 도움말 명령은 채굴 세션을 시작하지 않고 종료됩니다.

```sh
mkdir -p "$HOME/seine"
tar -xzf seine-linux-x86_64.tar.gz -C "$HOME/seine"
cd "$HOME/seine"
chmod u+x ./seine
./seine --help
```

본인 계정으로 이 단계를 수행하세요. `chmod u+x`는 파일 소유자에게 실행 권한을 부여하며, 시스템 전체에 설치할 필요가 없습니다. `./` 접두사는 현재 디렉터리의 파일을 실행하도록 셸에 지시합니다. 압축 해제된 문서와 라이선스 파일은 바이너리와 함께 보관하세요.

## 4단계: 주소 입력 및 연결

압축을 푼 폴더에서 시작하세요:

```sh
./seine
```

수신 주소 또는 등록된 `@name`을 입력하고 `stratum+tcp://bntpool.com:3333`을 선택한 뒤, 요청이 나오면 알아보기 쉬운 장비 이름을 정하세요. 이후 실행 시 seine는 작업 디렉터리를 기준으로 `seine-data/seine.config.json`을 다시 사용합니다. 같은 폴더에서 실행하면 설정을 쉽게 찾을 수 있습니다. 입력 항목과 데이터 디렉터리는 [설정 참고 문서](https://github.com/zpalmtree/seine/blob/v0.2.26/docs/guides/configuration.md)에 설명되어 있습니다.

채굴기의 해시레이트와 수락된 셰어 카운터를 확인하세요. 그런 다음 [My Stats](https://bntpool.com/stats)를 열고 동일한 수신 주소를 조회합니다. 수락된 셰어는 풀이 작업을 받고 있음을 확인해 줍니다. 지급은 별도의 보상 산정 및 지급 절차에 따라 이루어집니다. 채굴기 패널은 [대시보드 가이드](/ko/blog/seine-dashboard-explained/)에서 설명합니다. 정상적으로 종료하려면 `q` 또는 `Ctrl+C`를 누르세요.

## Linux에서 NVIDIA로 채굴하려면 무엇이 필요한가요?

Linux x86_64의 GPU 채굴에는 NVIDIA 드라이버와 호환되는 NVRTC 런타임 라이브러리가 필요합니다. NVRTC는 시작 시 GPU 커널을 컴파일합니다. [NVIDIA 설정 가이드](/ko/blog/mine-blocknet-nvidia-gpu/)에 따라 배포판 또는 NVIDIA 패키지로 런타임과 해당 builtins 라이브러리를 설치하세요. 패키지 이름은 배포판과 CUDA 버전에 따라 다르므로 본인 시스템에 맞는 안내를 사용하세요.

이 라이브러리가 있으면 기본 모드에서 CPU와 지원되는 NVIDIA 카드를 함께 사용해 채굴할 수 있습니다. GPU 런타임을 준비하면서 CPU 채굴을 먼저 설정하려면 명시적으로 CPU를 선택하세요:

```sh
./seine --backend cpu
```

이는 해당 실행에서 CPU만 사용하도록 하는 선택입니다. GPU 장치 선택과 GPU 셰어 수락 확인은 NVIDIA 가이드를 이어서 참고하세요. 여기서 설명하는 ARM64 릴리스에는 CPU 백엔드가 포함됩니다. CUDA를 설치해도 이 압축 파일에 NVIDIA 백엔드가 추가되지는 않습니다.

## Linux 시작 오류는 어떻게 해결하나요?

첫 번째 오류 메시지를 보고 다음 확인 항목을 선택하세요. 아키텍처 또는 런타임 오류는 셰어가 수락되기 전에 발생하므로 풀 주소나 스레드 수를 바꿔도 그 단계의 문제는 해결되지 않습니다. 실행 파일과 환경을 확인하는 동안 검증한 압축 파일을 보관하세요.

| 메시지 또는 증상 | 확인할 사항 |
|---|---|
| `Exec format error` | 아키텍처 불일치: `uname -m`을 압축 파일 이름과 비교하세요. |
| `GLIBC_2.39 not found` | 바이너리에 더 새로운 glibc가 필요합니다. 호환되는 시스템을 사용하거나 소스에서 빌드하고, 시스템 C 라이브러리는 배포판이 관리하도록 유지하세요. |
| `Permission denied` | 사용자의 실행 권한을 확인하고 실행을 허용하는 파일 시스템의 폴더를 사용하세요. |
| `libnvrtc` / `libnvrtc-builtins` | 호환되는 NVIDIA 런타임과 해당 builtins 라이브러리를 설치하거나, 준비하는 동안 `--backend cpu`를 사용하세요. |

셰어가 수락되기 시작하면 [휴즈 페이지 가이드](/ko/blog/huge-pages-blocknet-mining/)에서 선택적인 Linux 페이지 설정을 확인할 수 있습니다. [서버 가이드](/ko/blog/mine-blocknet-on-servers/)에서는 헤드리스 운영과 NUMA 배치를 다룹니다. 이 첫 실행 안내를 따르기 위해 두 준비 작업이 필요한 것은 아닙니다. 장비에서 무엇이 바뀌었는지 알 수 있도록 변경은 하나씩 적용하세요.
