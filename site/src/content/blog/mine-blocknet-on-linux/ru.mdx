Это руководство поможет запустить seine на настольном компьютере или сервере с Linux: от выбора архива до проверки принятых пулом шар. В качестве проверенного примера используется официальный выпуск v0.2.26. Подготовьте адрес получения Blocknet; где его найти, объясняется в [руководстве по кошельку](/ru/blog/blocknet-wallet-for-mining/). Вводите публичный адрес или зарегистрированное `@name`, но никогда не фразу восстановления кошелька.

## Как начать майнинг Blocknet на Linux?

<Answer>
Выберите архив Linux для своего процессора, проверьте его контрольную сумму SHA-256 и распакуйте в доступную для записи папку. Запустите `./seine`, введите адрес выплат и примите подключение к bntpool.com по умолчанию. seine автоматически выбирает число потоков CPU и может также использовать поддерживаемые карты NVIDIA на Linux x86_64, если установлены необходимые библиотеки среды выполнения.
</Answer>

## Шаг 1: проверьте архитектуру и glibc

Откройте терминал и выполните эти две команды проверки. Первая определяет архитектуру машины; вторая выводит версию библиотеки GNU C в системе на основе glibc. Они только читают данные: не запускают майнинг и не меняют конфигурацию компьютера.

```sh
uname -m
getconf GNU_LIBC_VERSION
```

Сопоставьте архитектуру с архивом в таблице ниже. Оба пакета Linux версии v0.2.26 требуют glibc 2.39 или новее. При установке более новой версии снова проверьте требования выпуска. Если система использует другую библиотеку C или более старую glibc, воспользуйтесь совместимой средой дистрибутива либо следуйте [инструкции по сборке из исходников](https://github.com/zpalmtree/seine/blob/master/docs/BUILDING.md).

| Вывод команды | Архив выпуска | Бэкенды |
|---|---|---|
| `x86_64` | `seine-linux-x86_64.tar.gz` | CPU и NVIDIA |
| `aarch64` | `seine-linux-aarch64.tar.gz` | CPU |

Каждому потоку майнинга CPU нужен блок памяти размером 2 GiB. seine выбирает начальное число потоков с учётом доступной памяти и ресурсов CPU, а затем настраивает его во время майнинга. При первом запуске не задавайте переопределения потоков и вычислительного ядра: сначала можно установить рабочее подключение, а затем менять настройки производительности.

## Шаг 2: скачайте и проверьте архив

Выберите Linux или Linux ARM64 в [разделе загрузки](/ru/#download). На странице того же [официального выпуска](https://github.com/zpalmtree/seine/releases/latest) скачайте также отдельный файл `SHA256SUMS.txt`, опубликованный среди файлов выпуска. Храните архив и файл контрольных сумм одной версии вместе. В примерах ниже используется x86_64; для ARM64 замените в командах `seine-linux-x86_64.tar.gz` на `seine-linux-aarch64.tar.gz`.

<img src="/assets/blog/linux-download.png" alt="Официальная таблица загрузок с архивами Linux и Linux ARM64" width="1200" height="900" loading="lazy" />

В терминале перейдите в каталог, куда браузер сохранил файлы, и вычислите контрольную сумму архива. В этом примере предполагается папка Downloads внутри домашнего каталога; если ваша папка загрузок называется иначе, укажите её фактическое имя.

```sh
cd "$HOME/Downloads"
sha256sum seine-linux-x86_64.tar.gz
```

Сравните полный шестнадцатеричный хеш со строкой именно этого архива в скачанном `SHA256SUMS.txt`. Перед распаковкой или запуском должны совпасть все цифры. Используйте для сравнения файл контрольных сумм, опубликованный отдельно с выпуском: внутри архива также есть манифест для распакованных файлов. Совпадение контрольной суммы подтверждает соответствие опубликованному значению; оба файла скачивайте из официального источника.

## Шаг 3: распакуйте и проверьте исполняемый файл

Создайте отдельную папку в домашнем каталоге, распакуйте в неё архив и запросите справку у программы. В архиве v0.2.26 файл `./seine` находится в корне, поэтому эти команды поместят исполняемый файл непосредственно в новую папку. Команда справки завершает работу без запуска майнинга.

```sh
mkdir -p "$HOME/seine"
tar -xzf seine-linux-x86_64.tar.gz -C "$HOME/seine"
cd "$HOME/seine"
chmod u+x ./seine
./seine --help
```

Выполняйте эти действия под своей учётной записью. `chmod u+x` даёт владельцу файла право на выполнение; установка для всей системы не нужна. Префикс `./` указывает оболочке запустить файл из текущего каталога. Храните распакованную документацию и файлы лицензий вместе с программой.

## Шаг 4: введите адрес и подключитесь

Запустите программу из папки с распакованными файлами:

```sh
./seine
```

Введите адрес получения или зарегистрированное `@name`, примите `stratum+tcp://bntpool.com:3333` и при запросе выберите узнаваемое имя установки. При последующих запусках seine использует `seine-data/seine.config.json` относительно рабочего каталога. Запуск из одной и той же папки помогает легко находить эти настройки. Запросы программы и каталог данных описаны в [справочнике конфигурации](https://github.com/zpalmtree/seine/blob/v0.2.26/docs/guides/configuration.md).

Следите за хешрейтом майнера и счётчиком принятых шар. Затем откройте [My Stats](https://bntpool.com/stats) и найдите тот же адрес получения. Принятые шары подтверждают, что пул получает работу; выплата происходит в рамках отдельного процесса начисления и отправки вознаграждений. Панели майнера описаны в [руководстве по интерфейсу](/ru/blog/seine-dashboard-explained/). Для корректной остановки нажмите `q` или `Ctrl+C`.

## Что нужно для майнинга на NVIDIA в Linux?

Для майнинга на GPU в Linux x86_64 нужны драйвер NVIDIA и совместимые библиотеки среды выполнения NVRTC. NVRTC компилирует вычислительные ядра GPU при запуске. Установите среду выполнения и соответствующую библиотеку builtins из пакетов вашего дистрибутива или NVIDIA, следуя [руководству по настройке NVIDIA](/ru/blog/mine-blocknet-nvidia-gpu/). Названия пакетов зависят от дистрибутива и версии CUDA, поэтому используйте инструкции для своей системы.

При наличии этих библиотек режим по умолчанию позволяет одновременно майнить на CPU и поддерживаемых картах NVIDIA. Чтобы сначала наладить майнинг на CPU, пока вы готовите среду GPU, явно выберите CPU:

```sh
./seine --backend cpu
```

Это включает только CPU для данного запуска. Выбор устройств GPU и проверка принятых GPU-шар описаны далее в руководстве NVIDIA. Описанный здесь выпуск ARM64 содержит бэкенд CPU; установка CUDA не добавляет бэкенд NVIDIA в этот архив.

## Как устранить ошибку запуска в Linux?

Выбирайте следующую проверку по первому сообщению об ошибке. Ошибка архитектуры или среды выполнения возникает до отправки принятых шар, поэтому смена адреса пула или числа потоков не исправит этот этап. Сохраните проверенный архив на время проверки исполняемого файла и окружения.

| Сообщение или симптом | Что проверить |
|---|---|
| `Exec format error` | Неподходящая архитектура: сравните `uname -m` с именем файла архива. |
| `GLIBC_2.39 not found` | Программе нужна более новая glibc. Используйте совместимую систему или соберите программу из исходников; управление системной библиотекой C оставьте дистрибутиву. |
| `Permission denied` | Проверьте право пользователя на выполнение и используйте папку на файловой системе, разрешающей запуск программ. |
| `libnvrtc` / `libnvrtc-builtins` | Установите совместимую среду выполнения NVIDIA и соответствующую библиотеку builtins либо используйте `--backend cpu`, пока готовите их. |

Когда шары начнут приниматься, [руководство по huge pages](/ru/blog/huge-pages-blocknet-mining/) поможет с необязательной настройкой страниц памяти в Linux. [Руководство по серверам](/ru/blog/mine-blocknet-on-servers/) описывает работу без монитора и размещение NUMA. Ни одна из этих подготовительных процедур не обязательна для первого запуска по этой инструкции; вносите изменения по отдельности, чтобы понимать, что изменилось на вашей машине.
