Доберіть потоки CPU до доступної пам’яті. Тут описано області 2 GiB, автоматичний добір seine v0.2.26 і перевірки після невдалого виділення пам’яті з ручними параметрами. Порівняння процесорів і виміряний хешрейт — у [посібнику з обладнання](/uk/blog/blocknet-mining-hardware-hashrate/). Приклади тут — обчислення пам’яті, не вимірювання швидкодії.

## Скільки RAM потрібно кожному потоку?

<Answer>
Кожному потоку CPU потрібна область Argon2id на 2 GiB. Залиште місце системі, програмам і майнеру. Почніть з автоматики seine, яка враховує доступну пам’ять і ресурси CPU. Ручна кількість потоків має вміщуватися в пам’ять, реально доступну під час запуску.
</Answer>

GiB — двійкова одиниця: 2 GiB дорівнюють 2 147 483 648 байтам. Область повторно використовується між хешами; завершений хеш не займає назавжди ще 2 GiB. Більше одночасних потоків потребують більше областей. [Опис Argon2id](/uk/blog/argon2id-proof-of-work-explained/) пояснює цю робочу пам’ять.

## Як розрахувати бюджет потоків?

Помножте заплановану кількість потоків CPU на 2 GiB. Таблиця не включає систему та інші витрати. Розрахуйте за нею області, а фактичну кількість оберіть за доступною пам’яттю та виміряною швидкістю.

| Потоки CPU | Лише пам’ять областей |
|---|---|
| 1 | 2 GiB |
| 2 | 4 GiB |
| 4 | 8 GiB |
| 8 | 16 GiB |
| 16 | 32 GiB |

Чотири потоки потребують 8 GiB для областей, тому для решти процесу й системи потрібно більше ніж 8 GiB доступної пам’яті. Якщо свідомо залишити 4 GiB на машині з 16 GiB, решта 12 GiB арифметично вміщує шість областей. Це вибір бюджету, а не обіцянка найкращого хешрейту на шести потоках.

Перевіряйте доступну пам’ять зі звичайними відкритими програмами через Диспетчер завдань Windows, Монітор активності macOS або інструменти Linux. Віртуальна машина чи контейнер можуть мати менший ліміт за хост. Використовуйте ефективний ліміт; заявлена RAM хоста не стає автоматично доступною в обмеженому середовищі.

## Як seine автоматично обирає потоки?

Під час першого запуску лише CPU не задавайте кількість. Виконайте команду з розпакованої теки Linux або macOS. У Windows використовуйте ті самі параметри з виконуваним файлом у PowerShell. [Початковий посібник](/uk/blog/how-to-mine-blocknet/) пояснює завантаження та адресу отримання.

```sh
./seine --backend cpu
```

У v0.2.26 автоматичний добір і налаштування типово резервують 5% ефективної загальної RAM, додатково враховуючи вже зайняту пам’ять. Ресурси CPU теж обмежують кількість. Задайте максимум для вужчого діапазону:

```sh
./seine --backend cpu --cpu-autotune-max-threads 4
```

Чотири — приклад стелі, не універсальний параметр. Автоматика може обрати менше. Стежте за потоками й середнім хешрейтом у [панелі](/uk/blog/seine-dashboard-explained/). Вона вимірює реальну конфігурацію; дочекайтеся стабілізації, перш ніж оцінювати зміну за коротким коливанням.

## Коли задавати сталу кількість потоків?

Для конкретного бюджету або відтворюваної конфігурації використовуйте сталу кількість. Приклад обирає два потоки CPU: 4 GiB для областей плюс інша пам’ять.

```sh
./seine --backend cpu --threads 2
```

`--threads` вимикає звичайний автоматичний вибір, якщо явно не ввімкнути також налаштування. Він перевизначає автоматичний резерв, тож залиште власний запас. Перевірки пам’яті діють. Кількість, що підходить установленій RAM, може перевищити доступну після запуску інших програм.

Змінюйте один параметр за раз. Записуйте потоки, доступну RAM і середній хешрейт за зіставного навантаження. Для автоматики приберіть сталий аргумент та збережені перевизначення. [Довідник v0.2.26](https://github.com/zpalmtree/seine/blob/v0.2.26/docs/guides/configuration.md) пояснює командний рядок і збережені параметри.

## Що перевірити після помилки виділення пам’яті?

Розрізняйте повідомлення про ефективний ліміт, доступну пам’ять і явне виділення великих сторінок. Перевірки різні. Закрийте зайві програми, зменште потоки й перезапустіть із місцем для звичайної роботи комп’ютера.

Перевірте призначену пам’ять контейнера чи віртуальної машини разом із хостом. Ліміт 1 GiB не вміщує область 2 GiB. Збільшення файлу підкачки не змінює вимоги; плануйте достатню фізичну пам’ять, доступну процесу.

За `--cpu-page-mode large` або `--cpu-page-mode large-1g` перевірте доступність потрібного резерву сторінок. Ці режими вимагають обраний тип. Дотримуйтеся [посібника huge pages](/uk/blog/huge-pages-blocknet-mining/) або поверніться до автоматичних сторінок для робочої базової конфігурації. Змінюйте сторінки й потоки окремо.

## Чи входить пам’ять GPU до бюджету CPU?

На дискретній NVIDIA області GPU містяться у VRAM. Потоки CPU далі використовують RAM системи. За спільного майнінгу розраховуйте ресурси окремо: вільна VRAM не розширює області CPU. [Посібник NVIDIA](/uk/blog/mine-blocknet-nvidia-gpu/) описує налаштування та лінії GPU.

В Apple Silicon CPU та GPU ділять об’єднану пам’ять. Не рахуйте її місткість двічі для інших завдань. Дотримуйтеся [посібника Mac](/uk/blog/mine-blocknet-on-mac/) для підтримуваного CPU-налаштування. Місткість визначає, що вміститься; виміряна швидкість — найкращу конфігурацію на вашій машині.

## Що перевірити перед тривалою роботою?

Переконайтеся, що потоки вкладаються в бюджет, програми реагують і надходять прийняті шари. Більше виділеної пам’яті саме по собі не доводить вищої швидкодії. Збережіть налаштування для свого навантаження й через [посібник відстеження пулу](https://bntpool.com/blog/uk/track-your-miner-on-bntpool/) підтвердьте свіжу роботу на адресі отримання.
