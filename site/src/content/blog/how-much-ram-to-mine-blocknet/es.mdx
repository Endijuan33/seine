Esta guía te ayuda a elegir hilos de CPU que quepan en la memoria disponible. Explica la asignación de 2 GiB, el ajuste automático de seine v0.2.26 y qué comprobar si una configuración manual no puede reservar memoria. Para comparar procesadores y tasas de hash medidas, consulta la [guía de hardware](/es/blog/blocknet-mining-hardware-hashrate/). Aquí los ejemplos son cálculos de memoria, no mediciones de rendimiento.

## ¿Cuánta RAM necesita cada hilo de minería?

<Answer>
Cada hilo de CPU necesita un área de memoria Argon2id de 2 GiB. Deja espacio para el sistema operativo, las aplicaciones y el minero. Empieza con el ajuste automático de seine, que considera la memoria disponible y los recursos de CPU. Un número manual de hilos debe caber en la memoria disponible al iniciar.
</Answer>

GiB es una unidad binaria: 2 GiB equivalen a 2.147.483.648 bytes. El área se reutiliza entre hashes; cada hash terminado no consume otros 2 GiB permanentemente. Más hilos simultáneos necesitan más áreas. La [explicación de Argon2id](/es/blog/argon2id-proof-of-work-explained/) describe por qué el algoritmo utiliza esta memoria.

## ¿Cómo calculas un presupuesto de hilos?

Multiplica los hilos de CPU previstos por 2 GiB para obtener la memoria de sus áreas. La tabla excluye el sistema y otros gastos de memoria. Úsala para calcular asignaciones; elige los hilos reales según la memoria disponible y el rendimiento medido.

| Hilos de CPU | Solo memoria de las áreas |
|---|---|
| 1 | 2 GiB |
| 2 | 4 GiB |
| 4 | 8 GiB |
| 8 | 16 GiB |
| 16 | 32 GiB |

Cuatro hilos necesitan 8 GiB para sus áreas, así que el equipo necesita más de 8 GiB disponibles para el resto del proceso y del sistema. Si reservas deliberadamente 4 GiB de un equipo de 16 GiB, los 12 GiB restantes permiten seis áreas por cálculo. Es una decisión de presupuesto, no una promesa de que seis hilos den la mejor tasa de hash.

Comprueba la memoria disponible con tus aplicaciones habituales abiertas. El Administrador de tareas de Windows, el Monitor de Actividad de macOS y las herramientas de Linux muestran el uso actual. Una máquina virtual o un contenedor puede tener menos memoria asignada que su anfitrión. Usa ese límite efectivo; la RAM anunciada del anfitrión no está automáticamente disponible dentro del entorno restringido.

## ¿Cómo elige seine los hilos automáticamente?

En la primera ejecución solo con CPU, deja el número de hilos sin definir. Ejecuta este comando desde la carpeta extraída en Linux o macOS. En Windows utiliza las mismas opciones con el ejecutable en PowerShell. La [guía de inicio](/es/blog/how-to-mine-blocknet/) explica la descarga y cómo introducir tu dirección de recepción.

```sh
./seine --backend cpu
```

En v0.2.26, el ajuste automático reserva por defecto el 5% de la RAM total efectiva, además de descontar la memoria ya utilizada. Los recursos de CPU también limitan los hilos. Para que el ajuste elija dentro de un rango menor, establece un máximo:

```sh
./seine --backend cpu --cpu-autotune-max-threads 4
```

Cuatro es un límite de ejemplo, no una configuración universal. El ajuste puede elegir menos hilos. Observa los hilos seleccionados y la tasa de hash media en el [panel](/es/blog/seine-dashboard-explained/) tras iniciar. El ajuste mide tu configuración real; deja que se estabilice antes de valorar un cambio por una fluctuación breve.

## ¿Cuándo conviene fijar los hilos?

Fija el número si tienes un presupuesto de memoria concreto o buscas una configuración repetible. Este ejemplo selecciona dos hilos de CPU, que necesitan 4 GiB para sus áreas más la memoria restante:

```sh
./seine --backend cpu --threads 2
```

Definir `--threads` desactiva la selección automática habitual, salvo que también actives el ajuste explícitamente. Sustituye la política de reserva automática, por lo que debes dejar tu propio margen. El minero sigue comprobando la memoria. Un número que cabe en la RAM instalada puede superar la disponible después de abrir otras aplicaciones.

Cambia una opción cada vez. Anota los hilos, la RAM disponible y la tasa de hash media con cargas comparables. Para volver al modo automático, elimina el argumento de hilos fijos y cualquier valor guardado que lo imponga. La [referencia de configuración de v0.2.26](https://github.com/zpalmtree/seine/blob/v0.2.26/docs/guides/configuration.md) explica cómo se aplican las opciones de línea de comandos y guardadas.

## ¿Qué debes comprobar tras un error de asignación de memoria?

Lee si el mensaje se refiere al límite efectivo, la memoria disponible o la asignación explícita de páginas grandes. Cada caso requiere comprobaciones distintas. Cierra las aplicaciones innecesarias, reduce los hilos solicitados y reinicia con espacio para el uso normal del escritorio.

Si un contenedor o una máquina virtual tiene un límite, comprueba su memoria asignada y la del anfitrión. Un límite de 1 GiB no puede alojar un área de 2 GiB. Ampliar el archivo de intercambio no cambia este requisito; planifica la minería con suficiente memoria física disponible para el proceso.

Si elegiste `--cpu-page-mode large` o `--cpu-page-mode large-1g`, comprueba que exista la reserva de páginas solicitada. Esos modos explícitos requieren ese tipo de respaldo. Sigue la [guía de páginas grandes](/es/blog/huge-pages-blocknet-mining/) o vuelve a la selección automática mientras estableces una configuración funcional. Ajusta las páginas y los hilos por separado.

## ¿Cuenta la memoria de GPU en el presupuesto de CPU?

En una tarjeta NVIDIA dedicada, las áreas de minería de GPU están en la VRAM. Los hilos de CPU siguen usando RAM del sistema. Dimensiona ambos recursos por separado al minar con CPU y GPU; la VRAM libre no es RAM adicional para las áreas de CPU. La [guía de NVIDIA](/es/blog/mine-blocknet-nvidia-gpu/) explica la configuración y las vías de GPU.

En Apple Silicon, CPU y GPU comparten memoria unificada. No cuentes esa capacidad dos veces al planificar otras cargas. Sigue la [guía de Mac](/es/blog/mine-blocknet-on-mac/) para la configuración de CPU compatible. La capacidad determina qué cabe; el rendimiento medido determina qué configuración funciona mejor en tu equipo.

## ¿Qué debes verificar antes de dejar el minero funcionando?

Comprueba que los hilos caben en tu presupuesto, las aplicaciones responden y llegan shares aceptados. Asignar más memoria no demuestra por sí solo un mayor rendimiento. Conserva la configuración adecuada a tu carga y usa la [guía de seguimiento del pool](https://bntpool.com/blog/es/track-your-miner-on-bntpool/) para confirmar trabajo reciente en tu dirección de recepción.
