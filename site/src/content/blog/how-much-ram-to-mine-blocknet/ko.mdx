가용 메모리에 맞는 CPU 스레드 수를 선택하세요. 이 가이드는 2 GiB 영역, seine v0.2.26의 자동 설정, 수동 설정에서 메모리 할당에 실패할 때의 확인 절차를 다룹니다. 칩 비교와 실측 해시레이트는 [하드웨어 가이드](/ko/blog/blocknet-mining-hardware-hashrate/)에 있습니다. 여기의 예시는 메모리 계산이며 성능 측정이 아닙니다.

## 스레드마다 RAM이 얼마나 필요한가요?

<Answer>
CPU 스레드마다 2 GiB Argon2id 영역이 필요합니다. 운영체제, 앱, 채굴 프로그램을 위한 공간도 남기세요. 가용 메모리와 CPU 자원을 고려하는 seine 자동 설정으로 시작하세요. 수동 스레드 수는 채굴 시작 시 실제 사용 가능한 메모리에 맞아야 합니다.
</Answer>

GiB는 이진 단위로, 2 GiB는 2,147,483,648바이트입니다. 영역은 해시 사이에 재사용되므로 해시를 하나 끝낼 때마다 2 GiB를 영구적으로 더 쓰지 않습니다. 동시 스레드가 늘면 영역도 더 필요합니다. [Argon2id 설명](/ko/blog/argon2id-proof-of-work-explained/)에서 이 작업 메모리를 다룹니다.

## 스레드 예산은 어떻게 계산하나요?

계획한 CPU 스레드 수에 2 GiB를 곱하세요. 표에는 시스템과 다른 오버헤드가 없습니다. 영역 계산에 사용하고 실제 수는 가용 메모리와 측정 처리량으로 선택하세요.

| CPU 스레드 | 영역 메모리만 |
|---|---|
| 1 | 2 GiB |
| 2 | 4 GiB |
| 4 | 8 GiB |
| 8 | 16 GiB |
| 16 | 32 GiB |

네 스레드는 영역에 8 GiB가 필요하므로 프로세스의 나머지와 시스템을 위해 8 GiB보다 많은 가용 메모리가 필요합니다. 16 GiB 기기에서 의도적으로 4 GiB를 남기면 나머지 12 GiB에 계산상 여섯 영역이 들어갑니다. 예산 선택의 예일 뿐 여섯 스레드가 최고 해시레이트라는 약속은 아닙니다.

평소 앱을 열어 둔 상태에서 Windows 작업 관리자, macOS 활성 상태 보기 또는 Linux 도구로 가용 메모리를 확인하세요. VM이나 컨테이너의 한도는 호스트보다 작을 수 있습니다. 그 실효 한도를 사용하세요. 호스트의 광고된 RAM이 제한 환경에 자동 제공되지는 않습니다.

## seine는 스레드를 어떻게 자동 선택하나요?

처음 CPU만 실행할 때는 수를 지정하지 마세요. Linux나 macOS에서는 압축을 푼 폴더에서 명령을 실행합니다. Windows에서는 PowerShell에서 실행 파일에 같은 옵션을 사용하세요. [설정 가이드](/ko/blog/how-to-mine-blocknet/)가 다운로드와 수신 주소 입력을 설명합니다.

```sh
./seine --backend cpu
```

v0.2.26의 자동 크기 선택과 조정은 이미 쓰는 메모리를 고려하면서 실효 총 RAM의 5%를 기본으로 남깁니다. CPU 자원도 수를 제한합니다. 조정 범위를 좁히려면 상한을 정하세요.

```sh
./seine --backend cpu --cpu-autotune-max-threads 4
```

4는 상한 예시이며 보편적인 설정이 아닙니다. 조정기는 더 적게 선택할 수 있습니다. [대시보드](/ko/blog/seine-dashboard-explained/)에서 선택된 수와 평균 해시레이트를 보세요. 실제 구성을 측정하므로 잠깐의 변동으로 판단하기 전에 안정될 때까지 기다리세요.

## 언제 스레드 수를 고정하나요?

특정 예산이나 재현 가능한 구성이 필요할 때 고정하세요. 예시는 CPU 두 스레드를 선택하며, 영역용 4 GiB에 다른 메모리가 추가로 필요합니다.

```sh
./seine --backend cpu --threads 2
```

`--threads`는 조정도 명시적으로 켜지 않는 한 일반 자동 선택을 끕니다. 자동 여유 정책을 덮어쓰므로 직접 여유를 남기세요. 메모리 검사는 계속 작동합니다. 설치 RAM에 맞는 수도 다른 앱 실행 뒤 가용 메모리를 초과할 수 있습니다.

한 번에 하나만 바꾸세요. 비슷한 부하에서 스레드, 가용 RAM, 평균 해시레이트를 기록하세요. 자동으로 돌아가려면 고정 인수와 저장된 재정의를 제거합니다. [v0.2.26 설정 문서](https://github.com/zpalmtree/seine/blob/v0.2.26/docs/guides/configuration.md)가 명령줄과 저장 설정 적용을 설명합니다.

## 메모리 할당 오류 뒤에는 무엇을 확인하나요?

메시지가 실효 한도, 가용 메모리, 명시적 큰 페이지 할당 중 무엇을 말하는지 구분하세요. 확인 항목이 다릅니다. 필요 없는 앱을 닫고 스레드를 줄인 뒤 정상적인 데스크톱 사용 공간을 남겨 다시 시작하세요.

컨테이너나 VM은 호스트와 할당 메모리를 함께 확인하세요. 1 GiB 한도에는 2 GiB 영역이 들어가지 않습니다. 스왑 파일을 늘려도 요구량은 변하지 않습니다. 프로세스가 쓸 충분한 물리 메모리를 계획하세요.

`--cpu-page-mode large` 또는 `--cpu-page-mode large-1g`를 선택했다면 요청한 예약 페이지 풀이 사용 가능한지 확인하세요. 명시 모드는 해당 종류를 요구합니다. [휴즈 페이지 가이드](/ko/blog/huge-pages-blocknet-mining/)를 따르거나 자동 페이지 선택으로 돌아가 작동하는 기준 구성을 만드세요. 페이지와 스레드는 따로 변경하세요.

## GPU 메모리도 CPU 예산에 들어가나요?

별도 NVIDIA 카드의 GPU 영역은 VRAM에 있습니다. CPU 스레드는 시스템 RAM을 사용합니다. 함께 채굴할 때 두 자원을 별도로 계산하세요. 빈 VRAM은 CPU 영역용 추가 RAM이 아닙니다. [NVIDIA 가이드](/ko/blog/mine-blocknet-nvidia-gpu/)가 설정과 GPU 레인 선택을 다룹니다.

Apple Silicon은 CPU와 GPU가 통합 메모리를 공유합니다. 다른 작업을 계획할 때 같은 용량을 두 번 계산하지 마세요. 지원되는 CPU 설정은 [Mac 가이드](/ko/blog/mine-blocknet-on-mac/)를 따르세요. 용량은 무엇이 들어가는지, 측정 처리량은 어떤 구성이 좋은지 결정합니다.

## 채굴을 계속 켜 두기 전에 무엇을 확인하나요?

스레드가 예산에 맞고 앱이 반응하며 승인된 셰어가 오는지 확인하세요. 더 큰 할당만으로 성능 향상이 입증되지는 않습니다. 부하에 맞는 구성을 유지하고 [풀 추적 가이드](https://bntpool.com/blog/ko/track-your-miner-on-bntpool/)로 수신 주소의 최근 작업을 확인하세요.
