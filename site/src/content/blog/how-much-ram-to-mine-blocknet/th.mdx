เลือกเธรด CPU ให้พอดีกับหน่วยความจำที่ใช้ได้ คู่มือนี้อธิบายพื้นที่ 2 GiB การเลือกอัตโนมัติใน seine v0.2.26 และสิ่งที่ต้องตรวจเมื่อค่าที่ตั้งเองจัดสรรหน่วยความจำไม่ได้ ดูการเปรียบเทียบชิปและแฮชเรตที่วัดจริงใน[คู่มือฮาร์ดแวร์](/th/blog/blocknet-mining-hardware-hashrate/) ตัวอย่างที่นี่เป็นการคำนวณหน่วยความจำ ไม่ใช่ผลทดสอบประสิทธิภาพ

## แต่ละเธรดต้องใช้ RAM เท่าไร?

<Answer>
แต่ละเธรด CPU ต้องใช้พื้นที่ Argon2id ขนาด 2 GiB เผื่อให้ระบบ แอป และโปรแกรมขุดด้วย เริ่มจากอัตโนมัติของ seine ซึ่งคำนึงถึงหน่วยความจำที่ใช้ได้และทรัพยากร CPU จำนวนที่ตั้งเองต้องพอดีกับหน่วยความจำที่มีจริงตอนเริ่มขุด
</Answer>

GiB เป็นหน่วยฐานสอง: 2 GiB เท่ากับ 2,147,483,648 ไบต์ พื้นที่ถูกใช้ซ้ำระหว่างแฮช แต่ละแฮชที่เสร็จไม่ได้กินเพิ่ม 2 GiB ถาวร เธรดพร้อมกันมากขึ้นต้องใช้พื้นที่มากขึ้น [คำอธิบาย Argon2id](/th/blog/argon2id-proof-of-work-explained/) อธิบายหน่วยความจำทำงานนี้

## คำนวณงบเธรดอย่างไร?

คูณจำนวนเธรด CPU ที่วางแผนด้วย 2 GiB ตารางไม่รวมระบบและค่าใช้จ่ายหน่วยความจำอื่น ใช้คำนวณพื้นที่ แล้วเลือกจำนวนจริงจากหน่วยความจำที่ใช้ได้และความเร็วที่วัด

| เธรด CPU | เฉพาะหน่วยความจำพื้นที่ขุด |
|---|---|
| 1 | 2 GiB |
| 2 | 4 GiB |
| 4 | 8 GiB |
| 8 | 16 GiB |
| 16 | 32 GiB |

สี่เธรดต้องมี 8 GiB สำหรับพื้นที่ จึงต้องมีมากกว่า 8 GiB ที่ใช้ได้เพื่อรองรับส่วนที่เหลือของโปรเซสและระบบ หากตั้งใจเผื่อ 4 GiB บนเครื่อง 16 GiB ส่วนที่เหลือ 12 GiB จะใส่ได้หกพื้นที่ตามการคำนวณ นี่เป็นตัวอย่างงบ ไม่ใช่คำรับรองว่าหกเธรดให้แฮชเรตดีที่สุด

ตรวจหน่วยความจำขณะเปิดแอปที่ใช้ปกติ ผ่าน Task Manager ของ Windows, Activity Monitor ของ macOS หรือเครื่องมือ Linux VM หรือคอนเทนเนอร์อาจมีโควตาน้อยกว่าโฮสต์ ใช้ขีดจำกัดที่มีผลจริง RAM ที่โฮสต์ประกาศไม่ได้พร้อมใช้ทั้งหมดโดยอัตโนมัติในสภาพแวดล้อมที่จำกัด

## seine เลือกเธรดอัตโนมัติอย่างไร?

การเริ่ม CPU อย่างเดียวครั้งแรกอย่าระบุจำนวน รันคำสั่งจากโฟลเดอร์ที่แตกไฟล์บน Linux หรือ macOS บน Windows ใช้ตัวเลือกเดียวกันกับไฟล์โปรแกรมใน PowerShell [คู่มือเริ่มต้น](/th/blog/how-to-mine-blocknet/) อธิบายการดาวน์โหลดและใส่ที่อยู่รับเงิน

```sh
./seine --backend cpu
```

ใน v0.2.26 การกำหนดขนาดและปรับอัตโนมัติสำรอง 5% ของ RAM รวมที่มีผลจริงตามค่าเริ่มต้น นอกจากคำนึงถึงหน่วยความจำที่ใช้อยู่ ทรัพยากร CPU ก็จำกัดจำนวนด้วย ตั้งเพดานเพื่อย่อช่วงปรับ:

```sh
./seine --backend cpu --cpu-autotune-max-threads 4
```

สี่เป็นเพดานตัวอย่าง ไม่ใช่ค่าที่เหมาะกับทุกเครื่อง ระบบอาจเลือกน้อยกว่า ดูจำนวนและแฮชเรตเฉลี่ยใน[แดชบอร์ด](/th/blog/seine-dashboard-explained/) การปรับวัดการตั้งค่าจริง รอให้คงที่ก่อนตัดสินจากความผันผวนสั้น ๆ

## ควรกำหนดเธรดคงที่เมื่อไร?

ใช้ค่าคงที่เมื่อต้องการงบเฉพาะหรือการตั้งค่าที่ทำซ้ำได้ ตัวอย่างเลือกสองเธรด CPU ต้องมี 4 GiB สำหรับพื้นที่และหน่วยความจำส่วนอื่นเพิ่ม

```sh
./seine --backend cpu --threads 2
```

`--threads` ปิดการเลือกอัตโนมัติปกติ เว้นแต่เปิดการปรับอย่างชัดเจนด้วย ค่านี้แทนนโยบายสำรองอัตโนมัติ จึงต้องเผื่อเอง การตรวจหน่วยความจำยังทำงาน จำนวนที่พอดีกับ RAM ติดตั้งอาจเกินที่ใช้ได้หลังเปิดแอปอื่น

เปลี่ยนทีละค่า จดเธรด RAM ที่ใช้ได้ และแฮชเรตเฉลี่ยภายใต้โหลดใกล้เคียงกัน หากกลับสู่อัตโนมัติ ให้เอาอาร์กิวเมนต์คงที่และค่าบันทึกที่ทับไว้ออก [เอกสาร v0.2.26](https://github.com/zpalmtree/seine/blob/v0.2.26/docs/guides/configuration.md) อธิบายค่าบันทึกและบรรทัดคำสั่ง

## ตรวจอะไรหลังจัดสรรหน่วยความจำผิดพลาด?

แยกว่าข้อความเกี่ยวกับขีดจำกัดจริง หน่วยความจำที่ใช้ได้ หรือการจัดสรรหน้าขนาดใหญ่ที่ระบุไว้ เพราะต้องตรวจต่างกัน ปิดแอปไม่จำเป็น ลดเธรด แล้วเริ่มใหม่โดยเผื่อพื้นที่สำหรับใช้เดสก์ท็อปตามปกติ

ตรวจหน่วยความจำที่จัดให้ VM หรือคอนเทนเนอร์พร้อมกับโฮสต์ ขีดจำกัด 1 GiB ใส่พื้นที่ 2 GiB ไม่ได้ การเพิ่มไฟล์ swap ไม่เปลี่ยนข้อกำหนดนี้ วางแผนหน่วยความจำจริงให้โปรเซสใช้ได้เพียงพอ

หากเลือก `--cpu-page-mode large` หรือ `--cpu-page-mode large-1g` ตรวจว่ามีพูลหน้าที่สำรองไว้ตามต้องการ โหมดเจาะจงต้องได้ชนิดที่เลือก ทำตาม[คู่มือ huge pages](/th/blog/huge-pages-blocknet-mining/) หรือกลับไปเลือกหน้าอัตโนมัติเพื่อสร้างค่าตั้งต้นที่ทำงานได้ เปลี่ยนหน้าและเธรดแยกกัน

## หน่วยความจำ GPU นับในงบ CPU ไหม?

บน NVIDIA แบบแยก พื้นที่ GPU อยู่ใน VRAM เธรด CPU ยังใช้ RAM ระบบ คิดสองส่วนแยกกันเมื่อขุดร่วมกัน VRAM ว่างไม่ใช่ RAM เพิ่มให้พื้นที่ CPU [คู่มือ NVIDIA](/th/blog/mine-blocknet-nvidia-gpu/) อธิบายการตั้งค่าและเลือกเลน GPU

Apple Silicon ใช้หน่วยความจำรวมร่วมกันระหว่าง CPU และ GPU อย่านับความจุเดียวกันสองครั้งเมื่อวางแผนงานอื่น ตาม[คู่มือ Mac](/th/blog/mine-blocknet-on-mac/) สำหรับ CPU ที่รองรับ ความจุบอกว่าอะไรใส่ได้ ความเร็วที่วัดบอกว่าค่าใดเหมาะที่สุด
