為電腦的可用記憶體選擇合適的 CPU 執行緒數。本指南介紹 2 GiB 工作區、seine v0.2.26 的自動設定，以及手動設定無法配置記憶體時的檢查步驟。晶片比較和實測算力請看[硬體指南](/zh-hant/blog/blocknet-mining-hardware-hashrate/)。這裡的範例是記憶體計算，不是效能測量。

## 每個挖礦執行緒需要多少 RAM？

<Answer>
每個 CPU 執行緒需要一個 2 GiB 的 Argon2id 工作區。還要為系統、應用程式和礦工程式留出空間。先使用 seine 的自動設定，它會考慮可用記憶體和 CPU 資源。手動指定的數量必須能放進啟動時真正可用的記憶體。
</Answer>

GiB 是二進位單位：2 GiB 等於 2,147,483,648 位元組。工作區會在各次雜湊間重複使用；每完成一次雜湊並不會永久消耗額外的 2 GiB。更多並行執行緒需要更多工作區。[Argon2id 說明](/zh-hant/blog/argon2id-proof-of-work-explained/)解釋演算法為何需要這些工作記憶體。

## 如何計算執行緒預算？

將計畫使用的 CPU 執行緒數乘以 2 GiB。表格不包含系統和其他記憶體開銷。用它計算工作區，再依可用記憶體和實測吞吐量選擇實際數量。

| CPU 執行緒數 | 僅工作區記憶體 |
|---|---|
| 1 | 2 GiB |
| 2 | 4 GiB |
| 4 | 8 GiB |
| 8 | 16 GiB |
| 16 | 32 GiB |

四個執行緒的工作區需要 8 GiB，因此還需要超過 8 GiB 的可用記憶體來容納程序的其他部分和系統。如果在 16 GiB 電腦上主動留出 4 GiB，剩餘 12 GiB 按計算可放六個工作區。這是預算範例，不保證六個執行緒的算力最高。

開啟日常應用程式後，透過 Windows 工作管理員、macOS 活動監視器或 Linux 記憶體工具查看可用記憶體。虛擬機或容器的額度可能小於主機。應使用該有效上限；主機標示 RAM 不會自動全部提供給受限環境。

## seine 如何自動選擇執行緒？

第一次僅用 CPU 執行時，不指定數量。在 Linux 或 macOS 解壓縮目錄執行下方指令。Windows 則在 PowerShell 中給執行檔使用相同參數。[入門指南](/zh-hant/blog/how-to-mine-blocknet/)介紹下載和填寫收款地址。

```sh
./seine --backend cpu
```

v0.2.26 的自動選擇與調整會考慮已使用記憶體，並預設保留有效總 RAM 的 5%。CPU 資源也限制數量。要縮小調整範圍，可指定上限：

```sh
./seine --backend cpu --cpu-autotune-max-threads 4
```

四只是上限範例，不是通用設定。調整器可能選擇更少執行緒。啟動後在[儀表板](/zh-hant/blog/seine-dashboard-explained/)查看選中的數量和平均算力。自動調整測量實際設定，應等它穩定後再判斷，不要僅憑短時波動。

## 何時固定執行緒數？

需要明確的記憶體預算或可重現設定時，可固定數量。範例選擇兩個 CPU 執行緒：工作區需要 4 GiB，另外還需要其他記憶體。

```sh
./seine --backend cpu --threads 2
```

明確使用 `--threads` 會關閉一般的自動選擇，除非同時明確啟用調整。它覆寫自動預留策略，因此需要自行留出餘裕。記憶體檢查仍會執行。能放進已安裝 RAM 的數量，在其他應用程式啟動後可能超過可用記憶體。

每次只改一個設定。在相近負載下記錄數量、可用 RAM 和平均算力。要恢復自動選擇，請刪除固定執行緒參數及已儲存的覆寫設定。[v0.2.26 設定參考](https://github.com/zpalmtree/seine/blob/v0.2.26/docs/guides/configuration.md)說明命令列和儲存設定的套用方式。

## 記憶體配置失敗後應檢查什麼？

先區分訊息是在說有效記憶體上限、目前可用記憶體，還是明確的大頁配置。它們對應不同檢查。關閉不需要的應用程式，減少執行緒，再為日常桌面使用留出空間後重新啟動。

對容器或虛擬機，同時檢查分配額度和主機記憶體。1 GiB 的額度無法容納一個 2 GiB 工作區。增大交換檔不會改變工作區需求；應規劃足夠的、程序可用的實體記憶體。

若選擇 `--cpu-page-mode large` 或 `--cpu-page-mode large-1g`，確認所需的預留頁面池可用。這些明確模式要求對應的記憶體頁面支援。按照[大頁指南](/zh-hant/blog/huge-pages-blocknet-mining/)設定，或先恢復自動頁面選擇來建立可運作的基準。頁面設定與執行緒數應分開調整。

## GPU 顯示記憶體計入 CPU 預算嗎？

獨立 NVIDIA 顯示卡的 GPU 工作區位於 VRAM。CPU 執行緒仍配置系統 RAM。同時挖礦時分別規劃兩種資源；閒置 VRAM 不是 CPU 工作區的額外 RAM。[NVIDIA 指南](/zh-hant/blog/mine-blocknet-nvidia-gpu/)介紹設定和 GPU 通道選擇。

Apple Silicon 的 CPU 與 GPU 共用統一記憶體。規劃其他工作時，不要把同一容量算兩遍。支援的 CPU 設定見[Mac 指南](/zh-hant/blog/mine-blocknet-on-mac/)。容量決定能放下什麼，實測吞吐量決定哪種設定更適合你的電腦。

## 讓礦工持續運作前應確認什麼？

確認執行緒符合預算、應用程式仍有回應，並且收到礦池接受的份額。增加配置本身不能證明效能更好。保留適合負載的設定，再用[礦池追蹤指南](https://bntpool.com/blog/zh-hant/track-your-miner-on-bntpool/)確認收款地址有近期工作紀錄。
