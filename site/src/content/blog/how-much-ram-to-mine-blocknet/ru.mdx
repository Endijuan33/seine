Подберите потоки CPU под доступную память. Здесь разобраны области 2 GiB, автоматический подбор seine v0.2.26 и проверки при неудачном выделении памяти с ручными настройками. Сравнения процессоров и измеренный хешрейт — в [руководстве по оборудованию](/ru/blog/blocknet-mining-hardware-hashrate/). Примеры ниже — расчёты памяти, а не замеры производительности.

## Сколько RAM требуется каждому потоку?

<Answer>
Каждому потоку CPU нужна область Argon2id размером 2 GiB. Оставьте место системе, приложениям и майнеру. Начните с автоматики seine, учитывающей доступную память и ресурсы CPU. Ручное число потоков должно помещаться в память, реально доступную при запуске.
</Answer>

GiB — двоичная единица: 2 GiB равны 2 147 483 648 байтам. Область используется повторно между хешами; каждый завершённый хеш не занимает ещё 2 GiB навсегда. Больше одновременных потоков требуют больше областей. [Описание Argon2id](/ru/blog/argon2id-proof-of-work-explained/) объясняет эту рабочую память.

## Как рассчитать бюджет потоков?

Умножьте число потоков CPU на 2 GiB. Таблица не включает систему и прочие расходы памяти. Рассчитайте по ней области, а фактическое число выберите по доступной памяти и измеренной скорости.

| Потоки CPU | Только память областей |
|---|---|
| 1 | 2 GiB |
| 2 | 4 GiB |
| 4 | 8 GiB |
| 8 | 16 GiB |
| 16 | 32 GiB |

Четыре потока требуют 8 GiB для областей, значит, для остального процесса и системы нужно больше 8 GiB доступной памяти. Если намеренно оставить 4 GiB на машине с 16 GiB, в оставшиеся 12 GiB арифметически входят шесть областей. Это пример бюджета, а не обещание лучшего хешрейта на шести потоках.

Проверяйте доступную память с обычными открытыми приложениями: Диспетчер задач Windows, Мониторинг системы macOS или инструменты Linux. Виртуальная машина или контейнер могут иметь меньший лимит, чем хост. Используйте этот эффективный лимит; заявленная память хоста не становится автоматически доступной внутри ограниченного окружения.

## Как seine автоматически выбирает потоки?

При первом запуске только CPU не задавайте число потоков. Выполните команду из распакованной папки Linux или macOS. В Windows используйте те же параметры с исполняемым файлом в PowerShell. [Начальное руководство](/ru/blog/how-to-mine-blocknet/) объясняет загрузку и адрес получения.

```sh
./seine --backend cpu
```

В v0.2.26 автоматический подбор и настройка по умолчанию резервируют 5% эффективного общего объёма RAM, дополнительно учитывая уже занятую память. Ресурсы CPU тоже ограничивают число. Для сужения диапазона задайте максимум:

```sh
./seine --backend cpu --cpu-autotune-max-threads 4
```

Четыре — пример верхней границы, не универсальная настройка. Автоматика может выбрать меньше. Следите за потоками и средним хешрейтом в [панели](/ru/blog/seine-dashboard-explained/). Настройка измеряет реальную конфигурацию; дождитесь стабилизации, прежде чем оценивать изменение по короткому колебанию.

## Когда задавать фиксированное число потоков?

Используйте фиксированное число для определённого бюджета или воспроизводимой конфигурации. Пример выбирает два потока CPU: 4 GiB для областей плюс остальная память.

```sh
./seine --backend cpu --threads 2
```

`--threads` отключает обычный автоматический выбор, если явно не включить настройку дополнительно. Он переопределяет автоматический резерв, поэтому оставьте запас самостоятельно. Проверки памяти сохраняются. Число, подходящее установленной RAM, может превысить доступную после запуска других приложений.

Меняйте один параметр за раз. Записывайте потоки, доступную RAM и средний хешрейт при сопоставимой нагрузке. Для возврата к автоматике уберите фиксированный аргумент и сохранённые переопределения. [Справочник v0.2.26](https://github.com/zpalmtree/seine/blob/v0.2.26/docs/guides/configuration.md) объясняет командную строку и сохранённые настройки.

## Что проверить после ошибки выделения памяти?

Различайте сообщения об эффективном лимите, доступной памяти и явном выделении больших страниц. Проверки различаются. Закройте ненужные приложения, уменьшите потоки и перезапустите, оставив место для обычной работы компьютера.

Проверьте выделенную память контейнера или виртуальной машины вместе с хостом. Лимит 1 GiB не вместит область 2 GiB. Увеличение файла подкачки не меняет требование; планируйте достаточную физическую память, доступную процессу.

При `--cpu-page-mode large` или `--cpu-page-mode large-1g` убедитесь, что нужный резерв страниц доступен. Эти режимы требуют выбранный тип страниц. Следуйте [руководству huge pages](/ru/blog/huge-pages-blocknet-mining/) или вернитесь к автоматическому выбору для рабочей базовой конфигурации. Меняйте страницы и число потоков отдельно.

## Входит ли память GPU в бюджет CPU?

На дискретной NVIDIA области GPU расположены в VRAM. Потоки CPU продолжают использовать системную RAM. При совместном майнинге рассчитывайте ресурсы отдельно: свободная VRAM не расширяет области CPU. [Руководство NVIDIA](/ru/blog/mine-blocknet-nvidia-gpu/) описывает настройку и выбор линий GPU.

В Apple Silicon CPU и GPU делят объединённую память. Не учитывайте эту ёмкость дважды при планировании других задач. Используйте [руководство Mac](/ru/blog/mine-blocknet-on-mac/) для поддерживаемой CPU-конфигурации. Ёмкость определяет, что поместится; измеренная скорость — лучшую конфигурацию на вашей машине.

## Что проверить перед длительной работой?

Убедитесь, что потоки укладываются в бюджет, приложения отзывчивы и поступают принятые шары. Большая аллокация сама по себе не доказывает прирост скорости. Сохраните подходящие настройки и через [руководство отслеживания пула](https://bntpool.com/blog/ru/track-your-miner-on-bntpool/) подтвердите свежую работу на адресе получения.
