在第二台電腦上查看 Blocknet 轉入付款，同時把付款授權保留在完整錢包中。本指南使用官方 CLI v1.2.0 與公開核心程式 v0.22.0，核查日期為2026年10月27日。下文介紹匯出檔案的操作流程、檔案授予的權限，以及載入後如何核對收款紀錄。

## 如何建立唯讀 Blocknet 錢包？

<Answer>
開啟完整錢包，使用 viewkeys 指令建立具獨立密碼的加密檢視檔案。將匯出的檔案傳到目標電腦，載入後核對地址與唯讀類型。等待錢包掃描追上進度，再用它查看轉入付款，支出操作仍留在完整錢包中。
</Answer>

## 選擇要監控的收款紀錄

從你希望監控轉入資金的完整錢包開始。[錢包設定指南](/zh-hant/blog/blocknet-wallet-for-mining/)介紹如何建立或復原錢包。檢視副本對應這個錢包的地址；它不會建立新的收款身分，也不會把代幣移到另一個帳戶。在處理任何匯出檔案之前，先記下副本對應的錢包與網路。

挖礦時，你可以繼續使用同一個已核對的付款地址。唯讀錢包能協助你在另一台可信任電腦上檢查錢包的轉入紀錄。[礦池監控指南](https://bntpool.com/blog/zh-hant/track-your-miner-on-bntpool/)處理的是另一項工作：不需錢包金鑰即可查看份額、礦池餘額與付款活動。根據問題選擇介面；需要查看私密收款紀錄時，檢視權限才有用。

## 從完整錢包匯出檢視檔案

在保存完整錢包的電腦上，連線至它正在執行的主網核心程式：

```sh
blocknet attach mainnet
```

用以下互動指令開啟目標錢包並檢查地址：

```text
load
address
```

如果錢包已鎖定，按一般提示解鎖。保持這次工作階段私密，因為下一步會顯示檢視金鑰資料。

開始匯出：

```text
viewkeys
```

[本文核查的用戶端](https://github.com/blocknetprivacy/blocknet/blob/948af4de8b7a3e3cddc86a329c7d2d003cb3fd6b/attach_wallet.go)會說明私有檢視金鑰可以顯示轉入資金，並要求確認繼續。只有確實要授予這種權限時才繼續。隨後，用戶端要求輸入完整錢包的密碼、為唯讀檔案設定新密碼，再確認新密碼。請選擇並保存供目標電腦使用的檔案密碼。

## 應該傳輸哪個檔案？

成功匯出後，用戶端會顯示檢視金鑰與所儲存檔案的路徑。請根據這條實際路徑辨識匯出的檢視檔案。使用適合傳輸私密錢包資料的方法，將它傳到你控制的電腦。分開保護檔案密碼，不要把終端機輸出中的金鑰納入截圖或疑難排解紀錄。

[錢包參考文件](https://github.com/blocknetprivacy/blocknet/blob/948af4de8b7a3e3cddc86a329c7d2d003cb3fd6b/docs/reference-wallet.md)列出的預設資料夾為 `~/.config/bnt/wallets/`，Windows 對應路徑為 `C:\Users\<you>\.config\bnt\wallets\`。設定的錢包路徑可能改變 load 所列出的資料夾。把匯出檔複製到目標電腦的錢包資料夾，方便用戶端找到它。原始完整錢包及其復原備份仍保存在各自預定的儲存位置。

## 在第二台電腦上載入並核對副本

按照[節點指南](/zh-hant/blog/run-blocknet-node/)在目標電腦上準備正在執行的核心程式，再連線至相同網路。使用為匯出檔案設定的密碼開啟它：

```text
load
```

如果已開啟另一個錢包，官方互動介面支援先卸載該錢包，再載入目標檔案。請依匯出的檔案名稱選擇，不要假定清單中的第一個錢包就是正確的錢包。

透過用戶端核對副本：

```text
address
status
```

將完整收款地址與完整錢包的地址比較，並檢查用戶端顯示的唯讀類型。這些檢查同時確認錢包身分與預期權限。無需嘗試傳送以驗證區別：[本文核查的核心程式](https://github.com/blocknetprivacy/core/blob/5a0a5b510c1dce46f4eeb12c33a291052e44e7b3/api_handlers.go)會拒絕唯讀錢包傳送付款或簽署訊息。

## 讓唯讀錢包找出轉入付款

目標節點需要擁有相關區塊，載入的錢包則需要掃描這些區塊。用以下指令查看錢包紀錄：

```text
outputs
history
```

即使節點已有對等連線，剛載入或匯入的錢包也可能仍在追趕掃描進度。參照[錢包同步指南](/zh-hant/blog/blocknet-wallet-not-syncing/)，區分區塊鏈下載與錢包掃描，並判斷是否需要執行掃描。

將轉入紀錄與完整錢包或付款紀錄中已知的交易 ID 對照。[瀏覽器指南](/zh-hant/blog/blocknet-explorer-guide/)可協助確認交易的公開入塊狀態，而唯讀錢包提供轉入付款的詳細資訊。目前的支出決策與授權應使用完整錢包完成。把檢視副本當作轉入監控工具，不要假定它會鏡像所有轉出紀錄或可支出餘額判斷。

## 私有檢視金鑰授予什麼權限？

[官方互動指令參考](https://github.com/blocknetprivacy/blocknet/blob/948af4de8b7a3e3cddc86a329c7d2d003cb3fd6b/docs/reference-core.md)提醒，私有檢視金鑰的持有者可以查看轉入資金。加密檢視檔案用自己的密碼保護存取，但開啟它仍會顯示私密付款資訊。只向預定的人或電腦授予權限。更改檔案密碼不會撤銷別人已經複製的檢視金鑰。

不要把支出或檢視秘密放進公開工具與求助訊息。收款地址用於向付款方提供收款資訊，私有檢視金鑰的用途不同。[隱身地址指南](/zh-hant/blog/stealth-addresses-explained/)解釋錢包如何辨識屬於自己的輸出。在本設定中，只傳輸你確實打算提供的檢視權限，復原資料仍與完整錢包一同保管。

## 保持可重複的檢視流程

再次使用監控電腦時，載入相同的檢視檔案，核對網路與地址，並先檢查掃描進度，再解讀某筆紀錄為何尚未出現。區分轉入紀錄與自己能夠授權支出的資金。如果你另建了錢包而取得新地址，現有檢視副本仍然對應舊錢包。

檢視設定可用後，仍要保留完整錢包的復原備份。檢視副本不能取代復原支出權限所需的資料。[助記詞指南](/zh-hant/blog/seed-phrase-explained/)解釋這種備份，[傳送與接收指南](/zh-hant/blog/send-receive-blocknet/)介紹付款流程。完整錢包、復原備份與檢視副本在日常使用中各有明確職責。
