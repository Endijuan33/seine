Спостерігайте за вхідними платежами Blocknet на другому комп’ютері, залишаючи підтвердження платежів у повному гаманці. Посібник використовує офіційний CLI v1.2.0 та публічне ядро v0.22.0, перевірені 27 жовтня 2026 року. Він описує роботу з експортованим файлом, пояснює наданий доступ і показує, як перевірити записи про отримання після завантаження.

## Як створити гаманець Blocknet лише для перегляду?

<Answer>
Відкрийте повний гаманець і командою viewkeys створіть зашифрований файл перегляду з окремим паролем. Перенесіть його на потрібний комп’ютер, завантажте й перевірте адресу та тип лише для перегляду. Дочекайтеся завершення сканування й переглядайте надходження, залишаючи витрачання коштів у повному гаманці.
</Answer>

## Оберіть надходження для спостереження

Почніть із повного гаманця, надходження якого хочете відстежувати. [Посібник із налаштування гаманця](/uk/blog/blocknet-wallet-for-mining/) описує створення й відновлення. Копія для перегляду відповідає адресі цього гаманця; вона не створює нову особу отримувача та не переміщує монети на інший рахунок. Перед роботою з експортованими файлами запишіть гаманець і мережу, до яких належить копія.

Для майнінгу можна й надалі використовувати ту саму перевірену адресу виплат. Гаманець для перегляду допомагає читати вхідні записи на іншому довіреному комп’ютері. [Посібник із відстеження пулу](https://bntpool.com/blog/uk/track-your-miner-on-bntpool/) має інше завдання: показувати шари, баланс пулу й виплати без ключів гаманця. Обирайте інтерфейс відповідно до запитання; доступ перегляду корисний, коли потрібен приватний запис про отримання.

## Експортуйте файл із повного гаманця

На комп’ютері з повним гаманцем підключіться до його запущеного ядра mainnet:

```sh
blocknet attach mainnet
```

Відкрийте потрібний гаманець і перевірте адресу такими командами оболонки:

```text
load
address
```

Якщо гаманець заблоковано, скористайтеся звичайним запитом розблокування. Зберігайте приватність сеансу, адже наступна операція відображає ключі перегляду.

Почніть експорт:

```text
viewkeys
```

[Перевірений клієнт](https://github.com/blocknetprivacy/blocknet/blob/948af4de8b7a3e3cddc86a329c7d2d003cb3fd6b/attach_wallet.go) пояснює, що приватний ключ перегляду розкриває надходження, і запитує підтвердження. Продовжуйте лише якщо хочете надати цей доступ. Потім він просить пароль повного гаманця, новий пароль для файлу лише для перегляду та його підтвердження. Оберіть і збережіть пароль файлу для комп’ютера призначення.

## Який файл потрібно переносити?

Після успішного експорту клієнт показує ключі перегляду та шлях до збереженого файлу. Визначте експортований файл за цим фактичним шляхом. Перенесіть його на комп’ютер під вашим контролем способом, придатним для приватних даних гаманця. Захищайте пароль окремо. Не включайте показані в терміналі ключі до знімків екрана чи діагностичних записів.

[Довідник гаманця](https://github.com/blocknetprivacy/blocknet/blob/948af4de8b7a3e3cddc86a329c7d2d003cb3fd6b/docs/reference-wallet.md) вказує стандартну папку `~/.config/bnt/wallets/` та її відповідник Windows `C:\Users\<you>\.config\bnt\wallets\`. Налаштований шлях гаманця може змінити папку, яку показує load. Скопіюйте експортований файл до папки гаманців на цільовому комп’ютері, щоб клієнт його знайшов. Зберігайте оригінальний повний гаманець і резервну копію для відновлення у визначеному сховищі.

## Завантажте й перевірте копію на другому комп’ютері

Підготуйте запущене ядро на цільовому комп’ютері за [посібником вузла](/uk/blog/run-blocknet-node/), а потім підключіться до тієї самої мережі. Відкрийте експортований файл із обраним для нього паролем:

```text
load
```

Якщо інший гаманець уже відкрито, офіційна оболонка дозволяє вивантажити його перед завантаженням потрібного. Обирайте за назвою експортованого файлу, не припускаючи, що перший гаманець у списку правильний.

Перевірте копію в клієнті:

```text
address
status
```

Порівняйте повну адресу отримання з адресою повного гаманця. Перевірте показаний клієнтом тип лише для перегляду. Це підтверджує і відповідність, і потрібний доступ. Пробувати надсилання не потрібно: [перевірене ядро](https://github.com/blocknetprivacy/core/blob/5a0a5b510c1dce46f4eeb12c33a291052e44e7b3/api_handlers.go) відхиляє надсилання та підписання повідомлень із гаманця лише для перегляду.

## Дайте гаманцю знайти вхідні платежі

Вузлу призначення потрібні відповідні блоки, а завантажений гаманець має їх просканувати. Перегляньте його записи цими командами:

```text
outputs
history
```

Нещодавно завантажений або імпортований гаманець може ще наздоганяти ланцюжок, навіть якщо вузол має піри. [Посібник із синхронізації гаманця](/uk/blog/blocknet-wallet-not-syncing/) допоможе розрізнити завантаження ланцюжка й сканування гаманця та визначити, чи потрібне сканування.

Зіставте надходження з уже відомим ID транзакції з повного гаманця або запису виплати. [Посібник оглядача](/uk/blog/blocknet-explorer-guide/) допомагає підтвердити публічне включення, а гаманець для перегляду надає деталі надходження. Використовуйте повний гаманець для поточних рішень про витрати та їх підтвердження. Розглядайте копію як монітор надходжень, не припускаючи, що вона відображає всі вихідні записи або рішення щодо доступного для витрат балансу.

## Який доступ надає приватний ключ перегляду?

[Офіційний довідник оболонки](https://github.com/blocknetprivacy/blocknet/blob/948af4de8b7a3e3cddc86a329c7d2d003cb3fd6b/docs/reference-core.md) попереджає, що власник цього ключа може бачити надходження. Зашифрований файл перегляду захищає доступ власним паролем, але його відкриття розкриває приватні платіжні дані. Надавайте доступ лише потрібній людині чи машині. Зміна пароля файлу не відкликає ключ перегляду, який хтось уже скопіював.

Не передавайте секрети витрачання та перегляду публічним інструментам і повідомленням підтримки. Адресу отримання передають для платежу; приватний ключ перегляду має іншу мету. [Посібник зі стелс-адрес](/uk/blog/stealth-addresses-explained/) пояснює, як гаманець упізнає власні виходи. Передавайте лише запланований доступ перегляду, а матеріали відновлення тримайте з повним гаманцем.

## Дотримуйтеся повторюваного порядку перегляду

Повертаючись до комп’ютера спостереження, завантажуйте той самий файл, перевіряйте мережу й адресу та дивіться на прогрес, перш ніж тлумачити відсутній запис. Розрізняйте запис про надходження та кошти, витрачання яких можете дозволити. Якщо створите інший гаманець із новою адресою, наявна копія для перегляду й надалі відповідатиме старому.

Зберігайте резервну копію для відновлення повного гаманця навіть після успішного налаштування перегляду. Копія для перегляду не замінює матеріал витрачання, потрібний для відновлення. [Посібник із сід-фрази](/uk/blog/seed-phrase-explained/) пояснює цей резерв, а [надсилання й отримання](/uk/blog/send-receive-blocknet/) — платіжний процес. Повний гаманець, резервна копія та копія для перегляду мають кожен чітке завдання.
