결제 승인은 전체 지갑에 유지하면서 두 번째 컴퓨터에서 Blocknet 입금을 확인하세요. 이 안내는 2026년 10월 27일 확인한 공식 CLI v1.2.0과 공개 core v0.22.0을 사용합니다. 파일 내보내기 절차, 파일이 부여하는 권한, 불러온 뒤 수취 기록을 검증하는 방법을 설명합니다.

## Blocknet 보기 전용 지갑은 어떻게 만드나요?

<Answer>
전체 지갑을 열고 viewkeys 명령으로 별도 비밀번호를 가진 암호화 보기 파일을 만드세요. 의도한 컴퓨터로 옮겨 불러온 뒤 주소와 보기 전용 유형을 검증하세요. 지갑 스캔이 따라잡도록 한 뒤 입금을 살펴보고 지출은 전체 지갑에서 하세요.
</Answer>

## 감시할 수취 기록 선택하기

입금을 관찰할 전체 지갑에서 시작하세요. [지갑 설정 안내](/ko/blog/blocknet-wallet-for-mining/)가 생성과 복원을 설명합니다. 보기 사본은 그 지갑 주소에 대응하며 별도 수취 신원을 만들거나 새 계정으로 코인을 옮기지 않습니다. 내보낸 파일을 다루기 전에 어느 지갑과 네트워크의 사본인지 적어 두세요.

채굴에는 같은 검증된 지급 주소를 계속 쓸 수 있습니다. 보기 지갑은 다른 신뢰하는 컴퓨터에서 입금 기록을 살펴보는 데 도움을 줍니다. [풀 추적 안내](https://bntpool.com/blog/ko/track-your-miner-on-bntpool/)는 지갑 키 없이 셰어, 풀 잔액, 지급 활동을 보여 주는 별도 작업입니다. 질문에 맞는 화면을 선택하세요. 비공개 수취 기록이 필요할 때 보기 접근이 유용합니다.

## 전체 지갑에서 보기 파일 내보내기

전체 지갑이 있는 컴퓨터에서 실행 중인 mainnet core에 연결하세요.

```sh
blocknet attach mainnet
```

셸 명령으로 의도한 지갑을 열고 주소를 확인하세요.

```text
load
address
```

잠겼다면 일반 잠금 해제 프롬프트를 사용하세요. 다음 작업이 보기 키 자료를 표시하므로 이 세션을 비공개로 유지하세요.

내보내기를 시작하세요.

```text
viewkeys
```

[검토한 클라이언트](https://github.com/blocknetprivacy/blocknet/blob/948af4de8b7a3e3cddc86a329c7d2d003cb3fd6b/attach_wallet.go)는 보기 개인 키가 입금을 드러낸다고 설명하고 계속할지 묻습니다. 그 접근을 주려는 경우에만 진행하세요. 다음으로 전체 지갑 비밀번호, 보기 전용 파일의 새 비밀번호, 새 비밀번호 확인을 요청합니다. 받는 컴퓨터에서 쓸 파일 비밀번호를 선택하고 보관하세요.

## 어떤 파일을 옮겨야 하나요?

내보내기가 성공하면 클라이언트가 보기 키와 저장 파일 경로를 표시합니다. 실제 저장 경로로 내보낸 보기 파일을 식별하세요. 비공개 지갑 데이터에 적합한 방법으로 자신이 관리하는 컴퓨터에 옮기세요. 파일 비밀번호는 따로 보호하세요. 터미널의 키 출력을 스크린샷이나 문제 해결 기록에 포함하지 마세요.

[지갑 참조](https://github.com/blocknetprivacy/blocknet/blob/948af4de8b7a3e3cddc86a329c7d2d003cb3fd6b/docs/reference-wallet.md)는 기본 폴더를 `~/.config/bnt/wallets/`, Windows 대응 경로를 `C:\Users\<you>\.config\bnt\wallets\`로 설명합니다. 지갑 경로 설정에 따라 load가 나열하는 폴더는 달라질 수 있습니다. 클라이언트가 찾도록 대상 컴퓨터의 지갑 폴더에 내보낸 파일을 복사하세요. 원래 전체 지갑과 복구 백업은 의도한 저장소에 보관하세요.

## 두 번째 컴퓨터에서 사본 불러와 검증하기

[노드 안내](/ko/blog/run-blocknet-node/)에 따라 대상 컴퓨터에 core를 실행하고 같은 네트워크에 연결하세요. 그 파일용으로 선택한 비밀번호로 내보낸 파일을 여세요.

```text
load
```

다른 지갑이 열려 있다면 공식 셸은 원하는 파일을 불러오기 전에 기존 지갑을 내리는 기능을 지원합니다. 목록 첫 지갑이 맞다고 가정하지 말고 내보낸 파일 이름으로 선택하세요.

클라이언트에서 사본을 검증하세요.

```text
address
status
```

전체 수취 주소를 원래 전체 지갑 주소와 비교하세요. 클라이언트에 표시된 보기 전용 유형을 확인하세요. 이 검사는 동일성과 의도한 접근 권한을 모두 확인합니다. 차이를 시험하려고 전송할 필요는 없습니다. [검토한 core](https://github.com/blocknetprivacy/core/blob/5a0a5b510c1dce46f4eeb12c33a291052e44e7b3/api_handlers.go)는 보기 전용 지갑의 전송과 메시지 서명을 거부합니다.

## 보기 지갑이 입금을 찾도록 하기

대상 노드에는 관련 블록이 있어야 하며 불러온 지갑은 이를 스캔해야 합니다. 다음 셸 명령으로 기록을 살펴보세요.

```text
outputs
history
```

새로 불러오거나 가져온 지갑은 노드에 피어가 있어도 아직 따라잡는 중일 수 있습니다. [지갑 동기화 안내](/ko/blog/blocknet-wallet-not-syncing/)로 체인 다운로드와 지갑 스캔을 구분하고 스캔이 필요한지 판단하세요.

전체 지갑이나 지급 기록에 이미 있는 거래 ID와 입금 기록을 대조하세요. [탐색기 안내](/ko/blog/blocknet-explorer-guide/)로 공개 포함 여부를 확인하고 보기 지갑으로 입금 상세를 봅니다. 현재 지출 판단과 승인은 전체 지갑을 사용하세요. 보기 사본은 입금 감시용이며 모든 발신 기록이나 사용 가능 잔액 판단을 똑같이 반영한다고 가정하지 마세요.

## 보기 개인 키는 어떤 접근을 주나요?

[공식 셸 참조](https://github.com/blocknetprivacy/blocknet/blob/948af4de8b7a3e3cddc86a329c7d2d003cb3fd6b/docs/reference-core.md)는 보기 개인 키 소유자가 입금을 볼 수 있다고 경고합니다. 암호화 보기 파일은 자체 비밀번호로 접근을 보호하지만 열면 비공개 결제 정보가 드러납니다. 의도한 사람이나 컴퓨터에만 권한을 주세요. 파일 비밀번호를 바꿔도 누군가 이미 복사한 보기 키는 폐기되지 않습니다.

지출 및 보기 비밀 정보를 공개 도구와 지원 메시지에 넣지 마세요. 수취 주소는 결제용으로 공유하지만 보기 개인 키의 목적은 다릅니다. [스텔스 주소 안내](/ko/blog/stealth-addresses-explained/)는 지갑이 자신의 출력을 알아보는 방식을 설명합니다. 이 설정에서는 의도한 보기 접근만 이전하고 복구 자료는 전체 지갑과 함께 보관하세요.

## 반복 가능한 보기 절차 유지하기

감시 컴퓨터로 돌아오면 같은 보기 파일을 불러와 네트워크와 주소를 검증하고, 항목이 없다고 해석하기 전에 진행 상황을 확인하세요. 입금 기록과 지출을 승인할 수 있는 자금을 구분하세요. 다른 지갑을 만들어 원래 지갑에 새 주소가 생겼다면 기존 보기 사본은 여전히 옛 지갑에 대응합니다.

보기 설정이 작동해도 전체 지갑의 복구 백업을 보관하세요. 보기 사본은 복구에 필요한 지출 자료를 대신하지 못합니다. [시드 안내](/ko/blog/seed-phrase-explained/)는 백업을, [보내기와 받기](/ko/blog/send-receive-blocknet/)는 결제 절차를 설명합니다. 전체 지갑, 백업, 보기 사본은 일상 작업에서 각각 분명한 역할이 있습니다.
