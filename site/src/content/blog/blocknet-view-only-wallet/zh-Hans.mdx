在第二台电脑上查看 Blocknet 转入付款，同时把付款授权保留在完整钱包中。本指南使用官方 CLI v1.2.0 和公开核心程序 v0.22.0，核查日期为2026年10月27日。下文介绍导出文件的操作流程、文件授予的权限，以及加载后如何核对收款记录。

## 如何创建只读 Blocknet 钱包？

<Answer>
打开完整钱包，使用 viewkeys 命令创建带独立密码的加密查看文件。将导出的文件传到目标电脑，加载后核对地址和只读类型。等待钱包扫描追上进度，再用它查看转入付款，支出操作仍留在完整钱包中。
</Answer>

## 选择要监控的收款记录

从你希望监控转入资金的完整钱包开始。[钱包设置指南](/zh-hans/blog/blocknet-wallet-for-mining/)介绍如何创建或恢复钱包。查看副本对应这个钱包的地址；它不会创建新的收款身份，也不会把代币转移到另一个账户。在处理任何导出文件之前，先记下副本对应的钱包和网络。

挖矿时，你可以继续使用同一个已核对的付款地址。只读钱包能帮助你在另一台可信电脑上检查钱包的转入记录。[矿池监控指南](https://bntpool.com/blog/zh-hans/track-your-miner-on-bntpool/)处理的是另一项任务：无需钱包密钥即可查看份额、矿池余额和付款活动。根据问题选择界面；需要查看私密收款记录时，查看权限才有用。

## 从完整钱包导出查看文件

在保存完整钱包的电脑上，连接到它正在运行的主网核心程序：

```sh
blocknet attach mainnet
```

用以下交互命令打开目标钱包并检查地址：

```text
load
address
```

如果钱包已锁定，按正常提示解锁。保持这次会话私密，因为下一步会显示查看密钥材料。

开始导出：

```text
viewkeys
```

[本文核查的客户端](https://github.com/blocknetprivacy/blocknet/blob/948af4de8b7a3e3cddc86a329c7d2d003cb3fd6b/attach_wallet.go)会说明私有查看密钥可以显示转入资金，并要求确认继续。只有确实要授予这种权限时才继续。随后，客户端要求输入完整钱包的密码、为只读文件设置新密码，并再次确认新密码。请选择并保存供目标电脑使用的文件密码。

## 应该传输哪个文件？

成功导出后，客户端会显示查看密钥和所保存文件的路径。请根据这条实际路径识别导出的查看文件。使用适合传输私密钱包数据的方法，将它传到你控制的电脑上。单独保护文件密码，不要把终端输出中的密钥纳入截图或故障排查记录。

[钱包参考文档](https://github.com/blocknetprivacy/blocknet/blob/948af4de8b7a3e3cddc86a329c7d2d003cb3fd6b/docs/reference-wallet.md)列出的默认文件夹是 `~/.config/bnt/wallets/`，Windows 对应路径为 `C:\Users\<you>\.config\bnt\wallets\`。配置的钱包路径可能改变 load 所列出的文件夹。把导出文件复制到目标电脑的钱包文件夹，方便客户端找到它。原始完整钱包及其恢复备份仍保存在各自预定的存储位置。

## 在第二台电脑上加载并核对副本

按照[节点指南](/zh-hans/blog/run-blocknet-node/)在目标电脑上准备正在运行的核心程序，再连接到同一个网络。使用为导出文件设置的密码打开它：

```text
load
```

如果已经打开另一个钱包，官方交互界面支持先卸载该钱包，再加载目标文件。请按导出的文件名选择，不要假定列表中的第一个钱包就是正确的钱包。

通过客户端核对副本：

```text
address
status
```

将完整收款地址与完整钱包的地址比较，并检查客户端显示的只读类型。这些检查同时确认钱包身份和预期权限。无需尝试发送来验证区别：[本文核查的核心程序](https://github.com/blocknetprivacy/core/blob/5a0a5b510c1dce46f4eeb12c33a291052e44e7b3/api_handlers.go)会拒绝只读钱包发送付款或签署消息。

## 让只读钱包发现转入付款

目标节点需要拥有相关区块，加载的钱包则需要扫描这些区块。用以下命令查看钱包记录：

```text
outputs
history
```

即使节点已有对等连接，刚加载或导入的钱包也可能仍在追赶扫描进度。参照[钱包同步指南](/zh-hans/blog/blocknet-wallet-not-syncing/)，区分区块链下载和钱包扫描，并判断是否需要执行扫描。

将转入记录与完整钱包或付款记录中已知的交易 ID 对照。[浏览器指南](/zh-hans/blog/blocknet-explorer-guide/)可帮助确认交易的公开入块情况，而只读钱包提供转入付款的详细信息。当前支出决策和授权应使用完整钱包完成。把查看副本当作转入监控工具，不要假定它会镜像所有转出记录或可支出余额判断。

## 私有查看密钥授予什么权限？

[官方交互命令参考](https://github.com/blocknetprivacy/blocknet/blob/948af4de8b7a3e3cddc86a329c7d2d003cb3fd6b/docs/reference-core.md)提醒，私有查看密钥的持有者可以查看转入资金。加密查看文件用自己的密码保护访问，但打开它仍会暴露私密付款信息。只向预定的人或电脑授予权限。更改文件密码不会撤销别人已经复制的查看密钥。

不要把支出或查看秘密放进公开工具和求助消息。收款地址用于向付款方提供收款信息，私有查看密钥的用途不同。[隐身地址指南](/zh-hans/blog/stealth-addresses-explained/)解释钱包如何识别属于自己的输出。在本设置中，只传输你确实打算提供的查看权限，恢复材料仍与完整钱包一同保管。

## 保持可重复的查看流程

再次使用监控电脑时，加载同一查看文件，核对网络和地址，并先检查扫描进度，再解释某条记录为何尚未出现。区分转入记录与自己能够授权支出的资金。如果你另建了钱包并因此获得新地址，现有查看副本仍然对应旧钱包。

查看设置可用后，仍要保留完整钱包的恢复备份。查看副本不能代替恢复支出权限所需的材料。[助记词指南](/zh-hans/blog/seed-phrase-explained/)解释这种备份，[发送与接收指南](/zh-hans/blog/send-receive-blocknet/)介绍付款流程。完整钱包、恢复备份和查看副本在日常使用中各有明确职责。
